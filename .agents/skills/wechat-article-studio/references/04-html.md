# 正文 HTML 与输出规范（第 4 步 + 输出规范）

**第 4 步 · 产出图文一体正文 HTML（关键交付，直接写进发布包）**
- 每篇一个自包含 HTML，微信公众号风格：大标题、主题色竖条小标题、金句加粗、"3件事"色块、居中金句块、文末陪伴定位卡片（不含点在看/转发等动作指令，见第2步"结尾不索取互动"原则）。
- **对齐铁律（section 版）**：**正文段落、小标题、卡片说明文字一律左对齐**（内层白色卡片 `<section>` 上写 `text-align:left`，text-align 可继承）；**只有该居中的才居中，并在该块自身 style 显式写 `text-align:center`**——顶部大标题色块、金句块、陪伴定位卡片、诗句/引文块、卡片标题。**严禁用 `<td align="center">` 或固定宽 + margin auto 做整体居中**（安卓会偏移右裁）。一句话：正文左对齐，金句/标题卡片才在块内居中。
- **正文里所有视觉元素一律用 `<section>`+内联样式绘制（卡片、色块、标签全用 section 嵌套 + 背景/圆角/边框），严禁 `<img>` 外链或位图、严禁 `<table>` 布局**（table 在微信安卓端会固化宽度导致窄屏右裁，见第4步"安卓裁切血案"）——保证复制一次即图文完整、粘贴后安卓/iOS 都自适应屏宽。
- **【强制·正文标准结构 = "section 流式骨架 + `<p>` 段落"（2026-09 起，取代旧 table 2号写法）】** 经 8 系列 71 篇实测，**`<table>` 布局在微信安卓端会固化宽度、窄屏整列右裁**（iOS 正常），故固定采用 `<section>` 流式骨架：
  1. **骨架（section 管"形"）**：`<body style="margin:0;padding:0;background:#页底色">` → 最外层 `<section style="box-sizing:border-box;width:100%;padding:16px 12px;background:#页底色">` → 内层白色卡片 `<section style="box-sizing:border-box;width:100%;background:#fff;…">`。卡片/色块/金句块/标签**全部用 `<section>` + 内联 style（background/padding/border-radius/border-left）绘制**；**每个块 style 必含 `box-sizing:border-box;width:100%`，禁止任何容器级 `width:NNNpx`/`max-width:NNNpx`（≥200px）、禁止 `<table>/<tr>/<td>`、禁止 `align="center"` 居中嵌套**；留白靠 padding，不靠固定宽。
  2. **多列网格的处理**：原"三栏并排卡片"（如三季卡）改成**纵向堆叠的满宽 `<section>`**（每块 `margin-bottom:8px`），窄屏自动上下排、永不横向溢出；装饰性小格子序列（如七格打卡）拍平成一行内联文字或堆叠小块。
  3. **竖条小标题**：用 `<section style="border-left:5px solid 主色;padding-left:14px;font-size:19px;font-weight:bold">` 表达，不再用"6px 色条 td + 标题 td"两格结构。
  4. **段落（`<p>` 管"文"）**：正文每个自然段一律 `<p style="margin:0 0 12px; font-size:16px; line-height:1.9; color:#正文色;">…</p>`；段距靠 `<p>` margin；**文字一律 `<p>/<span>/<b>/<strong>` 承载，全篇禁 `<table>/<div>/<h1-4>/<ul>/<li>`、禁 `data-*`、文字颜色不挂容器只挂 `<p>/<span>/<b>`**；列表用 `<br>`+`·`/`①②③`。
  3. **换行（`<br>` 只做正文段内换行）**：**正文段落内部**需要换行时**只用单个 `<br>`，严禁 `<br><br>` 双换行**（双换行=偷偷空一行，是"行距怎么调都没变化/空当过大"的根因，曾因此返工 4 轮）；段与段之间永远用新的 `<p>`，不用 `<br>` 堆。**但标题/白字色块内禁止 `<br>`**（白字标题里 `<br>` 会打断第二行白色继承，必须一行一个独立 `<p>`，见下方 C 类铁律）。
  4. **行距定稿基线**：正文 `line-height:1.9`；卡片内文字 `line-height:1.85`、卡内单元格 padding 约 14px；段距 `margin-bottom:12px`（卡片内小标题/条目间距可 14px）。
  5. **对齐**：正文 `<p>`、小标题、卡片说明文字默认左对齐（靠主表 `text-align:left`）；仅顶部大标题色块、金句块、陪伴卡、诗句/引文、卡片标题在**该块自身 style** 写 `text-align:center;`。
  - 一句话记忆：**section 管形、`<p>` 管文、`<br>` 只管段内换行不管段距**；调行距只改 `line-height`、调段距只改 `<p>` 的 `margin`，不要去动 `<br>` 数量或加空行。
- **【⭐ 生成阶段硬性规则（写正文时就照做，别等事后修，2026-09-21 新增）】** 依据微信官方《公众平台编辑器插件开发规范》全文 + 官方检测器源码：
  - **R1 · 块内「裸文本 + 内联元素」不得混排（治「行高小于字体大小」告警）**
    - ⛔ 不要写：`<p style="…line-height:1.9">这是正文<b>重点</b>继续正文。</p>`
    - ✅ 应该写：`<p style="…line-height:1.9"><span>这是正文</span><b>重点</b><span>继续正文。</span></p>`
    - `<span>` **不带任何样式**（颜色仍写在自己的 `<b>/<span>` 上）→ **视觉零变化**。
    - 或让强调**独立成段**（`<p style="…;font-weight:bold;color:#xxx">小标题</p>` + 普通段）。
    - 理由见 ②：官方按真实布局测行框数，混排会让行数虚增 → 误判叠字（与行高取值无关）。
  - **R2 · 控制嵌套层级（治 `nestNodes` 冗余嵌套）**
    - ⛔ **不要**用连续多层「只为了包一层」的 `<section>`：`<section style="width:100%"><section style="width:100%"><p>…</p></section></section>`
    - ✅ **把「背景 + padding + 圆角 + 边框」合并到一个 `<section>`**，需要视觉层次时靠 padding/border 拉开，不靠多层包裹。
    - 官方口径：同 tagName + 同内联样式 + 仅单子节点的连续链 **≤10 层**（超出编辑器会自动精简）；官方检测器 `nestNodes` 更严（DOM 深度 ≥15 即报）。
  - **R3 · 一律不写 `font-family`**（官方第 3 章「不建议设置任何字体族」）
    - ⛔ 删除所有 `font-family:…`（含 `Microsoft YaHei`、`-apple-system` 等任何写法）。
    - 公众号已内置优化过的默认字体栈；自定义会破坏一致性（iOS 17+ 部分版本字号/字间距明显差异）。
    - ⚠️ **官方检测器不查这条**（源码有函数但未调用）——所以「官方检测通过」≠「符合文档」。**生成阶段必须自行遵守。**
  - **R4 · 多段共用同一背景时，背景写公共容器**（官方 4.2.1）
    - ⛔ 不要给相邻多段各写一份相同 `background`。
    - ✅ 把它们放进**同一个外层 `<section>`**，背景写在该容器上。
  - **R5 · 其余禁用项（生成阶段即避开）**：`line-height` < 字号、`line-height:0`、`text-align:start/end`、`<pre>`、`height:0`、固定 `height`+`overflow:hidden`+含文字、固定 `width:≥200px`、大 `margin-left`、`position:absolute`/`transform` 破坏视觉顺序、`!important`、渐变背景承载文字（DM 下会转纯色/消失）、图片承载纯文本、`<div>/<h1-4>/<ul>/<li>/<table>/<img>`。
  - **⛔ 为什么必须先遵守（2026-09-22 逐函数复核实证）**：官方规范共 **22 个章节**，检测器只覆盖 **15 个**，**7 个章节完全不查**：
    - **唯一「函数已实现但未接入」**：`font-family`（`engine/rules/font-family.ts` 有 `checkFontFamilyViolation()`，但 `collect.ts` **调用 0 次**）；
    - **其余 6 个连实现都没有**：`4.2.1 背景容器`、`4.2.2 嵌套关系`（部分并入 `nestNodes`）、`4.3.1/4.4.1 图片承载纯文本`、`4.3.2 透明底图`、`4.3.3 补色机制`、`4.5.2 !important`。
    ⇒ **「官方检测通过」≠「符合文档」**——R3/R4/R5 里这些项**事后无法拦截**，只能靠生成阶段写对。随时可查：`wechat_official_verify.py --list-rules`（会一并打印这 7 条）。
- **【⛔ P0 · 微信粘贴不塌三条铁律 + 一键校验】** 微信编辑器粘贴时会三轮清洗 HTML，以下三类是实测"粘贴后丢色/样式整块丢失"的根因，成稿前必须用脚本自检归零：
  1. **A类 · 剥干净编辑器残留属性**：HTML 里**禁止任何 `data-page-node-id` 及其它 `data-*` 属性**（秀米/外部编辑器往返保存会给每个节点注入，连 body/head/meta 都有；微信把带 data-* 的节点当"外部组件"整段重置样式，头部白字标题会整块消失）。
  2. **C类 · 文字只用 `<p>` 承载、白字标题禁 `<br>`**：**禁止 `<div>`、`<h1>~<h4>`、`<ul>/<ol>/<li>`**（div/h 的 color 微信继承最不稳）；白字大标题**一行一个独立 `<p style="color:#fff;text-align:center;display:block;">`，绝不在白字标题里用 `<br>` 拆多行**（br 会打断第二行白色继承、回退深色看不见）。
  3. **B类 · 文字颜色写在 `<p>/<span>/<b>/<strong>` 自身，不写在 `<td>/<section>` 上**：`<td>` 只承担 `background/padding/width/border`，**不写 color**；td 里若有裸文字必须包 `<span style="color:同色">`。装饰竖条/空 td（仅 &nbsp;）不写 color。已自带 color 的强调标签（`<b>/<strong>`）内部不要再包外层色 span（会盖掉金句强调色）。一个标签只能有一个 `style=""`。
  - **一键自检/修复脚本（幂等）**：家庭教育工作空间两个工具配套使用：
    ① **结构转换（table→section 流式）**：`工具脚本/table转section_微信正文流式重构.py`。用法 `python table转section_微信正文流式重构.py <文件…>`（把 table/tr/td/div 全转 section、剥容器固定 px 宽与 data-*、竖条小标题转 border-left、多列网格转满宽堆叠；`--check` 仅统计 table 数）。**凡发现正文含 `<table>` 或容器固定宽，先跑它转换。**
    ② **规范校验/修复（启发式筛查）**：`工具脚本/微信HTML规范校验修复_wx_html_fix.py`。`--check` 体检、无参修复（剥 data-*、白字标题拆 br、文字色下沉 span、**消除块内混排** 等）。
     - ⛔ **块内不得「裸文本 + 内联元素」混排**（2026-09-21 修正，**取代旧「给 `<b>` 补字号」规则——那条已证伪**）。凡 `<p>`/`<section>` 内**既有裸文本、又有 `<b>/<strong>/<span>` 等内联元素**时，微信会报「**行高小于字体大小，且存在多行文本，可能导致文字重叠**」（#2.3.2）。
       - **真根因**：官方用真实浏览器测行框数（`range.getClientRects()`），内联元素边界被算成**额外 rect** → 行数虚增 → `高度/行数` 被除小 → **误判叠字**。**与 `font-size`、`line-height` 取值完全无关**（补字号、写 `inherit`、调大行高、删行高，全都照样报——已消融验证）。
       - ✅ **写法**：块内**每段文字都用无样式 `<span>` 包**（或让强调独立成段）。**视觉零变化**（`<span>` 不带任何样式，颜色仍写在 `<b>/<span>` 自身）。详见本文档下方「生成阶段硬性规则」。
     - ⚠️ **本工具只是启发式筛查，不是官方判定的复现**。权威判据是**官方工具**（见 ③c）。
     - **必须跑官方工具**（2026-09-21 新增，权威判据）：`工具脚本/wechat_official_verify.py`（封装微信官方 `wechatjs/verify-article-structure-spec`，真机 puppeteer 跑全 17 条规则）。用法 `python 工具脚本/wechat_official_verify.py --dir <成果根目录>`。**新系列交付前必须跑到「无任何违规」**（`nestNodes` 冗余嵌套另见 ③c 说明）。首次运行会自动 clone + `npm install`（约 2–3 分钟，⚠️ 必须走 PowerShell，bash 下 npm 会触发 wsl.exe 被拦）。
    ③ **全套发布前自检（通用版，交付门禁）**：`工具脚本/系列发布全套自检_selfcheck.py`。`--dir <成果根目录>` 一次跑完 9 项：①篇号连续 ②三件套齐全 ③标题三处逐字一致 ④来源声明在位 ⑤无动作指令/绝对化 ⑥零 table·div·img·data-*·class + section/p 配平 ⑦`wx_html_fix --check` ⑧预览页篇数正确 ⑨源正文 data-* 归零。**新系列一律用它把门**（退出码 0 才算可交付）；`--legacy` 用于既有系列巡检（放行"含历史 02 指南 / 早期包无 01 字段表 / 来源口径旧写法"等历史差异，只报真问题），`--source` 可指定来源关键词。**若打开过 HTML 预览（预览面板会写回 data-*），交付前须重跑本项，确认源正文 data-* 仍为 0。**

    ③b **模板感/表达节流（内容质量门，与③互补）**：`工具脚本/模板感诊断_template_scan.py --dir <成果根目录>`。③管"技术交付合格"，③b管"读起来不像同一个模具"——逐篇统计句式节流命中并识别结构轮换，超线标 ★；`--diag-structure` 另出结构特征。**改造/新写系列时先跑它定位要改哪几篇，改完再跑到命中数明显下降。**（实测：青春期30讲第10–18篇改造后，节流命中从 9 篇降到 0 篇、结构覆盖 6 型。）
    **交付标准（section 版）：所有正文 0 `<table>`、0 `<div>`、0 容器固定宽（width/max-width:≥200px）、0 data-*、0 img、section/p/span/b 标签配平**；预览合并页用 `工具脚本/重建全部正文预览.py` 一键重建。注意：`<系列名>_全部正文预览_N篇.html` 是本地校对页（不发布），其导航外壳可用 class/div，不在此禁令内。**交付前统一跑 `系列发布全套自检_selfcheck.py` 到"✅ 全部通过，可交付"**（比逐篇目检快且不漏）。
- 卡片直接内嵌正文对应位置（不是虚线占位）。
- 每篇文末**固定加来源声明**（用用户口径）。中文内容；正文颜色随主题色变化但保持可读。
- **文件直接落在该篇的 `发布包_第X篇/正文.html`**（与字段表、指南、封面同目录），不再另设 `排版HTML/` 目录、不另存副本。

## 输出规范（P1 质量线 · 违反则不算合格交付）
- **⛔ 三道人工关卡为最高优先级（硬性）**：Gate1 选题确认前不写正文；Gate2 样板（1–2篇）确认前不批量生产发布包；Gate3 封面（1组）确认前不批量生封面。**没有用户当次明确确认指令，严禁自行决策推进到下一阶段**（详见开篇"人工确认关卡"）。
- **每篇文末必须有来源声明**，口径以用户当次提供为准；定位常见为"读书笔记/学习心得，非原文摘录，版权归原作者及出版方所有，侵权联系删除，转载注明出处"。
- **篇号连续**；公众号名/署名在全套材料中统一（用户会给出，如"归途有光和孩子一起重启"）。
- 作者、书名、机构、数据等事实信息必须与原材料/权威口径一致；不确定就标注或询问，不编造。
- **⭐ 内容完整性优先于去重（硬性）**：改稿/节流时**先保"场景·父母心理转折·机制·方法·边界"五层齐全，再压重复句**；**绝不为了消灭高频词而把文章讲空**。重复句优先换说法（换喻体/换句法），不整段删除；若节流会伤到五层，**宁可不改**。改完逐篇用一句话回答五项分别是什么——答不全即回补（详见第2步"完整性红线"、第9步第7b项）。**"结构稿"不得称为"可发布成稿"**。
- **篇幅（按体裁分档，2026-09-28 修订）**：**叙事型 2000–2800 中文可见字符**（主档）／ **方法型 1200–1800** ／ 速览短答 900–1400；**1800–2000 为两档过渡带**；**收官篇的「工具合集／总导航」卡片区属附录，单独计**。区间是报警器不是配额；**改写降幅 ≥30% 必须额外复核叙事张力、情绪承接、方法细度、阅读节奏**（见第2步"删改降幅复核线"）。
- **父亲叙事化、不说教（硬性）**：正文走"改变故事线"而非议论文骨架（**结构须按第2步"六种结构"轮换，不得每篇同一模具**）；**课程/书的显性引用密度按内容类型分（类型A课程≤1–2处；类型B读书笔记放宽至6–10处+开头书名引荐块+模型用卡片呈现），但两类都必须贴着"我"的故事、在"我卡住/想通"处带入，不写板书**；观点改写成"我"的体感；道理讲一遍不重复；每篇≥2 处私人细节（物件/对话/时间点，**优先取自"真实素材池"，且不与既往文章重复**）；"我后来试着做的几件小事"**仅方法类文章使用**、允许笨拙失败；金句从情境里长出来，不写成板书。
- **叙事真实性三分法（最高优先，硬性）**：真实经历 / 课程案例改编 / 他人案例 三者**写法与标注各不相同**（详见人设预设节）——**改编情节必须在开头第一屏就标注"家庭场景改编"，不能只在文末解释**；**绝不把讲师自述或课程案例改写成作者的"真实经历""真实复盘"**。这是本账号长期最高风险点，优先级高于任何排版规范。
