## 三、怎么用

### 1. 写剪辑单（JSON）

```json
{
  "videos": ["第1段.mp4", "第2段.mp4", "第3段.mp4"],
  "script": "文案.txt",
  "out": "成片.mp4",
  "cut_silence": true,
  "model": "small",
  "visual": {"transition": "叠化", "xfade": 0.3, "color_match": true,
             "denoise": "轻", "trim_tail": 0.4},
  "marks": [
    {"word": "装的", "color": "#C2703C", "bold": true, "scale": 1.12}
  ],
  "punch": [
    {"text": "检查没查出来，不等于孩子在装",
     "marks": [{"word": "不等于孩子在装", "color": "#A8551F", "bold": true}],
     "anchor": "他是在装病逃学"},
    {"text": "害怕，也会让人觉得疼", "anchor": "害怕考试"}
  ],
  "seq": [{"text": "①", "seg": 1, "hold": 1.8},
          {"text": "②", "seg": 2, "hold": 1.8}],
  "cover": {"text": "不等于孩子在装", "anchor": "害怕考试"}
}
```

- **`videos`**：给 1 个或 N 个路径都行；只给 `video` 字符串等价于单文件模式
- `script` 省略 → 走**听写模式**（直接用 ASR 分段当字幕）
- `marks` 是**全片通用的标色规则**，匹配不到的词会静默忽略（方便一套规则复用多篇）

### 卡片位置：用锚点，**不要写时间码**

| 写法 | 含义 |
|---|---|
| `"anchor": "某句话"` | **推荐**——自动定位到含该文本的那句字幕（容忍标点差异与个别错字）|
| `"seg": 2` | 第 2 段开头（配 `"offset"` 微调）|
| `"at": "end"` | 片尾倒数若干秒（配 `"hold"`）|
| `"start": 12.5` | 硬写秒数（**最不推荐**，素材一变就全错位）|

可配 `hold`（持续秒数）、`lead`（anchor 提前量）。**锚点找不到会打印原因 + 列出可用字幕行**，不会静默失败。
片尾定格卡（方便截图）：`{"text":"...","at":"end","hold":2.0,"to_end":true}`

### 字幕策略：三种版本（不必全程都有字幕）

| 版本 | 效果 | 配置 |
|---|---|---|
| **全字幕** | 每句都有底部字幕 | `"subs": "all"`（默认） |
| **金句版** | 只有关键句出字幕 | `"subs": [{"anchor": "某句"}, ...]`（**只写锚点，字幕照抄原句**） |
| **纯卡片** | 无底部字幕，只有居中大卡 | `"subs": "none"` + `punch` |
| **全字幕 + 金句强调** | 全程都有，金句那几句更大更粗 | `"subs": "all"` + `"subs_emph": [{"anchor":"某句","style":"强调"}]` |

可选样式：`字幕`(62px 底部) / `强调`(78px 加粗，仍底部) / `序号条` / `金句`(100px 居中)。
单项覆盖：`size` / `color` / `bold` / `scale` / `outline`。
> ⚠️ 换**位置**（居中/靠上）要用 `"style"` 换整套样式，别用行内标签改对齐。

### BGM（背景音乐）—— **默认关闭**

**不写 `bgm` 就没有 BGM**（判据：需要「额外素材」的能力一律默认关，
需要「额外素材」→ 关；对「已有素材」做处理 → 开）。

| 位置（`placement`） | 效果 |
|---|---|
| **`头尾`**（默认） | **只垫没有口播的地方** —— 开头到第一句话之间、最后一句话到片尾 |
| **`全程`** | 整片垫底，**人声段自动压低**（`duck`，默认 12dB） |

来源两种：`file` 直接指定文件 / `style` 按风格从曲库筛
（曲库：`_资产/bgm/` 或 `<本篇>/_素材/bgm/`，配 `曲库.md` 标注风格）。

```jsonc
"bgm": {"file": "轻音乐.mp3",   // 或 "style": "安静的钢琴"
        "placement": "头尾",     // ⭐ 参数：头尾 / 全程
        "gain": -24,            // 相对口播的音量（dB）
        "duck": 12,             // 仅「全程」：人声段再压低多少
        "dips": [{"anchor": "某句", "extra": 6, "hold": 0.5}]}  // 定点额外压低
```

查曲库 / 试筛选：

```bash
python <技能>\scripts\video_bgm.py --list
python <技能>\scripts\video_bgm.py --pick "安静的钢琴"
```

CLI 快捷方式：`--bgm-file` / `--bgm-style` / `--bgm-placement` / `--bgm-gain` / `--bgm-duck`

> ⛔ 曲子找不到、或头尾没地方垫 → **报错停下**，绝不静默产出"没 BGM 的成片"。
> ⛔ **不联网下载音乐**（版权风险）——曲子需要人提供。
> ⚠️ `头尾` 模式要求片头片尾有静音 → 剪停顿会**自动保留头尾静音**（`keep_edges`）；
>    素材本身头尾就没静音时**报错**并建议改用「全程」，不会硬塞。
> ⚠️ BGM 会**拉高峰值-响度比** → 响度可能够不到 -14 LUFS（物理约束，见下文 PLR 一节）。

### ⭐⭐ 文案 MD 要怎么写（给创作者的要求）

完整规范：`...\skills\ffmpeg-vertical-video-pipeline\reference\md_authoring_guide.md`

## 四、⛔ 踩过的坑（改脚本前必读）

1. **ffmpeg 滤镜里的 Windows 路径会被吃**
   `C:\` 的**冒号是滤镜参数分隔符**，`ass=C:\x.ass` 必然失败。
   → **正解：`subprocess(cwd=目标文件所在目录)`，滤镜里只写文件名**。
   （比在字符串里堆 `\:` 转义可靠得多）

2. **CJK 满宽字符必须自动折行**
   16 个汉字 × 104px = 1664px，而竖屏只有 1080px → **实测两侧被裁掉**。
   → `video_build_ass.wrap_cjk()` 已内置（优先在标点后断），自检会逐行打印 px 宽度。

3. **`sys.stdout` 不可双重包装**
   多个脚本都写 `sys.stdout = io.TextIOWrapper(sys.stdout.buffer, ...)`，
   互相 import 时会报 `I/O operation on closed file`。
   → 一律改用 **`sys.stdout.reconfigure(encoding="utf-8", errors="replace")`**。

4. **ASS 颜色是 BGR 倒序**
   `#C2703C` → `&H003C70C2`（AA BB GG RR）。**写反了颜色就不对**。
   用 `video_build_ass.ass_color()` 转换，别手写。

5. **fontconfig 别误判**
   判断 ffmpeg 是否支持中文渲染时，`grep enable-lib` **查不到 `--enable-fontconfig`**（它没有 `lib` 前缀）。
   → 直接检查 `ffmpeg -version` 输出里是否含 `fontconfig` 字串。

6. **ffmpeg 调用一律用 `subprocess` 传 list**
   中文路径 + 特殊字符不经 shell 才安全（本项目曾因内联命令被 shell 吃掉出过事故）。

7. **⛔ 绝不可并发下载多个 HF 模型**
   两个下载抢同一缓存锁（日志里表现为 `state lock timeout`），会把 `model.bin` 写成
   **不完整的文件**，之后加载报：
   `RuntimeError: File model.bin is incomplete: failed to read a value of size 4 at position 0`
   → **必须串行下载**，且下载后**立即实际加载校验**（只看文件存在是不够的）。
   用 `python C:\Users\ZhuanZ\.workbuddy\binaries\ffmpeg\dl_models.py <模型名...>`（已内置串行 + 校验）。

8. **⛔ `arnndn` 后面必须加采样格式归一化**
   RNNoise 按 480 样本分帧，其输出帧长与本构建的 AAC 编码器**不兼容**，会报
   `Error submitting audio frame to the encoder: Invalid argument`。
   实测：输出 `fltp` → 失败；输出 `s16` → 成功。
   → 音频链**链尾**固定追加 `aformat=sample_fmts=s16:channel_layouts=stereo`
   （放链尾而非紧跟 arnndn，可保住中间环节的浮点精度）。

9. **⛔ 真峰值要靠 `alimiter`，且限制点要比目标低约 1 dB**
   单遍 `loudnorm` **压不住真峰值**：目标 -1.5 dBTP，实测产出 **+0.71 dBTP**（已过 0，有削波风险）。
   而 `alimiter` 限的是**采样峰值**，dBTP 是**真峰值**（含采样间过冲），两者实测差约 **0.9 dB**。
   → 限制点 = 真峰值目标 − 余量，代码里由 `alimiter.headroom_db`（默认 1.0）自动算。
   实测：配 1.0 余量后产出 `TP=-1.59 dBTP` ✅（不这么算只会得到 -0.63，白设）。
   ⚠️ `alimiter` 的 `level` 必须设 **false**，否则它会自动抬电平、把 loudnorm 的成果毁掉。

10. **⛔ 所有 `-i` 必须在所有 `-vf`/`-af` 之前**
    否则报 `Option vf ... cannot be applied to input url <第二个输入>`
    ——ffmpeg 把 `-vf` 当成**下一个输入**的选项了。
    ⚠️ **已踩两次**（自检脚本 + 端到端测试脚本）。造多输入命令时第一件事就是数 `-i`。

11. **⛔ `xfade` 要求各输入的分辨率/像素格式/SAR/帧率/时间基完全一致**
    不一致会报 `First input link main parameters (size AxB) do not match the corresponding
    second input link xfade parameters (size CxD)`，或更阴的「**命令成功但时长不对**」
    （实测第一次输出只有预期的 2/3）。
    → 每段分支固定加 `settb=AVTB,setsar=1,format=yuv420p`，音频统一 `aformat`。
    ⭐ **这个安全必须内置在拼装函数里（自动探测并统一），不能外包给调用方**——实测外包会漏。

12. **⛔ 多张卡片时间重叠 = 两条 Dialogue 同时显示 = 文字叠字**
    金句卡 1 的 `hold` 太长会盖到卡 2 的开头，两行大字直接叠在一起
    （实测画面上出现"检查害怕出来，也会让人觉得疼"这种串字）。
    → `resolve_overlaps()` 自动错开：优先裁前一张尾巴，裁不动（会短于 1.2s）就把后一张整体后移。

13. **⚠️ 无音轨的片段在拼接后会被「剪停顿」整段吃掉**
    拼装时会给无音轨段补 `anullsrc` 静音，于是这整段成了"长静音"，后续 `silencedetect`
    会把它剪掉（实测 13.05s → 9.30s）。纯 B-roll 素材需单独确认；口播素材（都有音轨）不受影响。

## 音频处理（口播声音美化）

```json
"audio": { "enabled": true, "preset": "标准", "override": {} }
```

`preset` 可选：`关闭` / `轻` / `标准` / `强` / `仿剪映声音美化`
`override` 可覆盖任意单参数，例如 `{"arnndn": {"mix": 0.9}, "loudnorm": {"I": -13}}`

**处理链顺序**（不可随意调换）：

```
highpass → arnndn → [afftdn] → deesser → equalizer → acompressor → loudnorm → alimiter → aformat
  去低频     神经网络     传统FFT     去齿音     音色塑形      压缩       响度标准化  真峰值限制  格式归一化
            降噪          降噪
```

**关键参数含义**

| 参数 | 作用 | 建议 |
|---|---|---|
| `highpass.f` | 去低频隆隆声 | 男声 70~90，女声 90~120 |
| `arnndn.mix` | 降噪强度 0~1 | 0.8 平衡；0.95 激进；0.6 温和 |
| `arnndn.model` | 模型（`std` `bd` `sh` `mp` `cb` `lq`） | 默认 `bd.rnnn` |
| `deesser.i` | 去齿音强度 0~1 | 0.4 起，齿音重就加 |
| `eq` | 音色冷暖厚薄 | `180Hz -2` 去闷、`3kHz +2` 提咬字、`8kHz +1` 加空气感 |
| `compressor.threshold` | 压缩起点(dB) | -18 温和，-20 更实 |
| `loudnorm.I` | 目标响度(LUFS) | 短视频平台用 **-14** |
| `loudnorm.TP` | 真峰值上限(dBTP) | **-1.5** 留安全余量 |
| `alimiter.headroom_db` | 限制器额外余量 | 默认 1.0（见坑 9） |

> 模型位置：`C:\Users\ZhuanZ\.workbuddy\binaries\ffmpeg\models\arnndn\*.rnnn`
> （ffmpeg 不自带，需另下；已备 `std/bd/sh/mp/cb/lq` 六款）

**调参工具**

```bash
# 只测响度，不改文件
python 工具脚本/video_audio.py --analyze 素材.mp4

# 列全部预设与默认参数
python 工具脚本/video_audio.py --presets
```

A/B 时重点听四件事：**①背景噪声剩多少 ②齿音刺不刺 ③人声发闷还是过亮 ④音量是否平稳**

### ⭐ 响度能否达标，先看 PLR（重要）

同时满足「目标响度 `I`」与「真峰值上限 `TP`」存在一条**硬约束**：

```
PLR（峰值−响度比）= TP − I      ← 素材自身的动态范围
达标所需上限      = TP目标 − I目标 = (-1.5) − (-14) = 12.5 dB
```

**素材 PLR 超过 12.5 dB 时，两者无法同时达标**——限制器会把峰值硬压下去，响度随之掉，
**无论怎么调 loudnorm 都补不回来**（本项已用 5 种方案实测确认：全部卡在 TP≈-1.74，响度差 1.7~2.6 LU）。

`--analyze` 会直接给出预判，**实测预测精度 ±0.1 LU**：

```
PLR（峰值−响度比）= 17.86 dB
达标所需上限     = 12.50 dB
→ ⚠️ 超标 5.36 dB，**无法同时达标**
   预计最终响度只能到约 -19.4 LUFS（差 5.4 LU）
```

**参考值**：纯口播素材 PLR 通常 **10~12 dB**（可达标）；
含背景音乐的视频 PLR 常达 **17~19 dB**（不可达标）。

**顺带一个实测结论**：`acompressor.makeup` 在本链里**无效**——
loudnorm 是线性补偿，会把 makeup 加的增益原样抵掉（实测 makeup 1.0/2.0/3.0 输出完全相同）。

## 七、平台适配（视频号，2026-09 检索后对齐）

| 项 | 平台要求 | 已实现 |
|---|---|---|
| 分辨率 | 1080×1920 竖屏（9:16）| ✓ |
| 编码 | H.264（H.265 部分平台不支持上传）| `-profile:v high -level 4.0` |
| 帧率 | 25 或 30fps | ✓ 多段不一致时自动统一 |
| **码率** | **6~10 Mbps**（平台还会二次压缩）| 默认 CRF + `-maxrate 12M`；`--bitrate 8M` 直接对齐（实测 8.2 Mbps）|
| 音频 | AAC | 192k / 48kHz |
| **封面** | **默认取视频第一帧**；**朋友圈分享时裁成 1:1** | `hook` 保证第一帧有字；`cover` 出 **9:16 + 1:1 两张** |
| **安全区** | 顶部 180 / **底部 360** / 右侧 110（估算）| 字幕 `margin_v=460`、`margin_lr=110`；`--safe-check` 自检 |

⭐ **开头钩子 `hook`**：视频号/朋友圈是**静音自动播放**，前 3 秒只有大字能抓人；
而且**第一帧会被平台默认当封面**——所以钩子要一句能独立看懂的话。
代码里钩子**不加淡入**，保证第一帧就是完整画面。

⚠️ **安全区数字是估算**：正式发布前建议发一条"仅自己可见"，真机确认字幕/卡片没被 UI 压住。
`--preview` 会打印安全区检查结果。

**内容侧结论**（检索结论与本项目 `_资产/发布数据复盘.md` 吻合）：
- ⭐ **别照抄抖音砍时长** —— 真正要改的是"信息有没有一直在往前走"，删掉"刚才说到/接下来我们看"这类过渡句；
- ⭐ **结尾给"转发理由"而不是求关注** —— 视频号的真杠杆是**被转发**（与复盘结论一致）；
- 微信**从未公开**完播率基准，网传及格线都是转抄 → 用**自己近 10 条的中位数**做基线。
