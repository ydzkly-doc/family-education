# 后台派生卡片文章（贴图）

仅在用户明确要求为已经定稿的公众号长文制作卡片文章时读取。它是可选增量，不因长文完成而自动触发。

## 一、先把三个概念分开

- **文章本体**：长图文 HTML、字段表和 2.35:1 封面组成的正式长文。
- **正文内干货卡**：长文 HTML 中用 `section` 绘制的清单、步骤或对照色块。
- **后台派生卡片文章（贴图）**：同一长文发布后，在公众号后台生成或编辑的竖版卡片传播载体；本技能为它制作可控的卡图、纯文本描述和字段资料。

后台派生卡片与文章本体是“一份内容、两个载体”。禁止写成：

- 两个封面版本或封面 A/B；
- 两篇独立文章或两条内容产线；
- 把系统自动生成的卡片直接等同于本技能人工设计的卡片发布包。

## 二、两道确认关卡

### Gate A：设计文档确认

先只交付一份卡片设计文档，包含：

1. 已定稿长文的段落编号与素材回溯；
2. 拆卡表及每张叙事职责，并写明张数依据（长文有几个独立核心意思、为何这样定、哪些已合并或为何不合并）；
3. 取舍说明：卡图讲什么、描述只补什么；
4. 纯文本描述全文、字符核算和话题标签草案；
5. 标题与后台字段草案；
6. 人物、数字、时间线与长文正文的一致性核对；
7. 逐卡来源类型表（真实经历／场景改编／第三方案例）、卡型、节点数、段落数、预计字量与密度。Gate A 的拆卡表是后续渲染的施工图，必须说明哪些内容合并、删去或只留在长文／描述中。

用户当次明确确认前，禁止生底图、试渲卡片、建正式卡片发布包、迁移目录或运行图片后处理。只允许做只读的字数、段号和一致性核算。

### Gate B：封面卡风格确认

Gate A 通过后，先做首张封面卡样板。用户当次明确确认风格前，不批量渲染其余卡、不组装正式包、不迁移目录。后续篇若用户明确要求沿用已经批准的同系列风格，可不重复 Gate B。

## 三、内容设计

- 长文是唯一素材源；存量补做时只读已定稿长文，不反向修改长文迁就卡片。
- 张数按内容厚度定，不固定套用某一公式：先数长文里有几个互不重复、能独立成立的核心意思（一条判断加它的支撑），一个意思单元配一张内容卡。
- 结构固定为“封面 1 张 + 内容 N 张 + 收尾 1 张”，但 **N 不固定**。先按长文中互不重复、能独立成立的核心意思确定内容卡：通常为 1–3 张；不能为了凑成 3 张制造薄卡。确有 4 个以上核心意思且无法用合适卡型合并时，可以建议超过 3 张，但须在 Gate A 说明原因并取得用户明确确认。
- Gate A 必须逐篇给出“建议内容卡数量、建议总张数和判断依据”，不能只套用全系列统一张数。当前常用区间是首页 1 张、内容 1–3 张、收尾 1 张，合计 3–5 张；这是编辑策略，不冒充平台上限。
- 不为凑张数把一个意思拆成两张（那是空卡），也不为省事把几个独立意思硬塞进一张（那是过载）。意思单元达到四个以上时，先用对照卡、时间线卡或四宫格把同类并进一张，而不是加卡。
- 篇幅偏少不是缺陷：实测反馈是张数越多越容易掉量，三张（内容卡一张）在某些篇就是正解。同一系列内各篇张数不必相同，但同一篇内各内容卡的厚薄应当相当。
- 每张卡都应能独立看懂，同时只承担一个清楚任务：钩子、机制、方法／对照、转折、情绪落点。并列内容必须围绕同一核心动作，不把不同层级的抽象词硬凑在一起。
- **“一屏一意”不等于“一屏一句”**。中间内容卡默认应有“1 个核心判断 + 2–4 个解释点／步骤／边界／可照念台词”，通常形成 3–4 个信息块；若只剩一句金句或一小段摘要，应回到长文补足本屏需要的机制与行动信息，而不是靠增加卡数解决。
- 中间卡正文采用明确的密度目标带：**内容块高度占可用内容区 62%–68%，70% 为红线**。低于 58% 时先回到长文补机制、例子、可照念台词或适用边界；不得用空行、同义重复或无据结论“填满”。高于 70% 时删减、合并或换卡型，不能靠缩小正文字号硬塞。留白是密度的结果，不作为脱离内容量的独立参数调整。
- 本项目 1242×1656 卡片的正文基准字号固定为 **40px**，不因过载继续缩小；内容卡／对照卡行距 1.66，时间线卡 1.64，四宫格 1.60。主标题一行时正文通常控制在 10–11 行，主标题两行时控制在 9–10 行。若设计语言或画布发生变化，应重新实测，不把这些项目参数冒充平台通用标准。
- 先按内容结构选卡型：单一主题论证用内容卡，恰好两组差异用对照卡，三个及以上顺序节点用时间线卡，四个并列概念才用四宫格。某一格明显过载、需要压小字号或挤占署名区，通常说明卡型选错，应换卡型而不是硬塞。
- 卡片不是长文截图，也不是逐段摘要。重新组织为“一屏一意”，保留关键事实与边界，不补写长文里没有的经历、数字或因果。
- 卡图上的文字、人物年龄、篇号、步骤数和时间数字必须与长文正文逐项核对；字段表或旧摘要与正文冲突时，以已定稿正文为准并报告冲突。
- 渲染前逐卡机械比对 Gate A 设计与渲染配置：节点／段落／行数必须一致，正文可见字符数原则上不偏离设计稿 ±15%，并用 `工具脚本/卡片密度预估_density.py` 预判密度。执行中需要新增节点、说明行或长文段落时，先修改设计并重新取得相应确认，不能把未经确认的扩写藏进渲染配置。
- 规则演进不追溯存量：新目标只用于后续篇目和用户明确点名升级的系列。复核旧稿时先按其制作时的已确认标准判断，不因新标准自动宣布旧稿失效或返工。

## 四、纯文本描述

- 定位是“钩子 + 卡图未讲的信息 + 自然指向长文”，不是把卡图再复述一遍，也不承担完整长论证。
- `02_卡片正文（纯文本）.txt` 默认以 **600 个后台口径字符**为中心，允许 **±10%**，即正文目标区间为 **540–660 字符**。正文要兼顾手机、电脑等多端展示，按语义自然分段；**单段约 120 字只作为偏长提醒值，不是平台限制或验收红线**。超过时复核多端可读性与表达完整性，确有完整表达需要可以保留，不得为了卡数字机械拆句或拆段。这里的正文仍是“钩子 + 卡图未讲的信息 + 自然指向长文”，不能为了凑到 600 字复述卡图、堆同义句或增加无来源内容。当前项目仍按“标题 + 正文不超过 1064 个字符”留出安全余量，但这是项目实测口径，不冒充平台永久承诺。
- 若原文特别短，能够补入的机制、例子、台词和边界仍不足以让正文自然达到 540 字，应在 Gate A 明确报告当前可写长度、缺少的素材和继续扩写的风险，并先询问用户是否接受短于 540 字的例外；未获确认前不得自行注水，也不得虚构家庭经历、数字或因果。
- 写作前列“卡图已经讲了 / 描述只补没讲的”对照，避免同一故事读两遍。
- 描述扩写或改稿后必须重新制作一次“卡图已讲／描述只补”重复度对照，不能沿用扩写前的判断。
- 末段给出阅读长文的具体理由，用陈述句自然指路，例如“完整的三封信留在长文里”；不写“点击原文、戳这里、赶紧关注”等动作指令。
- 纯文本不假设富文本能力；用自然段和空行组织。若后台支持范围有变化，以当次可见界面和官方说明为准。
- 字符数统一使用 `工具脚本/卡片正文字数核算_check.py` 核算；计数对象是最终粘贴到后台的完整 `02_卡片正文（纯文本）.txt`，若话题标签随正文粘贴，标签也计入总字符数，`01_标题作者摘要.txt` 标注的字符数必须与最终 `02` 实测一致。计数前将 CRLF 归一化为一个换行符；程序写入 Windows 文本时显式控制换行，完成后检查不存在 `\r\r\n`。动作词检测使用完整短语，不用单字黑名单造成误报。

## 五、视觉与文件

- 项目当前目标为竖版 3:4、合计 3–5 张（张数按内容厚度定）；建议画布 1242×1656。单张目标小于 100KB，但交付前须按当前后台实测确认，不把项目值写成普遍平台承诺。
- 本家庭教育项目的卡片底图默认采用**无人物、弱时间线**方案：封面卡与收尾卡可用日常静物，但文字安全区必须保持干净；中间内容卡优先纯色或轻微渐变，不铺人物照片或复杂场景。人物底图容易额外暗示年龄、关系与故事时点，确需使用时应在 Gate B 单独确认。
- 每篇通常准备两张无文字视觉底图，分别供封面卡与收尾卡使用；内容卡保持纯色或轻渐变。使用何种生成工具、是否产生额度／费用以及是否需要事前提示，按当前 Codex 图像工具规则执行，不沿用 WorkBuddy 的积分口径。
- **卡图文件名必须在公众号素材库全局唯一，不能依赖本地文件夹提供上下文。** 每个系列在 Gate A 前分配一个不可复用的系列资产码，并登记到项目级素材命名登记表。资产码使用 4–12 位大写英文字母或数字，以英文字母开头；同一系列后续不得换码，已占用的码不得分配给其他系列。
- 新卡图正式文件名统一为：`<系列资产码>_<中文系列短名>_第<两位篇号>篇_卡片_<两位卡序>_<角色>_v<两位版本>.jpg`。角色只用`封面`、`内容`、`收尾`；示例：`HZYJSJ_孩子与手机_第01篇_卡片_01_封面_v01.jpg`。系列码解决跨系列重名，篇号与卡序解决系列内重名，版本号解决返工或重复上传重名。
- 任何像素、文字或来源标注发生变化，都递增版本号；不得用同名文件覆盖公众号素材库中的旧版本。完全相同的本地副本可以保留同名，但再次上传前若素材库已有该名称，也必须递增版本号。预览图使用`_预览`后缀并与正式上传目录隔离，禁止上传。
- Gate A 必须列出系列资产码、中文短名和逐卡预计文件名；正式交付时生成上传清单，并在全系列范围检查 basename 不重复。自检还必须核对同一系列只使用一个资产码、文件内篇号与所在发布包一致、卡序连续、角色与卡位一致。
- 同一资源池中的底图、渲染配置和成品也必须带系列资产码、篇号和版本号，防止跨系列覆盖。旧系列已交付文件不强制追溯改名；需要重新上传或用户点名升级时，按新规则生成新版本。
- 卡片文字用确定字体后期排版，不要求图像模型生成中文。文字几何以实际边界测量为准，不用字号近似文字墨迹高度；尤其检查下伸笔画、行首标点、重叠、出界和高亮块切字。
- 渲染器应记录每个文字块与容器的实际坐标；安全区、越界、重叠、间距和密度优先读取这些白盒记录，再退回图像实测，最后才是人工目测。可靠性顺序为：**渲染记录 > 图像实测 > 人工目测**。
- 卡片文案优先使用纯中文表达，避免用字体可能不支持的勾叉、特殊序号或装饰符号。确需特殊字符时先做字形反向测试；检测异常不得静默当作通过。
- 若卡片第一张会被平台裁成其他比例展示，关键标题、署名和改编标注放在当前后台预览确认的安全区；不凭历史固定坐标硬套。
- 每一张卡都是可能脱离上下文独立传播的单元。逐张沿用长文对应段落的内容类型：用户确认的真实经历用身份标注，课程案例／改编情节用改编标注，第三方案例用来源标注；不得把整篇一律标成“改编”，也不能只标第一张。
- 使用当前图像工具及其标识规则；不自动移除第三方来源标记。逐张目检尺寸、体积、错字、人物、标注、安全区和画面完整性。至少抽查一张信息最密的中间卡原尺寸图，再检查逐篇预览和全系列合并预览；缩略图只能看节奏，不能替代原尺寸的字距、截断与可读性验收。
- 视觉判断与几何判断分开：错字、语义、来源标注靠人工目检；留白、间距、越界、重叠和文字墨迹边界必须先测量再改参数，不能仅凭缩略图观感调整。

## 六、发布包与迁移

### 待验收区与正式组包

Gate B 通过只代表视觉方向获批，不代表可以边渲染边写入正式发布包。批量成品先落在 `_过程文件/卡片文章/卡片成品_待验收/第NN篇/`，并在这里完成数量、全局唯一命名、尺寸、体积、密度、文字边界、来源标注、篇号与卡序的整套检查。

待验收区必须生成逐篇预览和全系列总览，并至少以原尺寸检查信息最密的一张卡。所有检查通过后，才复制到各篇 `卡片发布包/`；复制后逐张核对待验收区与正式包 SHA256 一致。迭代修改只发生在待验收区，正式包不得原位重渲染。Gate B 已确认的首张样板若完全不改，可按同一文件名和同一哈希进入正式包；只要像素、文字或标注有变化就递增版本号。

Gate A、Gate B 均通过后，才把对应单篇发布包迁为：

```text
发布包_第01篇_短标题/
  长图文发布包/
    正文_第01篇_短标题.html
    01_标题作者摘要.txt
    封面_第01篇_短标题.jpg
  卡片发布包/              # 后台派生卡片文章
    01_标题作者摘要.txt
    02_卡片正文（纯文本）.txt
    HZYJSJ_孩子与手机_第01篇_卡片_01_封面_v01.jpg
    HZYJSJ_孩子与手机_第01篇_卡片_02_内容_v01.jpg
    ...
```

卡片包的 `01_标题作者摘要.txt` 除后台字段、卡片顺序、来源说明、回溯对照和发布清单外，还应包含一份朋友圈转发文案；它与 `02_卡片正文（纯文本）.txt` 中以 600 字为中心、允许 ±10% 的后台正文是两种不同用途的文案，不得混写。`01` 不重复保存卡片正文全文，避免两处失步。

旧系列未制作卡片的发布包保持原结构，不批量迁移。设计文档与渲染脚本放系列 `_过程文件/` 或 `_档案/`，不塞入正式发布包。

为兼容现有 WorkBuddy 工具，磁盘目录仍叫 `卡片发布包/`，字段文件也沿用现有名称；对用户说明和数据复盘中统一写“后台派生卡片文章”，不再只写含混的“卡片版”。

## 七、交付前检查

- Gate A、Gate B 的确认记录明确，未把概括式“继续”外推到未到关卡；
- 卡片数量不超过已确认值，篇号／顺序号连续；正式文件名符合系列资产码规则，在本地全系列和公众号素材库中均保持唯一，上传清单无重复 basename；
- 卡图尺寸、比例、体积符合当前后台实测；逐张无错字、无重叠、无出界；
- 中间内容卡不是“一屏一句”：每张信息自足，密度目标为 62%–68%，低于 58% 已回到长文补足信息，超过 70% 已删减或换卡型；没有用空行、重复句或缩字填充；
- 卡型与内容结构匹配，没有把三阶段硬塞进两格对照，也没有用缩小字号掩盖过载；
- 每张卡的改编／来源标注在位，封面关键内容在实际安全区；
- 特殊符号已验证字形；信息最密卡完成原尺寸检查，并已核对逐篇预览与全系列合并预览；
- 所有文案可回溯长文，数字、人物与时间线一致；
- 纯文本描述在目标区间，只补卡图未讲的信息，末段自然指向长文，无动作指令；
- `01` 所写字符数与最终 `02`（含随正文粘贴的话题标签）实测一致，换行已归一化且不存在重复回车；
- Gate A 设计与渲染配置的逐卡比对已经输出，节点数、段落数、字量与密度无未说明偏差；几何断言优先采用渲染记录，并完成信息最密卡的原尺寸人工复核；
- 正式包只含交付文件，过程资产已归位；迁移后长图文三件套仍齐全；
- 待验收区与正式卡图逐张 SHA256 一致，正式目录没有迭代期的临时渲染物；
- 报告哪些规则来自当前后台、哪些是项目实测、哪些只是编辑建议。

## 八、发布后复盘

文章本体与后台派生卡片分行记录：载体、发布时间、通知状态、流量来源构成、阅读／曝光（后台提供什么记什么）、平均停留、分享、评论、新增关注和 24 小时／7 天表现。

- 不比较两个载体的原始阅读量，不用“谁阅读高”判断谁的内容或封面更好；
- 不把账号／日期级送达人数分配给单篇；
- 分别与各自同载体历史基线比较，优先看中位数，并检查极端值；
- 数据、用户确认的运营事实和编辑推断分栏写；
- 没有导流点击等指标就明确写“暂不可验证”，不能用曝光或阅读代替；
- 真正的 A/B 必须事前定义单一变量、可比样本和观察窗口。两个载体天然不同，不构成 A/B；
- 至少积累约 20–30 个可比样本后，再把稳定结论升级为长期 SOP。
