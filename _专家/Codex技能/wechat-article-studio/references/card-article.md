# 后台派生卡片文章（贴图）

仅在用户明确要求为已经定稿的公众号长文制作卡片文章时读取。它是可选增量，不因长文完成而自动触发。

## 一、先把三个概念分开

- **文章本体**：长图文 HTML、字段表和 2.35:1 封面组成的正式长文。
- **正文内干货卡**：长文 HTML 中用 `section` 绘制的清单、步骤或对照色块。
- **后台派生卡片文章（贴图）**：同一长文发布后，在公众号后台生成或编辑的竖版卡片传播载体；本技能为它制作可控的卡图、纯文本描述和字段资料。

后台派生卡片与文章本体是“一份内容、两个载体”。禁止写成：

- 两个封面版本或封面 A/B；
- 两篇独立文章或两条内容产线；
- 把系统自动生成的卡片直接等同于本技能人工设计的卡片发布包。

## 二、两道确认关卡

### Gate A：设计文档确认

先只交付一份卡片设计文档，包含：

1. 已定稿长文的段落编号与素材回溯；
2. 拆卡表及每张叙事职责，并写明张数依据（长文有几个独立核心意思、为何这样定、哪些已合并或为何不合并）；
3. 取舍说明：卡图讲什么、描述只补什么；
4. 纯文本描述全文、字符核算和话题标签草案；
5. 标题与后台字段草案；
6. 人物、数字、时间线与长文正文的一致性核对。

用户当次明确确认前，禁止生底图、试渲卡片、建正式卡片发布包、迁移目录或运行图片后处理。只允许做只读的字数、段号和一致性核算。

### Gate B：封面卡风格确认

Gate A 通过后，先做首张封面卡样板。用户当次明确确认风格前，不批量渲染其余卡、不组装正式包、不迁移目录。后续篇若用户明确要求沿用已经批准的同系列风格，可不重复 Gate B。

## 三、内容设计

- 长文是唯一素材源；存量补做时只读已定稿长文，不反向修改长文迁就卡片。
- 张数按内容厚度定，不固定套用某一公式：先数长文里有几个互不重复、能独立成立的核心意思（一条判断加它的支撑），一个意思单元配一张内容卡。
- 结构固定为“封面 1 张 + 内容 N 张 + 收尾 1 张”，但 **N 不固定**。内容卡以 3 张作为编辑时的优先建议起点，再按长文中互不重复、能独立成立的核心意思增减：只有 1–2 个核心意思时就用 1–2 张，不能为了凑成 3 张制造薄卡；确有 4 个以上核心意思且无法用合适卡型合并时，可以建议超过 3 张，但须在 Gate A 说明原因并取得用户确认。
- Gate A 必须逐篇给出“建议内容卡数量、建议总张数和判断依据”，不能只套用全系列统一张数。当前常用区间是首页 1 张、内容 1–3 张、收尾 1 张，合计 3–5 张；这是编辑策略，不冒充平台上限。
- 不为凑张数把一个意思拆成两张（那是空卡），也不为省事把几个独立意思硬塞进一张（那是过载）。意思单元达到四个以上时，先用对照卡、时间线卡或四宫格把同类并进一张，而不是加卡。
- 篇幅偏少不是缺陷：实测反馈是张数越多越容易掉量，三张（内容卡一张）在某些篇就是正解。同一系列内各篇张数不必相同，但同一篇内各内容卡的厚薄应当相当。
- 每张卡都应能独立看懂，同时只承担一个清楚任务：钩子、机制、方法／对照、转折、情绪落点。并列内容必须围绕同一核心动作，不把不同层级的抽象词硬凑在一起。
- **“一屏一意”不等于“一屏一句”**。中间内容卡默认应有“1 个核心判断 + 2–4 个解释点／步骤／边界／可照念台词”，通常形成 3–4 个信息块；若只剩一句金句或一小段摘要，应回到长文补足本屏需要的机制与行动信息，而不是靠增加卡数解决。
- 中间卡正文建议占可用内容区约 **45%–65%**。低于约 40% 时先检查信息是否过薄，再考虑适度调整字号、行距和垂直位置；不得用空行、同义重复或无据结论“填满”。高于约 70% 或需要明显缩小正文字号时，应删减或拆解，优先保证手机阅读。
- 先按内容结构选卡型：单一主题论证用内容卡，恰好两组差异用对照卡，三个及以上顺序节点用时间线卡，四个并列概念才用四宫格。某一格明显过载、需要压小字号或挤占署名区，通常说明卡型选错，应换卡型而不是硬塞。
- 卡片不是长文截图，也不是逐段摘要。重新组织为“一屏一意”，保留关键事实与边界，不补写长文里没有的经历、数字或因果。
- 卡图上的文字、人物年龄、篇号、步骤数和时间数字必须与长文正文逐项核对；字段表或旧摘要与正文冲突时，以已定稿正文为准并报告冲突。

## 四、纯文本描述

- 定位是“钩子 + 卡图未讲的信息 + 自然指向长文”，不是把卡图再复述一遍，也不承担完整长论证。
- 项目默认目标 200–350 个中文可见字符，每段尽量不超过 120 字；这属于当前编辑经验，不是平台永久承诺。后台硬限制、换行计数和字段位置在每次制作时以当前后台显示为准。
- 写作前列“卡图已经讲了 / 描述只补没讲的”对照，避免同一故事读两遍。
- 末段给出阅读长文的具体理由，用陈述句自然指路，例如“完整的三封信留在长文里”；不写“点击原文、戳这里、赶紧关注”等动作指令。
- 纯文本不假设富文本能力；用自然段和空行组织。若后台支持范围有变化，以当次可见界面和官方说明为准。

## 五、视觉与文件

- 项目当前目标为竖版 3:4、合计 3–5 张（张数按内容厚度定）；建议画布 1242×1656。单张目标小于 100KB，但交付前须按当前后台实测确认，不把项目值写成普遍平台承诺。
- 本家庭教育项目的卡片底图默认采用**无人物、弱时间线**方案：封面卡与收尾卡可用日常静物，但文字安全区必须保持干净；中间内容卡优先纯色或轻微渐变，不铺人物照片或复杂场景。人物底图容易额外暗示年龄、关系与故事时点，确需使用时应在 Gate B 单独确认。
- 卡图文件名必须带两位篇号和两位顺序号：`第01篇_卡片_01_封面.jpg`。同一资源池中的底图、配置和成品也带篇号，防止跨篇覆盖。
- 卡片文字用确定字体后期排版，不要求图像模型生成中文。文字几何以实际边界测量为准，不用字号近似文字墨迹高度；尤其检查下伸笔画、行首标点、重叠、出界和高亮块切字。
- 卡片文案优先使用纯中文表达，避免用字体可能不支持的勾叉、特殊序号或装饰符号。确需特殊字符时先做字形反向测试；检测异常不得静默当作通过。
- 若卡片第一张会被平台裁成其他比例展示，关键标题、署名和改编标注放在当前后台预览确认的安全区；不凭历史固定坐标硬套。
- 每一张卡都是可能脱离上下文独立传播的单元。逐张沿用长文对应段落的内容类型：用户确认的真实经历用身份标注，课程案例／改编情节用改编标注，第三方案例用来源标注；不得把整篇一律标成“改编”，也不能只标第一张。
- 使用当前图像工具及其标识规则；不自动移除第三方来源标记。逐张目检尺寸、体积、错字、人物、标注、安全区和画面完整性。至少抽查一张信息最密的中间卡原尺寸图，再检查逐篇预览和全系列合并预览；缩略图只能看节奏，不能替代原尺寸的字距、截断与可读性验收。
- 视觉判断与几何判断分开：错字、语义、来源标注靠人工目检；留白、间距、越界、重叠和文字墨迹边界必须先测量再改参数，不能仅凭缩略图观感调整。

## 六、发布包与迁移

Gate A、Gate B 均通过后，才把对应单篇发布包迁为：

```text
发布包_第01篇_短标题/
  长图文发布包/
    正文_第01篇_短标题.html
    01_标题作者摘要.txt
    封面_第01篇_短标题.jpg
  卡片发布包/              # 后台派生卡片文章
    01_标题作者摘要.txt
    02_卡片正文（纯文本）.txt
    第01篇_卡片_01_封面.jpg
    第01篇_卡片_02_内容.jpg
    ...
```

旧系列未制作卡片的发布包保持原结构，不批量迁移。设计文档与渲染脚本放系列 `_过程文件/` 或 `_档案/`，不塞入正式发布包。

为兼容现有 WorkBuddy 工具，磁盘目录仍叫 `卡片发布包/`，字段文件也沿用现有名称；对用户说明和数据复盘中统一写“后台派生卡片文章”，不再只写含混的“卡片版”。

## 七、交付前检查

- Gate A、Gate B 的确认记录明确，未把概括式“继续”外推到未到关卡；
- 卡片数量不超过已确认值，篇号／顺序号连续且文件名唯一；
- 卡图尺寸、比例、体积符合当前后台实测；逐张无错字、无重叠、无出界；
- 中间内容卡不是“一屏一句”：每张信息自足，正文密度与留白均衡；低密度卡已回到长文补足信息，而不是用空行或重复句填充；
- 卡型与内容结构匹配，没有把三阶段硬塞进两格对照，也没有用缩小字号掩盖过载；
- 每张卡的改编／来源标注在位，封面关键内容在实际安全区；
- 特殊符号已验证字形；信息最密卡完成原尺寸检查，并已核对逐篇预览与全系列合并预览；
- 所有文案可回溯长文，数字、人物与时间线一致；
- 纯文本描述在目标区间，只补卡图未讲的信息，末段自然指向长文，无动作指令；
- 正式包只含交付文件，过程资产已归位；迁移后长图文三件套仍齐全；
- 报告哪些规则来自当前后台、哪些是项目实测、哪些只是编辑建议。

## 八、发布后复盘

文章本体与后台派生卡片分行记录：载体、发布时间、通知状态、流量来源构成、阅读／曝光（后台提供什么记什么）、平均停留、分享、评论、新增关注和 24 小时／7 天表现。

- 不比较两个载体的原始阅读量，不用“谁阅读高”判断谁的内容或封面更好；
- 不把账号／日期级送达人数分配给单篇；
- 分别与各自同载体历史基线比较，优先看中位数，并检查极端值；
- 数据、用户确认的运营事实和编辑推断分栏写；
- 没有导流点击等指标就明确写“暂不可验证”，不能用曝光或阅读代替；
- 真正的 A/B 必须事前定义单一变量、可比样本和观察窗口。两个载体天然不同，不构成 A/B；
- 至少积累约 20–30 个可比样本后，再把稳定结论升级为长期 SOP。
