# 存量巡检与清理

仅在用户要求维护公众号成品时使用，不因为写文章就扫描或整理整个个人目录。

## 巡检

新系列走严格检查，旧系列使用 legacy。排除备份、过程文件和派生预览，不能把它们重复计入正式系列数量。

结果分四类报告：**明确缺陷**（真实性冲突、人设或年级冲突、无据数字、来源错配、高风险误导、`data-*` 污染、标题三处不一致）、**历史格式差异**（02 指南为 .md、来源口径不同、早期包无字段表——不是缺陷、不动）、**质量优化**（标题同质、语言指纹重复、系列过长、方法空泛、视觉识别分散、篇幅明显偏离区间、五层完整性缺项——只列建议，不擅自批量改）、**需要内容判断**（真实经历确认、叙事边界、标题风格偏好、数据解读）。报告给出具体文件与证据。**技术自检全部通过不等于内容质量已经通过**，两类都要报。

只读检查请求不授权修复；用户要求修复时，可在已授权范围内处理明确缺陷并复检，无须重复请示。标题版本冲突等实质取舍若无可靠依据，展示两个版本再确认。

## 清理

未圈定范围的“清理一下”先形成只读清单：建议移除的可重建文件、需要保留的本轮恢复副本、需确认的素材，以及仅需归位的过程文件。展示原路径、大小、理由和拟操作，让用户确认具体范围。已经明确列出并授权的路径无需再确认一次。

执行前验证绝对路径仍在授权目录内，避免越界。保留清单，系统回收站分批处理，每批最多 10 项，异常立即核对。不要以目录消失单独证明已经进回收站；应同时核实恢复信息，无法确认时如实说明，不能因异常盲目重复删除。

旧环境记录 send2trash 在中文路径下可能成功后仍抛异常，需核实实际状态，而非忽略所有错误。禁止用另一种删除方式绕过权限拒绝。

正式成果、原始资料、历史 `.md` 指南、未确认素材均不擅动。`长图文发布包/` 与 `卡片发布包/` 都是新结构下的正式成果目录，不得当作多余文件或过程目录；若只有后一目录而前一目录缺失，报告为迁移不完整，不自动搬动。已授权整理的候选图和后处理脚本移至系列 `_过程文件/`，保留复用价值。本轮修复前副本通常留到发布验证后。

`.gitignore` 不会自动解除已跟踪文件；确需版本库治理时单独核对索引与工作树，不能把取消跟踪等同于删除文件。此技能不自动提交、推送或修改全局 Git 配置。

清理后复检正式成果和引用关系，报告已处理路径、保留项、恢复位置、验证结果与未完成项。

## 合并系列与阶段目录收口

把两个或多个旧系列合并为新系列时，原始资料与旧生成成果必须分开判断：课程原件、逐字稿、原图等原始资料先复制进新系列的 `原始材料/`，生成文件清单与 SHA256，并与旧目录逐一核对；旧正文、旧封面和旧过程文件可在新系列完整交付且用户明确要求移除后退出，但不得把它们误当原始资料一起丢失。

移除旧系列前至少确认：新系列长图文、封面、后台派生卡片、系列手册、预览、上传清单与自检报告均已完成；记录旧目录文件数、总大小、迁移后的原件位置、哈希核对结果和待移除的绝对路径。删除仍使用可恢复的回收站方式；若系统接口只能证明源目录消失、不能枚举回收站恢复项，必须把“恢复位置未能独立验证”写入记录与交付说明。

清理 `样板_*`、旧预览或其他阶段目录前，不只检查文件是否重复，还要搜索脚本、手册和预览生成器的调用关系。若仍有调用方，先改为读取正式发布包，重建预览并核对篇数；清理后再次搜索残留引用并运行全系列自检。阶段目录清掉后出现的错误，不能以“文件本来就重复”为理由放行。

## 过程文件"定时过期"机制（2026-09-11）

过程文件随时间累积，靠人工记着清不现实。按**可重建性**分级设保留期，用脚本定期扫描：

| 类 | 内容 | 默认保留 |
|---|---|---|
| A | 完全可重建（`_预览/` 预览页） | 7 天 |
| B | 一次性快照（`_backup*`、`_备份/`） | 7 天 |
| C | 素材类（`_封面候选/`、`_过程文件/`、`_未采用*/`、`_原始*/`、`_归档*/`） | 14 天 |
| D | 长期归档（`_档案/`、`_资产/`） | 不过期 |

扫描工具：`工具脚本/过程文件过期扫描_scan_stale.py`（只读；`--out` 出报告、`--list A` 列路径、`--keep-days` 覆盖）。**判龄只看「文件真实最后修改时间」，不看目录自身时间。**

⭐ **快照总目录逐项判龄**：`_备份/` 这类目录的子项各自是一次独立快照，不能按整体判龄——整体取"内部最新文件"会让**新快照把旧快照的超期掩盖掉**（实测容器报 1 天，内部 17/34 项已 7–19 天）。脚本会自动识别并**逐快照展开**。凡"内含多个独立条目"的目录，判龄都要下沉到条目层。

节奏：每 1–2 周跑一次；A/B 类超期可批清，C 类超期先确认复用价值（候选图带提示词，删前摘进手册）。删除仍须走回收站 + 分批 ≤10 + 逐批核对 + 清后复检，清前先 git commit。

**⚠️ git 只在"目录被跟踪"时才兜底**：过程目录通常已被 `.gitignore` 排除 → 全部未跟踪 → `git commit` 对它们无效。清理前先 `git ls-files --error-unmatch <路径>` 实探；未跟踪时回收站是唯一退路，**清单留档为必需项**。

**⚠️ `send2trash` 误报**：中文路径下常抛 `FileNotFoundError`/`PermissionError` 却**实际已成功入回收站** → **绝不能凭异常判成败**，必须以 `os.path.exists()` 复核。目录级**真失败**时降级为"逐文件 + 最后清空目录"；"部分删除"（留空骨架 + 残留文件）**重试一次即可收口**。

**⚠️ 清后自检的预期副作用**：清理 A 类 `_预览/` 后，自检的【8】合并预览页**必然报 ❌**（该项就是检测预览页存在性），其余各项应全 ✅。→ **先重建预览再跑自检**，否则会误判为"清理弄坏成果"。

**重建预览优先用「各系列自带 `_build_preview.py`」**（统一输出本系列 `_预览/`）。通用脚本 `重建全部正文预览.py` 曾把预览写到系列根目录（逃出 `_预览/` 与 `.gitignore`、被误当正式产物），2026-09-21 已修。**结构迁移必须连脚本一起扫**——散落各系列的旧脚本不会自动跟进（实测某系列仍用旧路径模式 → 不认新结构 `长图文发布包/` → 静默产出"0 篇"空预览）。**重建后必须核对预览页篇数**。

**复检常能翻出存量 bug**（2026-09-21 一次复检揪出 3 个）。→ 报错先分**"预期副作用 / 清理致损 / 存量 bug"**三类定性，**归属未查明前不要改任何成品**。

**⚠️ C 类删除前必须先"摘提示词"（14 天较短，易丢资产）**：C 类里最值钱的是封面候选图的生成提示词。清理前把该篇**最终采用提示词**（或"意象 + 关键约束"）摘进该系列 `03_发布手册.md` 封面小节；未采用的意象也记一行备选。**已摘录的才可清；未摘录的不清；未定稿系列的候选图不动。**
