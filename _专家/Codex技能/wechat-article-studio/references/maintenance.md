# 存量巡检与清理

仅在用户要求维护公众号成品时使用，不因为写文章就扫描或整理整个个人目录。

## 巡检

新系列走严格检查，旧系列使用 legacy。排除备份、过程文件和派生预览，不能把它们重复计入正式系列数量。

结果分四类报告：**明确缺陷**（真实性冲突、人设或年级冲突、无据数字、来源错配、高风险误导、`data-*` 污染、标题三处不一致）、**历史格式差异**（02 指南为 .md、来源口径不同、早期包无字段表——不是缺陷、不动）、**质量优化**（标题同质、语言指纹重复、系列过长、方法空泛、视觉识别分散、篇幅明显偏离区间、五层完整性缺项——只列建议，不擅自批量改）、**需要内容判断**（真实经历确认、叙事边界、标题风格偏好、数据解读）。报告给出具体文件与证据。**技术自检全部通过不等于内容质量已经通过**，两类都要报。

只读检查请求不授权修复；用户要求修复时，可在已授权范围内处理明确缺陷并复检，无须重复请示。标题版本冲突等实质取舍若无可靠依据，展示两个版本再确认。

## 清理

未圈定范围的“清理一下”先形成只读清单：建议移除的可重建文件、需要保留的本轮恢复副本、需确认的素材，以及仅需归位的过程文件。展示原路径、大小、理由和拟操作，让用户确认具体范围。已经明确列出并授权的路径无需再确认一次。

执行前验证绝对路径仍在授权目录内，避免越界。保留清单，系统回收站分批处理，每批最多 10 项，异常立即核对。不要以目录消失单独证明已经进回收站；应同时核实恢复信息，无法确认时如实说明，不能因异常盲目重复删除。

旧环境记录 send2trash 在中文路径下可能成功后仍抛异常，需核实实际状态，而非忽略所有错误。禁止用另一种删除方式绕过权限拒绝。

正式成果、原始资料、历史 `.md` 指南、未确认素材均不擅动。已授权整理的候选图和后处理脚本移至系列 `_过程文件/`，保留复用价值。本轮修复前副本通常留到发布验证后。

`.gitignore` 不会自动解除已跟踪文件；确需版本库治理时单独核对索引与工作树，不能把取消跟踪等同于删除文件。此技能不自动提交、推送或修改全局 Git 配置。

清理后复检正式成果和引用关系，报告已处理路径、保留项、恢复位置、验证结果与未完成项。

## 过程文件"定时过期"机制（2026-09-11）

过程文件随时间累积，靠人工记着清不现实。按**可重建性**分级设保留期，用脚本定期扫描：

| 类 | 内容 | 默认保留 |
|---|---|---|
| A | 完全可重建（`_预览/` 预览页） | 7 天 |
| B | 一次性快照（`_backup*`、`_备份/`） | 14 天 |
| C | 素材类（`_封面候选/`、`_过程文件/`、`_未采用*/`、`_原始*/`、`_归档*/`） | 90 天 |
| D | 长期归档（`_档案/`、`_资产/`） | 不过期 |

扫描工具：`工具脚本/过程文件过期扫描_scan_stale.py`（只读；`--out` 出报告、`--list A` 列路径、`--keep-days` 覆盖）。

节奏：每 1–2 周跑一次；A/B 类超期可批清，C 类超期先确认复用价值（候选图带提示词，删前摘进手册）。删除仍须走回收站 + 分批 ≤10 + 逐批核对 + 清后复检，清前先 git commit。
