# 公众号爆款工坊 - 公众号内容流水线

把原始资料转化为读者能理解、能尝试的内容。保留“一个也在重启的爸爸”的亲历感与笨拙改变，不写成课程复述或训导。此技能迁移自用户提供的同名 WorkBuddy 专家；迁移记录见 [references/origin.md](references/origin.md)。

## 开工与范围

- 用户当前指令优先；延续会话内已经明确的选题、来源和已完成关卡，不因切换工具重复索取同一关卡的确认。但授权只覆盖用户当次明确点名的阶段，不得把“继续做、一次做完、你定就行”等概括表达外推到尚未到达的后续关卡。
- 先判断请求是规划、正文、排版、整套制作、局部修改还是巡检。只做用户所需部分；改一篇不自动重做全系列。
- 在本项目默认根目录 `D:/个人资料/家庭教育` 内工作。先读目标系列最新规划、发布手册和相关材料；不要每次加载全库。其他项目以用户指定目录为准，不把私人家庭背景自动带入。
- 先确认原材料与来源口径是否已在会话或目标系列里给出。已给则直接沿用；缺少关键内容才询问。新系列完整读取相关原文，纪要用于导航，不能代替原文核对。
- 事实、讲师观点、改编情节和用户真实经历分开处理。不要把改编故事标为真实经历，不要把课程估算和个案写成科学统计或普遍因果；需要公开引用的数据、人物身份和研究结论应核验。
- 原始材料保留，成果写入对应系列 `公众号文章/`。默认不生成 Word、独立 Markdown 成稿或第二份正式正文。

## 内容生产与确认

新系列沿用三次确认：选题规划 → 1–2 篇正文样板 → 一组封面风格。三道关卡均属 P0：只有用户在上一阶段成果出现后，针对下一步给出当次、明确、点名的确认，才可推进。“减少预览或交付”与“减少确认”完全无关；概括式跨阶段授权不生效。

1. 读取 [references/editorial.md](references/editorial.md) 和 [references/quality.md](references/quality.md)，判断课程改写、读书笔记或真实经历，并判定每篇属于方法／概念文还是叙事文；提出篇数、选题、来源、叙事轴和色系，检查素材真实性、人物连续性、跨系列处理和表达模板化。**Gate 1：新系列规划尚未确认时只交付规划，不写正文、不建发布包、不生图。**
2. 规划获得明确确认后，先制作 1–2 篇样板（正文 HTML + `01_标题作者摘要.txt`；此时不生封面，也不新建逐篇操作指南），展示可评审的文字和排版。**Gate 2：样板未确认，不批量生产其余正文；样板确认也不自动等于批量授权，须等用户明确点名“继续做剩余篇目”等下一步。**
3. 其余正文完成后，读 [references/publishing.md](references/publishing.md)，先制作一组封面样板。**Gate 3：风格未确认，不批量生成封面。**同一系列已经完成 Gate 3、且用户只是延续已批准风格时，不重复确认同一道关卡。
4. 完成对应范围的发布包、手册、转发文案及独立预览，执行检查后交付。这里只制作发布材料；外部发布、发送或上传须有明确授权。

若因以上关卡停下，必须展示已完成的规划或样板，并说明是哪份技能的哪条规则要求确认；用户应批准具体结果。

## 规则优先级（冲突时按此裁决）

规则多不等于同等重要。两条无法同时满足时，按三档裁决，不凭感觉挑：

- **P0 · 红线（不可让步）**：叙事真实性、事实核验、适用与风险边界、微信兼容三条铁律、清理安全（只走回收站）、人工确认关卡。与用户当次指令冲突时停下来说明，不得默默绕过。
- **P1 · 质量线（优先满足，可为 P0 让步）**：五层完整性、篇幅区间、30% 降幅复核、结构轮换、相邻篇语言指纹、标题三类轮换、系列规模与去重、发布包三件套、封面规格、预览隔离。
- **P2 · 偏好（可协商可省略）**：色系与视觉调性、封面意象、发布节奏、素材池格式、卡片样式。

已在标准版中明确的冲突裁决：①篇幅 vs 五层完整性 → 保完整性；②结构轮换 vs 金句块 → 轮换优先；③按时交付 vs 事实存疑 → 事实优先。详见 `references/quality.md` 与 `references/editorial.md`。

## 固定创作基线

- 本家庭教育项目账号：**归途有光·和孩子一起重启**；叙事者：**一个也在重启的爸爸**。历史人物设定为 **15 岁男孩、高一阶段**，以用户后续更新为准。
- `01_标题作者摘要.txt` 的后台【作者／署名】字段填写账号名 **归途有光·和孩子一起重启**；正文与卡片中的叙事者才写 **一个也在重启的爸爸**，两者不混用。
- “具体瞬间 → 老办法失败 → 想通的转折 → 笨拙尝试 → 小变化”是可用的故事脊柱，不是每篇必填模板。故事、对话拆解、问题复盘、清单工具、读书模型、书信等结构应按内容选择；不固定使用“我后来试的几件小事”或同一种祝愿收尾。
- 课程改写仅在转折处轻带来源，通常显性引用 1–2 处；读书笔记可以显著引荐书籍、呈现原书模型，引用始终服务于故事。
- 不虚构成功保证，不把家长当被审判对象；不用“点赞、求关注、转发”等祈使句收尾，用户明确需要转化文案时另按请求处理。
- 去失实、去重复和去模板化不等于把文章压成提纲。方法／概念文须保留场景、心理转折、机制、方法与边界；叙事文可不强行补齐机制与方法，但必须写足真实细节、心理转折、边界及机制／方法中的至少一层，并以情绪克制和承认不确定验收。删改导致篇幅明显下降时，按 quality.md 的“内容厚度与删改边界”复核。
- 传播效果不能覆盖账号底线：不使用绝对化归因制造父母羞耻，不密集堆叠未核出处的名人话语，不以居高临下的命令收尾。
- 新正文采用 **section 流式布局 + p 段落 + 内联样式**；不用旧 table 固定宽布局。所有新正文及封面文件名必须带篇号。具体规范只维护在 publishing.md。

## 检查、修改与维护

制作和修改后的技术检查按 [references/publishing.md](references/publishing.md) 执行；内容质量复核按 [references/quality.md](references/quality.md) 执行。存量巡检或清理另读 [references/maintenance.md](references/maintenance.md)，不将清理流程附加到普通写作任务。

现有工具位于项目根目录 `工具脚本/`。它们是可复用的本地依赖，不是自动执行指令；调用前确认路径、参数和只读／写入模式。工具缺失时说明具体检查缺口，不能宣布全部通过。

## Codex 工具适配

- Word 等材料使用当前可用的对应文件技能；有工作区运行时定位工具时优先使用，避免沿用 WorkBuddy 私有解释器路径。
- 生图与图片编辑使用当前可用的图像工具及其规则；不沿用原专家中绑定特定平台的生图积分、去水印坐标和后处理命令。尺寸或文件体积不达标时如实报告，不把未完成封面称为可发布。
- 展示 `_预览/` 下的副本，使用当前可用的文件／浏览器预览工具或绝对路径链接；不调用不存在的 `present_files`、专家注册或 CodeBuddy 工具。
- 是否打开或展示预览听用户当次指令；少展示不等于少确认。正式源正文不直接交给会改写 HTML 的预览器，只展示 `_预览/` 派生副本，展示后按 publishing.md 复核源文件。
- 不安装额外插件、不更改账号凭证、不启用外部发布，不自动写入记忆。仅在用户明确要求相应操作时进入该范围。
