# 第 3 步 · 技法卡提炼与可迁移度判定

> 目标：把拆解报告里的发现，切成**独立可复用的最小单元**，判定能不能搬到本账号，写入技法库。
> **立卡质量决定技法库的价值**——卡立歪了，以后照搬就翻车。

---

## 一、什么才算"一张卡"

### 立卡标准

一张卡 = **一个独立可复用的写作动作**。判定方法：

| 测试 | 通过条件 |
|---|---|
| **独立性** | 单独看这张卡，能明白怎么用，不需要同时看其他卡 |
| **可执行性** | 读完能**立刻动手写**，不是"要有共情"这种概念 |
| **最小性** | 不能再拆——再拆就只剩"用好词"这种废话 |
| **可迁移性** | 能脱离原文的具体内容，搬到别的题材 |

### 立卡 vs 不立卡

**✅ 该立卡**：
- "用具体时间点开头代替抽象感慨"（`昨晚9点47分，我第三次从床上爬起来`）
- "把标题写成对话姿态而非命令姿态"（`孩子，我为什么不让你玩手机？`）
- "结尾用一句对仗短句收束，不用动作指令"

**❌ 不该立卡**：
- "情绪要饱满"（概念，无法执行）
- "这个选题好"（不是技法，是判断）
- "用了很多金句"（描述现象，不是可复用动作）
- "文章结构是总分总"（这是拆解发现，属于报告，不是技法——除非能提炼出"什么样的题适合总分总"）

> **判据：能不能写出一条"下次我这么写"的指令？写不出就别立卡。**

## 二、可迁移度判定（核心）

**唯一标尺：能不能搬到「归途有光·和孩子一起重启」这个账号。**

| 等级 | 判定条件 | 处理 |
|---|---|---|
| `✅ 可直接用` | 与账号定位、人设、读者群、调性均不冲突，拿来即用 | 立卡，写入维度目录 |
| `⚠️ 需改造` | 技法有效，但依赖特定条件（大号背书、虚构案例、强情绪煽动、特定领域黑话、其他读者群） | 立卡，**必须写清改造方案** |
| `❌ 不适用` | 与 P0 红线冲突（编造经历 / 绝对化承诺 / 情绪操纵 / 制造羞耻） | **同样立卡**，顶部标红"本技法不采用"，写明原因 |

### 常见判定情形对照表

| 情形 | 判定 | 说明 |
|---|---|---|
| 用具体场景细节替代抽象论述 | `✅` | 与本账号"叙事化"方向一致 |
| 结尾"点个在看，转发给需要的人" | `❌` | 本账号调性克制，不用动作指令 |
| "90%的父母都做错了" 这类数据断言 | `❌` | 无据数字 + 制造焦虑，双重违规 |
| 用名人名言收尾 | `⚠️` | 可用，但需核实出处真实（本账号要求核不到不写） |
| "低配/高配/顶配" 三段递进结构 | `⚠️` | 结构好用，但这种"分级"表达略带评判感，改造为描述性分级 |
| 第一人称真实经历 | `⚠️` | **关键**：若原文是他人经历/虚构，搬到本账号**必须按改编处理并标注**，不得冒充真实经历 |
| 制造羞耻驱动行动 | `❌` | 直接违反"减少羞耻"账号锚点 |
| 把痛感层层放大但不给出口 | `❌` | 情绪操纵 |
| 用"我注意到你最近……"这类观察式开场 | `✅` | 非评判、可照用 |

### ⚠️ 特别提醒：第一人称技法的陷阱

外部好文章大量使用第一人称叙事。**搬到本账号时必须过这道关**：

1. 原文的"我"是**作者真实经历**吗？（多数头部号的故事其实是改写/虚构/他人案例）
2. 技法本身是"用第一人称"，还是"用第一人称讲了一件具体小事"？
   - 前者可迁移（我们也可以写"我儿子"）
   - 后者**不可迁移**（我们不能把别人的经历说成自己的）

**处理**：标 `⚠️ 需改造`，改造方案写明"可学其**叙事密度**（一件小事讲透一个道理），但故事须替换为本账号真实素材或标注改编"。

## 三、技法卡 6 项必填（缺项不得立卡）

照 `_资产/技法库/_模板_技法卡.md`：

| # | 字段 | 要求 | 常见错误 |
|---|---|---|---|
| 1 | **原始出处** | 文章 + 账号 + **原句照抄** | 只写"某篇文章" |
| 2 | **为什么有效** | 机制解释，猜测须标"推测" | 写"因为这样更打动人"（空话） |
| 3 | **改造示例** | **本账号的具体例句** | 写"可以套用到家庭教育"（没给例子） |
| 4 | **反例与边界** | 什么时候用会翻车 | 留空 |
| 5 | **与既有规则的关系** | 新增/强化/冲突/已验证 | 留空 |
| 6 | **待验证** | 本账号发过后验证了吗 | 谎报"已验证" |

> **第 3 项是本工坊与其他"拆解文"最大的区别**：必须给出**本账号可用的具体例句**，
> 不是"你可以这样用"。例句要贴合"15岁/高一/儿子"的固定人设。

## 四、落盘规则

### 文件命名
- 用**技法名**作文件名，不用编号：`用具体时间点开头代替抽象感慨.md`
- 不用序号是因为技法会增删，编号会乱

### 存放目录
按**技法的主要作用点**归入五个维度之一：
```
01_选题与角度/
02_标题与开头钩子/
03_结构与节奏/
04_情绪曲线与共鸣点/
05_金句与结论收尾/
```
**跨维度怎么办**：归到**最主要**的那一维，在卡内注明"本技法也涉及 XX 维"。

### 一篇文章立几张卡
- **通常 1–3 张**。一篇文章真正值得学的技法很少。
- **可以为 0 张**：如果这篇的写法本账号已有，或全是不可用的套路，就写"本次未立卡"并说明原因。
- **不要为了数量凑卡**。10 张注水卡不如 1 张能照做的卡。

## 五、查重与合并

立卡前**必须查** `00_技法总览.md`：

| 情况 | 处理 |
|---|---|
| 已有一模一样的技法 | **不立新卡**，在旧卡内追加"另一处印证"（附新原句） |
| 已有相似但有新增点 | 立新卡，卡内写明"XX 技法的变体，新增点是……" |
| 与已有卡冲突 | **立卡 + 明确标注冲突**，这是 Gate C 最需要讨论的情况 |

---

## 六、⛔ 立卡纪律

- **不冒充原创**：卡内必须写明原始出处。你研究的是"这篇这么写"，不是"应该这么写"。
- **不夸大**：不写"用了必爆""爆款密码"。**未验证就写"尚未验证"。**
- **不隐瞒不可用**：`❌ 不适用` 的卡**必须立**。它记录了"为什么我们不学这个爆款套路"，
  防止团队以后重复研究、或误以为是好招而照搬。
- **诚实留白**：机制解释若只是猜测，**写"推测"**。硬编因果比说不知道更糟。
