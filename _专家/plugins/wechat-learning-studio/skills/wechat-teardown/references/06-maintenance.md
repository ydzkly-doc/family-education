# 第 7 步 · 技法库维护与效果验证

> 目标：让技法库**越用越准**——把"看起来有效"的技法，验证成"确实有效"的技法。

---

## 一、定期回看（建议每 10–15 张新卡或每月一次）

### 回看三件事

| # | 动作 | 判定 |
|---|---|---|
| 1 | 检查 `⚠️ 需改造` 的卡 | 已在实践中改造成功的 → 升级为 `✅ 可直接用`，补一句"已验证改造方案" |
| 2 | 检查 `待验证` 的卡 | 本账号发过相关文章后，用发布数据复盘的结果更新状态 |
| 3 | 检查"观察"状态的反哺候选 | 样本够了就提上 Gate C，仍然不够就继续观察 |

---

## 二、与发布数据复盘交叉验证

**这是技法库最有价值的闭环**。

`_资产/发布数据复盘.md` 记录每篇发布后的：标题类型 / 开头类型 / 结构类型 / 阅读分享收藏 / 是否带来关注 / 被引用那句话 / 24h 与 7 天表现。

**验证方法**：
1. 选出某张技法卡，找出本账号**用过该技法**的文章
2. 对比**没用过**该技法的同类文章
3. 看数据是否有差异

**判定纪律**：
- **样本 < 10 篇**：不足以判断，**写"样本不足"**，不要下结论
- **样本 20–30 篇**：可以形成初步判断，写入卡片"待验证"字段
- **真 A/B**：两个备选标题分发到**不同渠道或时段**才叫对比（工坊 SOP 已有此定义）

> ⛔ **不要凭感觉说"这个技法有效"**。工坊 SOP 明确写着"规则要能被数据推翻"，
> 本工坊的技法库同理——**它是候选知识，不是教条**。

## 三、库的健康度检查

| 检查项 | 健康标准 |
|---|---|
| 可追溯性 | 每张卡都能顺着"来源报告 → 原文链接 → 原句"链走到头 |
| 无重复 | 同一技法不重复立卡（相似的在卡内注明"变体"） |
| `❌` 卡齐全 | 遇到过的不可用套路都立了卡，不遗漏 |
| 总览表同步 | `00_技法总览.md` 的进度数与实际文件数一致 |
| 无编造 | 全部证据等级如实标注，无"10万+"类未核实表述 |

**定期跑一次文件数核对**：
```bash
find "_资产/技法库" -name "*.md" -not -name "_*" -not -name "00_*" -not -name "README*" | wc -l
```
与总览表登记的卡数比对。

## 四、技法库的"退休"机制

**技法库不做删除清理**（它是知识资产）。但允许**标记失效**：

| 情况 | 处理 |
|---|---|
| 技法被数据证伪 | 卡内追加"⚠️ 2026-XX 实践证伪：……"，状态改为"已证伪"，**保留卡片** |
| 平台规则变化导致技法失效 | 同上，写明"因平台 XX 变化失效" |
| 与账号定位调整冲突 | 重新判定可迁移度，可能从 `✅` 降为 `⚠️` 或 `❌` |

**为什么不删**：被证伪的技法同样是知识——它防止以后重新捡起来当新发现。

## 六、可选的自动化（需用户明确要求才建）

若用户希望**定期自动拆解**，可创建 recurring automation：
- 内容：自动搜捕候选 → 输出候选清单 → **停在 Gate A**
- **不可**自动化到"自动拆解 + 自动改 SOP"——那会绕过全部 Gate，违反 P0 红线
- 频率建议：每周 1 次（搜索+筛选足够）
