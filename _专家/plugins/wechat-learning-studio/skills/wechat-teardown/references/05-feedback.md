# 第 5–6 步 · 反哺清单与执行同步

> 目标：把技法库里成熟的发现，**经用户逐条确认**，写进工坊（`wechat-article-studio`）的 SOP。
> **这是本工坊唯一被允许修改工坊文件的通道，且必须先过 Gate C。**

---

## 一、⛔ 反哺铁律

1. **先入库、后确认、再落地**。用户没点头，工坊一个字节都不动。
2. **逐条确认，不打包放行**。用户说"可以"通常只代表同意其中几条，需明确哪几条。
3. **改完必须三处同步**（见第四节），否则改动**不生效**。
4. **改完必须留痕**，写入 `_资产/SOP变更日志.md`。

---

## 二、Gate C · 候选反哺清单格式

**累积到 5–8 张新卡、或出现冲突类发现、或用户要求时**，输出这张表并停手：

| # | 候选技法 | 拟写入 SOP 位置 | 与现有规则的关系 | 建议 | 证据 |
|---|---|---|---|---|---|
| 1 | 用具体时间点开头代替抽象感慨 | `references/02-writing.md` 第2步 | 新增 | 采纳 | 3篇文章重复出现 |
| 2 | | `references/01-planning.md` 第0步 | **冲突**：SOP 要求 XXX，这篇做法相反 | 建议讨论 | 1篇，证据弱 |
| 3 | | | 强化（SOP 已有，本篇印证） | 只需记录 | |

**"建议"栏的四个取值**：
- **采纳**：证据足、与账号调性一致、可直接写入
- **观察**：有潜力但证据不足，先留存，累积到更多样本再议
- **讨论**：存在冲突或判断困难，需要用户拿主意
- **驳回**：不建议写入（如与账号调性不符）

**清单后必须附三个问题**：
1. **哪几条采纳？**（请用户逐条点名）
2. **冲突项怎么处理？**（改规则 / 保留原规则 / 折中）
3. **驳回的要不要记录？**（记入"已确认不采用"区，避免以后重复提出）

> **不要因为"这条明显很好"就自行采纳。** 好的判断也是判断，要用户签字。

---

## 三、执行反哺（仅用户确认后）

### 第 1 步：定位写入位置

工坊 SOP 的结构（已迁为「常驻骨架 + 按需细则」）：

| 文件 | 内容 | 适合写入的技法类型 |
|---|---|---|
| `agents/wechat-article-studio.md` | 流程骨架、P0 红线、Gate 关卡、人设 | **仅**核心原则/红线类 |
| `skills/wechat-sop/SKILL.md` | 入口 + 何时加载表 | 一般不动 |
| `skills/wechat-sop/references/01-planning.md` | 第 0–1 步（规划/选题） | 选题类技法 |
| `skills/wechat-sop/references/02-writing.md` | 第 2 步（写正文） | 结构、句式、叙事类技法 |
| `skills/wechat-sop/references/04-html.md` | 第 4 步 + 输出规范 | 排版类 |
| `skills/wechat-sop/references/05-publish-kit.md` | 第 3、5、6、7 步 | 发布包类 |
| `skills/wechat-sop/references/vision.md` | 视觉识别 | 配色/封面类 |

**默认落位原则**：**写作技法 → `02-writing.md`**（细则密度最高、最贴内容）。
**只有**当技法属于"账号不可动摇的核心原则"时，才考虑写进 agent 骨架。

### 第 2 步：写进 SOP 的措辞纪律

- **只写"当前该怎么做"**，不写考古（旧值/被推翻的旧做法 → 记入变更日志）
- **与既有规则风格一致**：同层级用同样的标记（`⛔`/`✔`/`·`）
- **不制造重复**：若已有类似规则，**改为强化原规则**而非另起一条
- **标明来源**：可写"（来自外部样本研究，2026-XX-XX）"便于以后回溯

### 第 3 步：⛔ 三处同步（漏一处改动就不生效）

**这是 2026-09-11 踩过的坑**：只改了派生版与 zip，没同步 cache → **改动完全未生效**。

**唯一真相源是 `plugins/cache/.../1.0.0/`（WorkBuddy 实际加载处）**。

固定顺序：
```
1. 改 cache（唯一真相源）
   C:\Users\ZhuanZ\.workbuddy\plugins\cache\my-experts\wechat-article-studio\1.0.0\
        ↓
2. 同步 marketplace
   C:\Users\ZhuanZ\.workbuddy\plugins\marketplaces\my-experts\plugins\wechat-article-studio\
        ↓
3. 重打包 zip（_专家/wechat-article-studio.zip）
        ↓
4. 三处归一化比对（含换行符 / BOM）
```

**比对注意**：`glob` 不匹配点目录，需用 `os.walk`，否则会漏 `.codebuddy-plugin/` 误报不一致。

**校验**：跑 `expert-manager/scripts/validate_expert.py`，须通过。

### 第 4 步：留痕

写入 `_资产/SOP变更日志.md`：
- 写入日期、来源技法卡、写入位置、措辞变化（旧 → 新）、原因

### 第 5 步：更新技法库状态

- `00_技法总览.md` 的"反哺记录"区登记（技法名 / 写入位置 / 确认日期）
- 该技法卡内"与既有规则的关系"更新为"已验证写入 SOP"

---

## 四、反哺后的验证（可选，但推荐）

反哺效果**不靠感觉判断**：

1. **短期**：跑 `工具脚本/模板感诊断_template_scan.py --dir "公众号/<系列>/公众号文章"`，
   看新写的文章在相关指标上是否有变化
2. **长期**：与 `_资产/发布数据复盘.md` 交叉——新规则启用后发布的文章，
   数据表现是否优于之前（**需 20–30 篇样本**，不要凭一两篇下结论）

> **工坊 SOP 自己的立场**："规则要能被数据推翻，20–30 篇后再定稿。"
> 所以反哺进来的新规则，**是"候选规则"，不是"定论"**。数据不支持时，同样要改回去。

---

## 五、⛔ 禁止清单

- ❌ 未经 Gate C 确认就改工坊任何文件
- ❌ 把"用户说可以"理解为"整张清单都通过"（需逐条点名）
- ❌ 只改 cache 或只改 marketplace（必须三处同步）
- ❌ 不改变更日志就默默改规则（留痕是纪律）
- ❌ 在 SOP 正文里写考古信息（旧值、被推翻的做法 → 一律记变更日志）
