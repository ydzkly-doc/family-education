# 第 4 步 · 技法库同步与维护

> 目标：让技法库始终**可查、可追溯、不重复**。每拆完一篇就要同步一次。

---

## 一、库的物理结构（固定，不得随意改）

```
_资产/技法库/
├── README.md                  ← 索引 + 使用规则（少改）
├── 00_技法总览.md              ← 一页速查表（每拆完一篇更新）
├── _模板_技法卡.md             ← 立卡模板
├── 01_选题与角度/
├── 02_标题与开头钩子/
├── 03_结构与节奏/
├── 04_情绪曲线与共鸣点/
├── 05_金句与结论收尾/
└── _拆解报告/
    ├── _模板_拆解报告.md
    └── YYYY-MM-DD_<短标题>.md
```

**落位理由**：技法库属**长期资产**，放在 `_资产/`（与真实素材池、发布数据复盘并列）。
这是用户既有的目录规范——`_` 前缀 = 管理类，与内容系列目录区分。

---

## 二、每拆完一篇的同步清单（四项，缺一不可）

| # | 动作 | 文件 |
|---|---|---|
| 1 | 写拆解报告 | `_拆解报告/YYYY-MM-DD_<短标题>.md` |
| 2 | 立技法卡（如有） | `<维度目录>/<技法名>.md` |
| 3 | 更新总览表 | `00_技法总览.md`（进度 + 对应维度表格） |
| 4 | 检查反哺候选 | 若累计新卡达 5–8 张 → 准备 Gate C |

### 总览表要更新的三个地方

1. **进度区**：已拆解篇数、已立卡张数、待确认反哺候选数、最近更新日期
2. **对应维度表格**：新增行（技法名 / 可迁移度 / 来源 / 状态）
3. **已确认不采用（❌）区**：若本次立了 `❌` 卡，同时在此登记

---

## 三、命名与可追溯规范

| 对象 | 命名规则 | 理由 |
|---|---|---|
| 拆解报告 | `YYYY-MM-DD_<短标题>.md` | 日期前缀便于时间排序、看学习进度 |
| 技法卡 | `<技法名>.md` | 用名字不用编号，增删不乱 |
| 短标题 | 取原文标题关键词，≤12 字 | 便于在文件列表里辨认 |

**可追溯链条必须完整**：
```
技法卡 → 来源报告（卡内"来源报告"字段）→ 原文链接（报告第0节）→ 原句（报告内照抄）
```
任何一环断了，这张卡以后就没人敢用。

---

## 四、反哺候选的积累监控

在 `00_技法总览.md` 的"待确认反哺候选"区维护。**触发 Gate C 的条件**：
- 新卡累计 **5–8 张**，或
- 出现**冲突类**发现（原文写法与工坊 SOP 相悖），或
- 用户主动要求

**未达触发条件时，不要主动催用户拍板**——技法库本身就有价值，不急于改 SOP。

---

## 五、只读与边界

- 技法库的**所有文件都是本工坊可写的**（这是自己的资产）
- **工坊（`wechat-article-studio`）的所有文件是只读的**，除非用户在 Gate C 逐条确认（见 `05-feedback.md`）
- **用户个人目录、原始材料**：只读，不改不删
- 技法库**不设保留期、不做清理**——它是知识资产，区别于过程文件（`_预览/`、`_备份/` 那类才按保留期清理）

---

## 六、与既有资产的交叉引用

| 资产 | 关系 |
|---|---|
| `_资产/发布数据复盘.md` | 本账号发布后的数据 → 验证技法卡是否真的有效（见 `06-maintenance.md`） |
| `_资产/真实素材池.md` | 技法卡给出的"本账号例句"若用到了真实素材，注明来源，避免重复消耗同一细节 |
| `_资产/SOP变更日志.md` | 反哺执行后，在此留痕（旧值、实证、被推翻的做法） |
| `工具脚本/模板感诊断_template_scan.py` | 反哺后若改了句式规则，可用它验证本账号文章是否真的有变化 |
