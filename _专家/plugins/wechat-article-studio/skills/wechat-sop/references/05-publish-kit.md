# 卡片·手册·发布包（第 3/5/6/7 步）

**第 3 步 · 做干货卡片（HTML）**
- 把可收藏内容（清单、节奏表、对照表、路径图）做成 700px 宽 HTML 卡片，扁平、纯色块、无渐变阴影，每张底部带署名行。
- **卡片是朋友圈社交货币**：底部除署名外，放一句**不带动作指令、但本身就适合被转发的"转发主语句"**（呼应第 2 步传播⑥，如"不是孩子不努力，是我们都太急了"），让卡片脱离文章也能独立传播。

**第 5 步 · Word 版本（默认不做，仅按需）**
- **默认不生成 Word/.docx 版本**；标准交付只含：发布包（正文.html+字段txt+指南md+封面）、卡片 HTML、选题规划、发布手册、转发文案。
- **仅当用户当次明确要求 Word/docx/打印存档时才产出**；用户说"不要 Word"则跳过，不必再问。
- 若需要：用 python-docx（隔离 venv，勿全局 pip）转 .docx，微软雅黑、标题层级、金句加粗、列表、来源声明。

**第 6 步 · 配套手册**
- **【2026-09-10 起，这里是发布操作说明的唯一归口】** 因发布包内 `02_发布操作指南` 已取消，**操作步骤、后台字段说明、发布前自查清单统一写进根目录 `03_发布手册.md`**（每系列一份、全篇通用），不再逐篇重复。内容须含：
  - **单篇后台操作 4 步**：①打开该篇发布包 `正文_第X篇_*.html` → 浏览器 `Ctrl+A` 全选 `Ctrl+C`；②mp 后台 → 草稿箱 → 新建图文 → 正文区粘贴；③照 `01_标题作者摘要.txt` 填标题/作者/摘要/话题标签；④上传 `封面_第X篇_*.jpg` → 手机预览 → 存草稿/发布。
  - **发布顺序与节奏**（含踩情绪时间点、建议发布时机、篇间间隔）。
  - **发布前自查清单**（全套通用一份即可）：标题三处一致、来源声明在位、**读书笔记/课程改写类不声明原创**、手机端卡片无横向溢出、无动作指令、无绝对化表述、封面 2.35:1 且≤200KB。
- **朋友圈 / 家长群转发文案（每篇一段、一屏内）→ 归口各篇 `01_标题作者摘要.txt`**（原在逐篇指南里，指南取消后丢失，现恢复到 `01`）。规格见下方 § 朋友圈转发文案段。

**第 7 步 · 组装「发布包」（每篇一个文件夹，正文就在包内）**

> ⛔ **Gate 2（样板确认）**：规划经 Gate 1 确认后，**先只做 1–2 篇完整发布包**（正文.html + 01 字段表；封面此时不生、02 操作指南已取消），停手请用户确认样板。**未确认前，禁止批量生产其余发布包。**
> ⛔ **Gate 3（封面确认）**：到做封面时，**先只生 1 组（1 篇 / 1–2 张候选）封面**，完整后处理并展示，**未确认风格前禁止批量生封面**（生图耗积分）。

> 背景：微信官方 `draft/add` 等草稿/发布接口**仅企业主体且已微信认证的公众号可用**；个人订阅号、未认证号在微信开发者平台根本看不到 AppSecret 栏，无 API 权限（实测返回 48001 或无凭证）。浏览器自动化/RPA 复用 cookie 虽个人号可用，但**违反微信服务协议、有封号风险，不做**。因此对无 API 权限的账号，统一交付**零风险半自动发布包**：用户登录 mp 后台手动新建图文，复制粘贴即可。
>
> **铁律：一篇正文只一份，直接生成在发布包里。** 不再有独立 `排版HTML/` 目录、也不复制正文——第 4 步把正文 HTML 直接写到 `发布包_第X篇/正文.html`，字段表/指南/封面都与它同目录。省 token、改一处即生效、绝无两份不一致。标题/摘要/作者取自第 1 步规划表。

> **样板生命周期**：Gate 2 只做最少 1–2 篇样板。标准版直接把样板写入未来正式发布包；若某个执行环境另建 `样板_*` 评审目录，该目录只用于临时评审。正式包完成后须先做 SHA256 比对、搜索调用方，把预览脚本切到 `发布包_*/长图文发布包/正文_*.html`，重建并核对篇数，再按回收站规则清理样板；清后重新搜索残留引用并跑全系列自检。正式发布包是唯一内容真源。

- 在成果文件夹（如 `公众号文章/`）下，为每篇建一个 `发布包_第X篇_短标题/` 文件夹。

  **⭐ 两层结构（2026-09-15 起，配合卡片文章）**：

  ```
  发布包_第X篇_短标题/
  ├── 长图文发布包/     ← 长文三件套
  └── 卡片发布包/       ← 卡片交付物（做卡片文章时才有）
  ```

  **⚠️ 存量兼容**：旧系列的发布包**没有子目录**（三件套直接在包根），**同样合法**。
  目录迁移采用「**逐篇随做**」策略——**做某篇卡片文章时，顺手把该篇迁为新结构**；
  未迁移的旧结构照常可用（工具链已兼容双结构）。详见 `13-card-article.md` 第 3.1 节。

  **长图文发布包/ 内含**：
  1. **`正文.html`**：第 4 步直接生成于此。浏览器打开→Ctrl+A 全选→Ctrl+C→粘进公众号正文区。**正文零 `<img>`**（卡片全是 `<section>`+内联样式绘制，**禁用 `<table>` 布局**），粘贴即图文完整、无需传正文图。
     - **⛔ 正文顶部不得生成"上一站／下一站"等前后篇视觉导航（2026-09-21 用户明确）**：粘贴到公众号后**它们不能点击**（纯文本，无 `a`/`href`/`onclick`），**且与公众号合集的自动导航重复**，只会白占首屏。
       系列连续性由**统一眉题 + 内容承接 + 公众号合集**承担：
       · **眉题**（`第 N 篇 · 共 M 篇 ｜ 第X季 · 板块名`）＝**唯一**系列坐标提示，保留；
       · **跨篇跳转**＝公众号**合集（专辑）**，平台原生、可点击，**不在正文里再画一遍**；
       · **整体地图**＝只在总纲/末篇出现；
       · 想交代"下一篇讲什么"，**结尾用一句自然陈述句**即可，**⛔ 不得伪装成按钮/链接/可点击控件**，写不出就省略。
  2. **`01_标题作者摘要.txt`**：逐项列清后台字段——标题（**≤64字，且钩子压在前20字；必须与 `正文.html` 顶部大标题逐字一致**，见第1步"标题长度与钩子位置"）、作者（公众号署名）、摘要/digest（≤120字，不填抓正文前54字）、原文链接（留空）、备选标题、话题标签/合集名、封面文件名与规格；开头注明"正文即本文件夹 `正文.html`"。
     + ⭐ **第 7 项：朋友圈 / 家长群转发文案**。规格见下方「§ 朋友圈转发文案段」。
  3. **`02_发布操作指南` —— 不再生成（用户明确）**：`.txt` 与 `.md` 都不产出。发布流程已固化（复制正文 → 填字段 → 传封面 → 发布），逐篇附指南是冗余。
     - **发布包标准 = 三件套**：`正文_第X篇_*.html` + `01_标题作者摘要.txt` + `封面_第X篇_*.jpg`。
     - 原本写在指南里的内容**去向**：①**操作步骤与后台字段说明** → 归口到成果根目录的 **`03_发布手册.md`**（每系列一份，全篇通用，不再逐篇重复）；②**本篇朋友圈/群转发文案** → ⭐ **归口到各篇 `01_标题作者摘要.txt`**（第 7 项）；③**发布前自查清单** → 同样只在发布手册里保留一份。
     - **历史兼容（存量保留、增量停生）**：**凡已存在的 `02_*`（不论哪个系列、.txt 或 .md）一律保留、不清理、不删**；只是**后续新写的篇目不再生成**。新系列的包本就不含它，不要反过来去"补齐"。（见第 10 步"区分历史约定与过程文件"）
  4. **封面图（严格 2.35:1、无文字无 AI 水印、单张 ≤200KB）**：公众号封面**必填**（正文全用 section 画、无位图，封面是唯一需要图的地方）。**比例必须 2.35:1**（推荐 **1200×511**；**不要 3:2**）；核心意象放画面**中央方形安全区**，两侧只放暖色背景/留白；暖色与正文主题色统一；**画面风格 = 写实摄影风**（2026-09-11 用户确认，见 `vision.md`；**不要扁平插画/矢量风**）。ImageGen 出 2–3 张候选（命名 `封面候选1_意象.jpg`），出图后**固定后处理流水线**：去 AI 水印/内容标识角标（优先按 2.35:1 横裁一并切掉边缘水印；水印若在画面内则取邻近背景色覆盖/修补）→ 逐张目检确认无文字、无水印 → 压到每张 **200KB 以内** → 再放入发布包。**生成前先告知用户会消耗图片生成积分**。意象呼应本篇主题。

     **封面生图与后处理——防返工硬规则（2026-09 踩坑后补充，务必照做）**：
     - **A0. 首选「无人物静物构图」（实测最优，强烈推荐）**：系列封面**优先只画物件、不画人**——如"关着的门+挂在把手上的手机+门口拖鞋""深夜台灯下的练习册""三把椅子围成对话""冰箱上的约定纸+笔""日落球场的球+两个水瓶"。优点：①彻底规避 AI 画错人物年龄/性别/人数（实测首次生成就把中年爸爸画成**秃顶+络腮胡**）；②物件+暖光+中央安全区构图天然稳定高级；③整系列视觉统一、辨识度高。**每篇用"一个能代表本篇的物件组合"承载主题**，比画人更保险。只有用户明确要人物时才走下面的 A 条。
     - **A. 人物年龄/性别强约束（仅当画面必须有人的时候）**：默认人设是"中年爸爸 + 15岁儿子"，但 AI 常把中年爸爸画成**秃顶/白发爷爷**、把青少年画成**小学生/幼童**、甚至多出第三个人。提示词必须显式写死：父亲 `middle-aged / early 40s, thick full head of dark black hair, short stubble, NOT balding / no receding hairline / no grey hair, NOT elderly / NOT a grandfather, clearly an adult parent`；儿子 `teenage boy about 15, tall slim adolescent, nearly as tall as the father, long pants, NOT a small child / NOT an elementary-school kid`；并写 `only two (or N) people, no third person`、`whole head visible with margin above, head-to-knees framing`。出图后**逐张目检：人物年龄对不对、人数对不对、有没有画成老人/小孩**，不合格直接重生（别指望后期修）。
     - **A2. 主体不能太小（实测踩坑）**：AI 有时把场景画成"中间一条细带、四周大片空白"（如远景球场），裁成 2.35:1 后主体过小、画面空。提示词要写 `CLOSE-UP view, main objects occupy roughly 65–70 percent of the frame width, NOT tiny, NOT a thin distant band`；出图后目检主体占比，太小则重生。
     - **B. 为 2.35:1 裁切预留构图（防切头/切道具）**：横版封面要裁掉上下，人物若填满画面，裁切必切头或切掉关键道具。提示词里要写：`wide horizontal banner, place figures in the VERTICAL MIDDLE, leave ≥15–25% EMPTY space both ABOVE the heads and BELOW the hands/table, keep figures small-to-medium, NOT filling the frame, generous empty background on far left and far right`。**生成时就让人物小、上下留白足，比"画满再硬裁"稳得多**；人物占比太大的图宁可重生。
     - **⭐ B2. 必须生成"横图"、绝不生成"竖图再裁"（2026-09-11 实测，直接决定清晰度）**：**生成尺寸一律选横版（如 `1536x1024`）；禁止用竖版（如 `1024x1536`）裁出 2.35:1**。竖图裁横带会浪费掉约 60% 像素、剩下的部分再被放大，**两步都在丢细节**。实测对照（同一张源图）：竖图裁带后放大到 1400 → 细节保留率 **86.1%**；横图裁带后缩小到 1200 → **97.6%**，色阶密度也更高。
     - **B2b. 生图工具水印：无法关闭，但 2.35:1 裁切会自动切掉（2026-09-11 实测结论）**：当前生图工具**不提供"不加水印"参数**（`footnote` 是另加水印、不能置空），水印固定打在**右下角**（内容为"AI 生成 / WORKBUDD>"双行白字）。**好消息是：1536×1024（3:2）裁 2.35:1 需居中取高 653、每边切掉约 185px，底部水印天然落在裁切线之外**——实测成品右下角放大 3 倍**完全干净、无残留**。**所以"生成→裁剪"这条流程本身就是去水印，不必额外处理**；只需按 D 条目检确认即可。**不要为了去水印而在画面内做修补**（会留痕迹且没必要）。若某张构图必须保留底部内容、水印可能进框，则优先按 B 重生一张留白足的图。
     - **⭐ B3. 后处理只"缩"不"放"（硬规则）**：裁完 2.35:1 后的宽度**必须 ≥ 目标宽度**，只允许向下缩放，**严禁向上放大**。实测放大 1.37 倍会使锐度损失约 45%。**推荐终稿 1200×511**（该尺寸已满足头条封面要求；不要为"看起来更大"而放大到 1400/1536）。**自查方法**：处理后若 `成品宽度 > 裁切后带宽`，说明发生了放大 → 回退重来。
     - **B4. 判断成片细腻度，别只看"锐度"**：扁平插画的大色块+硬边缘会让拉普拉斯类锐度指标虚高，**说明不了清晰**。要看**独立色阶数**与**高频细节能量占比**——真实照片在这两项上显著更高。
     - **C. 后处理裁切线纪律**：以 1536×1024 出图、裁成 1536×654（高 654）为例——右下角"AI 生成/平台水印"约在原图 **y>945、x>1380**，故**底部裁切线必须落在原图 y≤945** 才能把水印全切到框外；人物头在画面上部时裁切起点 y0 要足够小以保住头顶（父亲发尖常出现在原图 y≈40–100）。**"保头"与"去水印"冲突时（头太靠上、底切又会切道具），优先按 B 重生一张留白足的图，不要硬裁。**
     - **⭐ B5. 生图当下就把提示词写进该系列发布手册（2026-09-11 新增，治本）**：候选图会按过程文件规则（C 类 14 天）被清理，**等到清理时再补提示词，原 prompt 多半已丢失、只能反推**。因此**生成封面时**即在系列发布手册追加「**封面意象与提示词存档**」小节，字段：候选序号 / 意象名 / 画面要素 / 视觉作用 / 最终采用哪张，并附统一风格后缀与统一约束（`no text, no words, no letters` + 横构图供 2.35:1 裁切）。这样候选图可放心清理，资产不丢。
     - **D. 目检必过项**：每张裁完放大**右下角**（如裁 300×120 再放大 2 倍）确认无水印白字残留；确认**每个人物头/脚完整无裁切**、核心道具（水杯/本子/门）在画面内；无任何文字。
     - **E. 后处理用隔离 venv 的 Pillow**（系统 python 无 PIL）：`C:\Users\<用户>\.workbuddy\binaries\python\envs\default\Scripts\python.exe`。原始带水印 png 用完即删/归档，发布包只放裁切后的 `封面_第X篇.jpg`。

     **封面"无文字"规则与 B 方案（默认 A，用户要字才走 B）**：
     - **默认方案 A · 纯无字（推荐）**：封面图**不带任何文字、也不让 AI 写字**。理由：①AI 写中文几乎必出错字/乱码/糊字；②信息流与转发会从中心裁方形，图上文字易被切；③文字叠水印难修。标题靠**公众号后台独立的标题文字层**（订阅号列表/转发卡片自动渲染【标题】字段），不依赖图内有字。
     - **方案 B · 无字底图 + 脚本后期叠中文（用户明确要"金句压图/图上有标题"时才做）**：AI 仍只出**干净无字底图**，然后**用脚本（Pillow + 确定的中文字体）把标题/金句精确叠上去**——字体、字号、位置、留白完全可控、零错字，并主动避开中央方形裁切区。**严禁让 AI 直接在图里写中文字。**

  4. 发布包内**不含**成稿 md、不含正文副本、**不含发布操作指南**（操作步骤归口根目录发布手册，朋友圈文案归口 `01` 字段表第 7 项）。
- 发布包是**可选/按需**环节：用户明确要"能直接发/发布包/发草稿/最后一公里"时做；批量时可先做 1 篇样板确认再套用。
- 若未来升级为**企业主体+已认证公众号**，可走官方 API 全自动；届时字段 txt 即 articles JSON 数据来源，正文 section 卡片可转为微信图床可用的位图。

## § 朋友圈转发文案段 · 规格（`01_标题作者摘要.txt` 第 7 项）

一段，**一屏内**，**第一人称**——写"我为什么转它"，不是"这篇文章讲了什么"。

- **首行独立成行、短、能自己站住**（朋友圈折叠后只露首行）；
- ⛔ 不写成文章摘要（后台字段里已有一份）、不写成全文精华、不用"干货/必看/码住"广告腔；
- ⛔ 不写动作指令（"转给需要的家长""点赞关注"）——沿用全账号红线，不因场景放宽。
  可用"我把完整过程写在文章里了"这类**内容指向**，结尾留一行"（粘贴公众号文章链接）"。

**示例**（青春期的这一篇，老指南原样）：

```
儿子把手机递过来："爸，我想要这双鞋。"价格够我买两双普通鞋。
我差点吼出"学生比什么穿"，话到嘴边忍住了。
后来才懂：青春期突然爱美、追名牌，不是学坏，是他在急着确认"我是谁、值不值得被喜欢"。
第三条路：外表干净得体就好，把夸奖留给他的努力、善良和担当——
你肯定什么，孩子就往哪里长。
```
