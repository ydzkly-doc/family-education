# 沉淀与自检（第 8–9 步）

**第 8 步 · 沉淀与命名**
- 所有产物放到**与原材料同目录**下的成果文件夹（如 `公众号文章/`），结构：`发布包_第X篇_短标题/`（**两层**：`长图文发布包/` + `卡片发布包/`；**旧系列无子目录、三件套直接在包根，同样合法**）。**长图文发布包内含三件套**：`正文_第X篇_*.html` + `01_标题作者摘要.txt` + `封面_第X篇_*.jpg`；**不再含 02 操作指南**。**卡片发布包（做卡片文章时才有）**：`01_标题作者摘要.txt` + `02_卡片正文（纯文本）.txt` + `第XX篇_卡片_NN_*.jpg`（**卡图文件名必须带篇号前缀**，防上传公众号图库时跨篇覆盖）。**目录迁移策略＝逐篇随做**（做某篇卡片时顺手迁移该篇），详见 `13-card-article.md` 第 3.1 节；另可保留 `卡片/`（独立 700px 卡片，供单独存图）；手册 md（选题规划 / 发布手册 / 转发文案）放根目录。**不设 `排版HTML/` 目录**（正文已在发布包）；**默认不建 `成稿md/`**；**仅当产出 Word 时才建 `Word版本/`**。
- **⭐【项目产物落位规则 · 硬性，2026-09-10 用户明确；2026-09-29 目录重整】工作空间根目录只允许四类东西，其余一律归位**：
  - **✅ 允许留在根目录**：①**内容总目录 `公众号/`**（**所有文章/讲书系列都住在它下面**，如 `公众号/青春期30讲/`、`公众号/王金海讲书/<书名>/`）②**学习系统 `学习计划/`**（学习规划师的状态目录）③系统项（`.git/`、`.gitignore`、`.workbuddy/`）④固定的管理目录（`工具脚本/`、`_专家/`、`_资产/`、`_备份/`、`_档案/`）。

    | 产物类型 | 落位 |

    | 一次性报告 / 方案 / 验收记录（含 `00_*.md`、`overview.md`） | `_档案/报告/` |

- **【强制】生成「全部正文预览」单文件**：只要系列 ≥2 篇，在成果文件夹根目录**必须**额外产出一个自包含的合并预览页 `<系列名>_全部正文预览_<N>篇.html`（如 `青春期30讲_全部正文预览_18篇.html`），用脚本把各发布包正文 HTML 的 `<body>` 内容按**篇号 1→N 连续顺序**抽出来合并进同一页：顶部一排按篇号排序的导航胶囊按钮（数字+短主题）、当前篇高亮、底部「◀上一篇 / 下一篇▶」翻页按钮 + 键盘 ←/→ 切换、中间显示「第 X 篇 / 共 N 篇 · 主题」；每篇正文包在 `<section class="art" id="artN">` 里，默认只显示当前篇（`.show`）。该文件仅用于预览/校对，**不进发布包、不发布**；脚本（如 `_build_preview.py`）可留在成果文件夹供增删篇后重跑。
  - **⛔ 但"生成它"绝不含"自动打开它"**：**该文件默认只在磁盘上待命，不交付、不预览**。是否 present 由用户当次明确指令决定（详见下条与 `04-html.md` 同题条）。
  - **⚠️ 生成后要自查体积**：合并页把 N 篇的内联样式全塞进一页，**体积随篇数线性增长**。实测 `孩子总犯错误怎么办_全部正文预览_6篇.html` = **1563KB**、`青春期30讲_18篇` = 385KB。**若用户要求打开预览，先告知体积**（>500KB 时建议只看单篇而非合并页），别让用户等一次漫长渲染。
- **交付与否听用户指令（2026-09-10 用户明确；2026-09-19 第三次重申并升格为"默认关闭"）**：需要交付时用 present_files 一次给齐（各发布包的正文/字段/封面 + **全部正文预览.html** + 手册 md + 卡片），**系列多篇时预览合并页排在 files 数组首位**。**但默认是"不交付、不打开预览"**——用户反馈"每次都执行 present_files 很耗时"（2026-09-19 再次反馈："你每次到这一步时都非常耗时……后面能否不要在自动打开文件预览了，需要查看的我会显示告诉你"）。**是否需要交付、是否打开预览，一律以用户当次明确的"打开/看一下/给我看看"为准。**（注意：这是"少交付"，**不等于"少确认"**——Gate 1/2/3 的确认一次都不能省。）
  - **⭐ 默认动作 = 文字报告路径**：做完后**在回复里写清产物路径**即视为交付完成，**不要调用 present_files**。**".txt/.md/.jpg 可放心列" ≠ ".html 要顺手列"**——默认对任何文件都不调。
  - **⛔ 加重理由（2026-09-19 实测）**：present_files 打开 `.html` 会让**预览面板完整渲染整页 DOM**；合并预览页最大 **1.5MB**，是"每次到这一步都慢"的直接原因。**用户已连续两次反馈，第三次重申——不得再用"顺手方便"为理由破例。**
- **⚠️【最高优先级·预览污染隔离，2026-09-06 实证根治】present_files 的内置 HTML 预览面板会把渲染后的 DOM 写回磁盘源文件**：它渲染 `.html` 时会给每个节点（连 head/meta/title/body）注入 `data-page-node-id="随机22位"`（数百个），并**就地改写磁盘上被它渲染的那个 .html**（实测：干净正文 16912 字节→打开 6 秒后变 22072 字节、mtime 更新、布满 data-id）。`.txt`/`.jpg` 不进富文本渲染、不会被写回污染。`data-*` 是微信丢样式的 A 类根因（微信据 `data-*` 把节点当外部组件整段重置）。**这与用户无关、不是秀米/编辑器往返**——就是 present_files 预览本身写回所致；历史各系列的"data-id 污染"同源。
  - **铁律①：正式源正文绝不直接 present_files**。各发布包的 `正文_第X篇.html` 只能在文件里、由脚本/校验工具读写；**present_files 打开的合并预览页必须是独立的派生副本**：`_build_preview.py` 读取源正文时**先正则剥 `data-*`（双保险）**，把合并页输出到**独立 `_预览/` 子目录**（纯派生、不发布、随时 `python _build_preview.py` 重建覆盖）。预览面板污染的只是这份副本，下次重建即复原；源文件物理上不被写回。
  - **铁律②：交付/发布前必须 `--fix` 清洗保险**。`_build_preview.py` 支持 `--fix`：就地剥掉所有发布包源正文里的任何 `data-*`。每次生成/修改正文后、以及**任何一次 present_files 之后**，跑一遍并 grep 确认 `data-page-node-id` 计数全 0 再交付（脚本已在断舍离系列落地，可作模板复用：`data-*` 正则 `\s*data-[a-zA-Z0-9_-]+="[^"]*"`）。
  - **铁律③：`.txt`/`.md`/`.jpg` 可放心 present_files**（不渲染富文本、不被写回）；只有 `.html` 有写回污染，且只需预览那份 `_预览/` 副本，绝不在 present_files 的 files 里直接列各发布包 `正文_*.html`。
- **【发布包卫生：包内只允许三件套】** 发布包是"打开即用"的成品夹，**只放**：`正文_第X篇_*.html` + `01_标题作者摘要.txt` + `封面_第X篇_*.jpg`（**02 操作指南不再生成**），或**新结构下的两个子目录** `长图文发布包/` 与 `卡片发布包/`。**任何过程脚本（`_cover_proc.py` 等）、未采用的封面候选图（`封面候选*.jpg`）、`_原始png/`、`_chk_*.png` 目检图都不许留在包里**——生图脚本与候选图统一移到该系列 `公众号文章/_过程文件/`（**挪、不删**：候选图留有可复用的提示词与后处理参数），原始带水印 png 移到 `_原始图归档_日期/`。
  - 交付前用脚本自查：遍历 `发布包_*/`，凡文件名不匹配**白名单正则** `^(正文_.*\.html|01_.*\.txt|封面_第\d+篇_.*\.jpg|长图文发布包|卡片发布包)$` 的即列出。**⚠️ 新结构的两个子目录名必须列入白名单**——否则会被误判为"多余待清理"甚至误删（2026-09-15 修正）。**注意例外**：`02_发布操作指南.*`（含新系列已产出的那批）属**存量保留项、不是过程文件**，不得清理——清理时须把 `02_*` 排除在白名单外单独放行。
- **【版本库治理：过程目录不进 git，2026-09-10 落地】** 工作空间 `.gitignore` 必须忽略过程目录：`_backup*/`、`_归档*/`、`_过程文件/`、`_预览/`、`_原始png/`、`_封面候选/`。
  - **⚠️ 关键坑：`.gitignore` 对"已被跟踪"的文件无效**。补完规则后必须再执行 `git rm -r --cached <路径>`（**只移除索引、本地文件全部保留**）才能真正生效。实证：某工作空间加了规则但仍有 **157 个过程文件**被跟踪（多为已删除目录在索引里的残留记录），须一次清干净。
  - `git rm` 路径过多会报 `WinError 206 文件名或扩展名太长` → 改用 `git rm -r --cached --pathspec-from-file=<清单文件>`。
  - 自检：`git ls-files | grep -E '_backup|_预览|_原始png|_封面候选|_归档|_过程文件'` 计数应为 0；`git check-ignore -v <示例路径>` 应命中规则。

     - **⭐ D 规则：块内不得「裸文本 + 内联元素」混排（2026-09-21 修正，取代旧「`<b>` 必须带 `font-size`」）**：
       - **⛔ 旧规则已证伪**（曾据此白改 41 篇）：给 `<b>` 补 `font-size`、写 `inherit`、调大行高、甚至**删掉行高**，官方**全都照样报**。**根因与 `font-size`/`line-height` 取值无关。**
       - **真根因**：凡 `<p>`/`<section>` 内**既有裸文本、又有内联元素**（`<b>/<strong>/<span>` 等），粘贴到公众号会报「**行高小于字体大小，且存在多行文本，可能导致文字重叠**」（#2.3.2）。官方用真实浏览器测行框数（`lineCount = range.getClientRects().length`），内联元素边界被算成**额外 rect** → 行数虚增 → `contentHeight/lineCount` 被除小 → **误判叠字**。
       - → **修法**：把块内**直接子级的裸文本也用无样式 `<span>` 包起来**（或让强调独立成段）。**视觉零变化**。
       - 脚本已支持自动修复：`微信HTML规范校验修复_wx_html_fix.py` 无参运行即可（体检会报 `D:p内混排 N`）。

     - **⚠️ 报错必须按规则名分开看**：不同规则**互不相干**。曾把 `nestNodes`（嵌套层级）误当成「行高没修净」而白追一轮。

  3. **坐标/板块名**全套一致（如"共 N 篇"、三季名称）。
  4. **标题三处逐字一致**：正文顶部大标题 = 字段表【标题】= 发布手册引用。**比对前必须先归一化**，否则全/半角与排版差异会大量误报：
     - 去标点与引号（含中英弯直引号 `""''“”‘’`、书名号《》、括号、分号、省略号）、去空白与连接符（`-—·・`）后逐字比对；
     - 旧系列（正文标题分两行排版）额外容忍**"分词位移"**：标点落在行首/行尾导致去标点后两串略有出入时，若互为子串即视为一致；
     - **抽取正文大标题要兼容多种历史写法**：①新系列 `font-size≥20px + text-align:center`；②旧系列未写字号但 `display:block + bold + 居中`；③**单行内多个 `<p>` 连写**的情况（不能只按行匹配）。命中标题块后遇小字号行（≤16px，坐标/说明行）即停，避免把金句块、坐标行误当标题。
  5. 每篇文末**来源声明在位**、口径与用户当次一致。**自检需认三类口径**（不同系列类型写法不同，只认一种会误判）：
     - ① 课程类：「扶鹰教育-王金海课程…非课程原文/非原文摘录」；
     - ② 读书笔记类：「本文为读书笔记，观点整理自《书名》…非原文摘录」；
     - ③ **原创真实经历类**：「本文为作者真实经历原创分享…人物与细节已做模糊化处理…转载请联系授权」——实证曾把这类篇误判为"缺来源声明"。
  6. **无"点在看/点赞/转发/求关注/分享给"等动作指令**；无绝对化承诺。**检测只扫可见文字**（先剥 `<script>/<style>` 块，避免把导航脚本里的词当正文），并建**叙事豁免表**——描述性语句不算动作指令，如"点赞越多，我凉得越快""我把这套分享给你""父母改变百分之一、孩子可能改变百分之百"。
     - **⚠️ 豁免词必须"长词优先"排序后再替换**，否则短词先替换会破坏长词边界（如"百分之一"先替换会切碎"百分之百"）导致残留误报。
     - **⭐ 检查范围必须包含「标题」（2026-09-16 补，原规则只查正文与文末卡片，是边界遗漏）**：标题里同样不得出现**动作指令**——"建议收藏／看完你会更懂孩子／值得各位家长参考／一定要读／记得转发"等。**判据**：标题只承担"说清内容 + 制造点击欲"两件事；**若想表达"这份内容值得留下来"，主语必须是"我"**（"我写下来给自己留个底"），不是要求读者。
  6b. **⭐ 四条正文禁例 + 位置判别（2026-09-16 增补）**：逐篇确认没有为"更有力"而使用——①绝对化归因制造羞耻（"全看父母的嘴"）②密集引用不标出处 ③结尾居高临下的指导（"亲爱的爸爸妈妈们，嘘，别说话"）④**"普通父母/智慧父母"式二分标签给读者归类**。
     - **通用自查句**：**"这句话把说话人放在什么位置？"**——是否高于读者？是否在替读者下决定？**四条里有三条属隐性违规（对比标签／祈使句／动作词），都不刺眼，正因如此才最容易漏检。** 判据不是"语气重不重"，而是"位置高不高"。
     - **并列式结构另加一道**：写完做"**核心动作提取**"——把每个分论点的核心动作写成一句话比对；**若两三条相同，就是"换场景不换对象"的注水并列**，必须合并或换对象重写（细则见第2步"并列式分论点不得同质"）。
  7. 主表 `text-align:left;`、仅金句/标题/陪伴卡块内居中（左对齐铁律）；**正文段落均为 `<p style="margin…line-height:1.9">` 包裹、无空 spacer `<tr>` 撑段距、无 `<br><br>` 双换行、全篇无 `<div>/<h1-4>/<ul>/<li>`**（2号写法 + 微信三条铁律）。
  7b. **⭐ 内容完整性（逐篇人工回答，脚本查不出，最容易漏）**：对每篇问一句——"**这篇的场景、父母心理转折、机制、方法、边界分别是什么？**"，**五项都要能答出来**。**场景**＝长在哪个具体瞬间（有时间/动作/对话/物件）；**父母心理/认知转折**＝我自己从旧想法走到新想法的过程（没有它，文章只剩评判）；**机制**＝为什么会这样；**方法**＝读完今晚能做什么（具体话术/动作/时机）；**边界**＝适用到什么程度、何时不适用。**任何一项答不出，说明改稿时为了压重复删过头了，必须回补**。**⭐ 另须逐篇确认「收口双句」在位**（文末的**身份自述**"我也是个还在重启的爸爸…" + **认知转折**"我后来…"）——**它不是可选零件，是账号锚点级内容**；去模板化只轮换表达、不得删除。用 `工具脚本/收口双句巡检_check_closing.py 公众号/<系列>/公众号文章` 自动查（报"缺自述/缺转折/相邻句式重复"）。同时核对：**可见字符数在 1600–2400**（速览短答类 900–1400），**若比原稿减少 ≥30% 已逐项复核过叙事张力/情绪承接/方法细度/阅读节奏**。注意：节流脚本指标全绿 ≠ 文章完整（见第2步"完整性红线"）。
  7c. **⭐ 口播感（台词与金句）—— 三层分工，别把责任搞混**（2026-09-28 新增；细则见第 2 步「出声朗读测」）：
     - ① **机械筛（脚本）**：`python 工具脚本/check_spoken.py 公众号/<系列>/公众号文章` —— 报出**超长分句（>15 字）／书面连接词串联／疑似工整顺口溜**。**只筛不判：命中≠一定错，改不改由人定。**
     - ② **复读筛（Agent 可做）**：把台词/金句抽成清单、脱离上下文逐条重读"这话在饭桌上说得出口吗"。**⚠️ agent 就是生成它的模型，存在系统性盲区——只能当筛子，不能当判据。**
     - ③ **出声念（只能人工，唯一权威）**：**唯一能抓到"脸红／打结"的一环**。⛔ **Agent 不得声称执行过这一步**（它没有发声与身体反馈，"念"文本不产生任何新信息）；**交付报告里必须显式写一行「⏸ 待人工：出声朗读测」**，不得含糊带过、不得默认已完成。
  8. 封面：**2.35:1**（如1536×654）、**无文字、无 AI 水印/角标**（裁完放大右下角逐张目检）、**单张 ≤200KB**、核心意象在中央安全区；**人物头/脚完整无裁切、核心道具入画**；**人物年龄/性别/人数与人设一致**（中年爸爸≠秃顶老人，15岁儿子≠小学生/幼童，不多人）。
