## 【重要】Codex 抓到我一个真 bug：删掉了 report()，导致检测路径 NameError

### 事实核实（我独立复现，未轻信对方结论）
Codex 反馈「新版脚本漏了报告函数，检测完成会报错」。我做了三层核实：

1. **版本对比**（确证是我删的）：
   - `2a38301`（我最初写的工具）函数清单**有** `report`
   - `HEAD`（我上一轮提交的）函数清单**没有** `report`，但 L613 **仍在调用** `report(result, args)`
2. **静态复现**：加载 HEAD 版本 → `hasattr(m,'report')` = False；
   模拟检测路径调用 → `AttributeError: module 'headver' has no attribute 'report'`
3. **真机端到端**：修复后跑默认检测路径 → 正常输出（违规 0 篇 ｜ 执行异常 0 篇）

### 根因
我用**两行注释做替换边界**重写 dedupe 段：取 `#---- dedupe` 到 `#---- CLI`
两点之间的文本整体替换，而 `report()` 函数**正好夹在这两个标记之间**，被整段删掉。

### 为什么我三次测试都没发现（更值得记）
我测了 `--dry-run` / `--setup` / `--list-rules` 三条路径——
但**这三条都在到达 `report` 之前就 return 了**，**只有默认检测路径会走到它**。
我打印过函数清单，但只是扫了一眼、**没逐项比对**，等于没看。

### 处置
1. **接受 Codex 的修复**（已核实正确）：恢复 `report()`。
   且其 `only_bad` 版本**比我的更严谨**——我原版 `[x for x in result if x.get("groups")]`
   会丢掉 error 项，Codex 版含 `x.get("error")`。
2. **Codex 另补的「可见文本变化则不写回」保护**：我做了精确分支测试
   （monkeypatch 注入会改文本的 cleaned）：
   - 分支 A（文本一致）：same_text=True / written='ok' / 磁盘被改=True ✅
   - 分支 B（文本变化）：same_text=False / written=None / 磁盘被改=False ← **被拦截** ✅
   （第一版用例失败：构造的零宽字符被 visible_text 的空白压缩吃掉了，没造出"文本不一致"）
3. **固化为正式工具** `工具脚本/py_ast_health.py`（AST 静态体检，找「被调用但未定义」）
   - 用已知有 bug 的 HEAD 版本**反向验证它有效**：精准抓出 L613 report() 未定义，退出码 1
   - 全量跑 16 个工具：0 隐患，退出码 0

### ⛔ 可推广教训
**大段替换（尤其用注释行做边界）之后，不能只靠「跑通几条命令」验收。**
- **测试必须覆盖每条分支**，不能只测最短路径（`--setup`/`--dry-run` 都是提前 return 的短路径）
- **用静态检查兜底**：`python 工具脚本/py_ast_health.py`（0 退出码才算过）
- **拿注释当替换边界时，边界内内容必须先打印逐项确认**（打印了却没比对 = 没看）
- **别用内联 `python -c` 写含反引号/`$` 的中文**（本日已踩三次，见下）
