## 【重要】Codex 抓到我一个真 bug：删掉了 report()，导致检测路径 NameError

### 事实核实（我独立复现，未轻信对方结论）
Codex 反馈「新版脚本漏了报告函数，检测完成会报错」。我做了三层核实：

1. **版本对比**（确证是我删的）：
   - `2a38301`（我最初写的工具）函数清单**有** `report`
   - `HEAD`（我上一轮提交的）函数清单**没有** `report`，但 L613 **仍在调用** `report(result, args)`
2. **静态复现**：加载 HEAD 版本 → `hasattr(m,'report')` = False；
   模拟检测路径调用 → `AttributeError: module 'headver' has no attribute 'report'`
3. **真机端到端**：修复后跑默认检测路径 → 正常输出（违规 0 篇 ｜ 执行异常 0 篇）

### 根因
我用**两行注释做替换边界**重写 dedupe 段：取 `#---- dedupe` 到 `#---- CLI`
两点之间的文本整体替换，而 `report()` 函数**正好夹在这两个标记之间**，被整段删掉。

### 为什么我三次测试都没发现（更值得记）
我测了 `--dry-run` / `--setup` / `--list-rules` 三条路径——
但**这三条都在到达 `report` 之前就 return 了**，**只有默认检测路径会走到它**。
我打印过函数清单，但只是扫了一眼、**没逐项比对**，等于没看。

### 处置
1. **接受 Codex 的修复**（已核实正确）：恢复 `report()`。
   且其 `only_bad` 版本**比我的更严谨**——我原版 `[x for x in result if x.get("groups")]`
   会丢掉 error 项，Codex 版含 `x.get("error")`。
2. **Codex 另补的「可见文本变化则不写回」保护**：我做了精确分支测试
   （monkeypatch 注入会改文本的 cleaned）：
   - 分支 A（文本一致）：same_text=True / written='ok' / 磁盘被改=True ✅
   - 分支 B（文本变化）：same_text=False / written=None / 磁盘被改=False ← **被拦截** ✅
   （第一版用例失败：构造的零宽字符被 visible_text 的空白压缩吃掉了，没造出"文本不一致"）
3. **固化为正式工具** `工具脚本/py_ast_health.py`（AST 静态体检，找「被调用但未定义」）
   - 用已知有 bug 的 HEAD 版本**反向验证它有效**：精准抓出 L613 report() 未定义，退出码 1
   - 全量跑 16 个工具：0 隐患，退出码 0

### ⛔ 可推广教训
**大段替换（尤其用注释行做边界）之后，不能只靠「跑通几条命令」验收。**
- **测试必须覆盖每条分支**，不能只测最短路径（`--setup`/`--dry-run` 都是提前 return 的短路径）
- **用静态检查兜底**：`python 工具脚本/py_ast_health.py`（0 退出码才算过）
- **拿注释当替换边界时，边界内内容必须先打印逐项确认**（打印了却没比对 = 没看）
- **别用内联 `python -c` 写含反引号/`$` 的中文**（本日已踩三次，见下）

### ⚠️ 当日第三次踩「反引号被 bash 解释」的坑
写本段日志时用内联 `python -c`，文中反引号被 bash 当命令替换执行，
导致 ①日志内容大面积丢失 ②误执行若干命令 ③混入无关输出。
**已改用「Write 工具写脚本文件 → 再执行」的安全方式修复。**
→ 铁律：**凡是含反引号、`$`、中文的文本，一律不放进内联 `python -c`。**

## 四项确认落地 + 新增「合集过渡」设计

### ✅ 用户确认（2026-09-22）

### ⭐ 「妻子不只说了一次」的三层价值（已写进方案）
1. **证明这句话当时没被听进去**——她说过不止一次，说明我一开始根本没听。
   比"妻子点醒了我"真实得多，也**更痛、更可信**。
2. **让"转变"变成过程而非顿悟**——不是一句话就改变了，是被说了好几次才慢慢听进去。
   **与账号"重启"的定位完全一致：重启是过程，不是开关。**
3. **对观众更宽容**——等于告诉屏幕前的人：**你听不进去也正常，我当时也是。** 卸掉观众的羞耻感。

### ⭐ 合集过渡（新建专项文件 `_系列过渡文案_合集版.md`）
**最高原则未变：每条自成一体。合集≠连续剧。**
- ✅ 过渡只能是**软连接**："下一条我说说当时家里是怎么乱起来的"
- ❌ 禁止把核心留给下一条／禁止开头"上一集我们说到"
- **判据：把过渡句删掉，这一条还完整吗？**

**关键设计（三个易错点）**：
1. **结尾是两个去处**（下一条视频 + 公众号）→ 定顺序：**收尾金句落地 → 【引流·可选】→ 【合集·过渡】**。
   即**最后一句留给"下一条"**（能让观众留在合集里，对账号更有价值）；公众号那条说了就能记住，不必压轴。
   ⚠️ 例外：引流话术做实的那条（留给"开通知"当篇）才把引流放压轴。
2. **"收尾金句"与"过渡句"是两句、不要合并**；顺序不可反（先落地再引下一集，反了就成预告片）。
3. **⛔ 过渡句不替下一条下结论**：❌"下一条告诉你有个办法能让他回学校" ✅"下一条我说说我是怎么想这个问题的"——**只承诺"我说"，不承诺"解决"**。

## ✅ 第五条初稿：《不是没人管，是各拉各的车》（第6篇）

**原第6篇最有价值的是那张六步清单，但清单不适合做视频**：六步念下来 60 秒+，**观众一条也记不住**；且是"该做什么"的并列结构，**没有情绪落点**。

→ 定为核心：**「不是没人管，是各拉各的车」**——一句能被复述、被截图、让人照见自己家的话。
→ **清单不丢，落公众号**（那条 20 分）。**视频给洞察，公众号给清单——正是 80/20 的正确分法。**
→ 额外好处：**这条不再是一篇"教程"，而是一句"我们家的实话"。前者没人转，后者会。**

### 主打金句 + 三条做法
- ★主打：**「不是没人管，是各拉各的车」**（12字）
  ⭐ 为什么是这句：多数人以为家里出问题是因为"**没人管**"。这句把默认想法翻过来——**有人在管，但方向相反，比没人管还伤。**
- ☆次级：①「返校是目标，但不能是**唯一那把尺子**」②「车没动，**人先散了**」
- **三条做法序号条**：① 先定顺序：安全在前，返校在后 ② 分工：家里只留一个主要沟通者 ③ 换尺子：别只看"返没返校"

### ⚠️ 三处危险点（都写进拍摄建议）
1. **"她在推，我在踩刹车"**：语气是**难为情地承认**，不是"夸她贬我"的自我表演。
   ⛔ **绝不能带出一丝"她当时太急、推得太狠"的意思**——立场只能是**我错了**（她在做对的事，我在拖）。
   ⚠️ **一个字都不能检讨她**，落点始终是"**我没使劲**"。
2. **"给孩子甩脸子"要平、要快，不停、不加重**：一带情绪就变成**诉苦**；**也不要加解释**（"我那时候工作压力大"）——**一解释就变成找借口，自曝就废了**。
3. **"把气撒在她身上"一句带过、不展开**：不举例、不描写细节（例子会伤人）。

### 承接与启下的特殊处理

- **⭐ 启下（这条特殊）**：结尾明说"**最后一条，我想说给还没出问题的家庭。**"
  **为什么要明说"最后一条"**：① 给合集一个明确收口（观众知道快结束了，反而更愿意看完最后一条）② **解释为什么下一条换题材**（前四条讲"已经出问题了怎么办"，最后一条讲"还没出问题时该想什么"）——不解释观众会觉得跳。
  ⚠️ 不写成"下一条告诉你怎么预防"（不承诺结果）。
