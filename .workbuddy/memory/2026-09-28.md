## 核实 Gemini 的「全库 AI 味诊断」（用户转来，问"你看看"）

**背景**：用户转来 Gemini 对全库 192 篇正文的 6 条「AI 味」诊断 ＋ 5 条通用写作建议，要我评审。
（与今天早些时候的 **Codex 评测核实** 同源——**用户有"定期转外部 AI 评测让我核"的习惯，这是第 2 次**。）

### 方法（新增可复用工具）

**新建 `工具脚本/ai_style_audit.py`**（只读，不改任何文件）——把"感觉像 AI 写的"变成可复核数字。
指标：开篇 N 字内时间戳／冲突动作／顿悟句式／「不是…而是」密度／打卡模板／端水句／结尾模板，
并输出**按系列的命中密度榜** ＋ 命中篇目清单。用法：`python ai_style_audit.py --top 14`。

### 全库实测（198 个 `正文_*.html` ／ 24 系列）

| 指标 | 实测 | Gemini 的说法 |
|---|---|---|
| 开篇 300 字内分钟级时间戳 | **44/198 = 22.2%** | "几乎全部"（夸大 4~5 倍） |
| 冲突动作（摔门/反锁/砰） | 33/198 = 16.7% | "几乎是默认开场" |
| 顿悟句式 | 31/198 = 15.7% | "每篇第 3~5 段必有一次" |
| **「不是…而是」** | **134/198 = 67.7%，平均 1.28 次/篇** | "篇篇充斥着" |
| 打卡/工具模板 | 45/198 = 22.7% | "每篇都有 7 天打卡格" |
| 端水句（因人而异/不意味着） | **9/198 = 4.5%** | "正文里泛滥"（几乎不存在） |
| 结尾模板（重启的爸爸） | **164/198 = 82.8%** | 判为"文末牛皮癣"（**误判**） |

### 关键判定

1. **它没编造**——抽查 4 组引用（"分数是一时的格局是一世的"／"夸他的鞋"／"恋，也是练"／"世界卫生组织"）
   **全部命中真实文件**，24 个系列也数对了。**证据质量高**。
2. **但统计方法有硬伤**：把自己的阅读印象当成全库统计，**整体夸大 4~5 倍**。
   （讽刺点：**"把局部印象过度概括"本身就是 AI 味的一种**。）
3. **⭐ 它最大的一处误判**：把 **82.8% 的「结尾重启爸爸」判成 AI 套路/牛皮癣**——
   那实际是**账号锚点级内容，SOP 明文「收口双句不可删」**。它不知道这是有意设计，
   **不能按"去 AI 化"删掉**（该数字也正好暴露：仍有 34 篇缺失，与"33 篇缺失"的旧账吻合）。
4. **⭐ 真正的问题比它说的更精准**：不是"全库泛化"，是**集中爆发在少数系列**——
   `手机方案` 系列 **14 篇正文开篇全部落在晚十点—凌晨一点**（占全库时间戳命中的近 1/3）；
   青春期30讲（第10/18篇的金句）、手机方案第1篇（第三方科普腔）也都是**单系列现象**。
   → **定位不同 → 修法完全不同**：它主张"改全库 prompt"，实际应该**改单系列的开篇规则**。
5. **它建议里有 P0 风险的一条**：建议 3「医学与免责声明全部收敛到文末灰字，正文只讲一个洞察」
   ——⛔ **直接冲撞 P0「适用与风险边界」**（拒学/自伤/抑郁类必须在正文给专业求助边界），**不可照做**。
6. **建议 4/2 有二次风险**：「写父亲翻车」「让孩子真实反击」方向对，
   但⛔ **不能为"翻车"编造情节、不能替孩子补台词**（撞叙事真实性三分法）——
   须限定在"改编声明覆盖范围内"或真实素材池。

## SOP 补丁：「出声朗读测」分三层 + 明确 Agent 边界

**用户问**：「所以后续在生成的你都会自己朗读一遍？」

**答**：**不会，也做不到**——朗读测要抓的是"脸红／舌头打结"，那是**身体反应**；
我只有一种模式，**恰好就是该条要避开的"默读"**，"念"文本对我**零信息增量**。**声称念过＝不实汇报。**

⭐ **用户这一问点出了 SOP 的执行主体错配**：原文写着"**要出声，不能默读**"，却只标"人工必经项"，
**没写 agent 该做什么** → agent 要么默默跳过、要么含糊带过，**用户两样都无从察觉**。

### 改了什么（专家包三方 PASS）

| # | 位置 | 变更 |
|---|---|---|
| 1 | `02-writing.md`「出声朗读测」 | 扩成**三层分工**：①**机械筛**（脚本）②**复读筛**（agent 可做，**有系统性盲区**）③**出声念**（**只能人工，唯一权威**）；＋ **⛔ Agent 边界两条**：**不得声称执行过**／**交付须显式写「⏸ 待人工：出声朗读测」** |
| 2 | `08-selfcheck.md` 第 9 步 | 新增 **7c 条**（紧挨 7b「内容完整性·脚本查不出」那条，同属人工必过项） |
| 3 | **新工具 `工具脚本/check_spoken.py`** | 第①层实现：抽台词/金句 → 报超长分句（>15 字）／书面连接词／连续同字数分句。**只读、只筛不判** |

### ⚠️ 脚本踩的三个坑（均已修）

1. **引号要在「去标签后的纯文本」里找**——否则匹配到 HTML 属性（`style="display:inline-block…"`），
   **把 CSS 当成台词**（实测第 1 篇直接报了条 20 字的"台词"，属假阳性）。
2. **连接词只对台词测**——金句是"可独立截图的一句话"、本就偏书面，套台词标准会大面积误报。
3. **箭头链不是台词**（"难受→刷屏→更晚睡"）。

### 验证

手机方案 9–14 篇：**台词 42 条（5 条待人工确认）／金句 19 条（7 条待人工确认）**——
命中的都是真实偏长的台词，**无属性误报**；专家包三方 md5 全一致。

⭐ **沉淀判据（可推广）**：**SOP 里凡"要靠身体／感官反馈"的自检项（朗读、听感、目检），必须写明 agent 边界**，
否则规则会退化成"agent 看一眼、跳过、不吭声"。
→ 同类待查：视频号出片的"**逐张目检画面**"（我能读图，但应写清"**读图 ≠ 人眼在手机上的观感**"）。
