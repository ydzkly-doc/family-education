## 公众号排版视觉规范——色调与结构（2026-09-03 沉淀，跨系列复用）
> 经验来源：青春期30讲（18篇）按三季换莫兰迪色；为什么学生不喜欢上学（8篇）从旧 class/style 写法整体重制为 table 规范；孩子不上学了怎么办（6篇）系统换色。以下为可直接套用的标准。

**一、HTML 结构铁律（微信粘贴不塌的前提）**
> ⚠️ **【2026-09-05 起最高优先级·推翻 table 骨架】布局一律用 `<section>` 流式，禁用 `<table>/<tr>/<td>` 做布局。** 实测：微信**安卓 X5 内核会把 `<table>` 宽度固化，窄屏(360–410px)整列右裁、右侧内容被屏切掉**；iOS WebKit 二次缩放故正常（现象="安卓显示不全、苹果正常"）。改 width:100%、剥 data-id、拖窄浏览器复制都无效，根子是 table 布局。新标准：每个块 `<section style="box-sizing:border-box;width:100%;…">`，卡片靠 background/padding/border-radius/border-left；**禁容器级固定宽(width/max-width:≥200px，如680/677px)、禁 align="center" 居中嵌套**；多列网格(三季卡)→纵向堆叠满宽 section；竖条小标题→`border-left:5px solid 主色`；文字仍用 `<p>/<span>/<b>/<strong>`，禁 div/h/ul/li/img/data-*。**旧 table 稿一键转换：`工具脚本/table转section_微信正文流式重构.py <文件…>`（幂等）；预览重建 `工具脚本/重建全部正文预览.py`；交付校验跑 `wx_html_fix.py --check`。** 2026-09-05 已对 8 系列 71 篇全部转换合格，备份在 `_backup_table改section_20260905/`。以下 table 骨架描述仅作历史存档，不再使用。
- （旧·已废弃）外层：`<table width="100%" style="background:#页面底色">` → `<tr><td align="center" style="padding:24px 12px;">` → 内层 **680px 主表**。
- （旧·已废弃）主表必须显式 `style="...text-align:left;"`（text-align 可继承，防止外层 `align="center"` 让正文段落也居中）。
- **正文段落/小标题/卡片说明一律左对齐**；只有顶部标题块、金句块、陪伴卡、诗句引文、卡片标题在**该块自身 style** 写 `text-align:center;`。
- 所有视觉元素（卡片、色块、竖条小标题、示意图、标签胶囊）**全用 `<table>+<tr>+<td>`+内联 style 绘制**；严禁 `<img>` 外链位图、严禁 `<style>` 块/class。
- **【2026-09-04 起强制】标签白名单仅 `table/tr/td/p/span/b/strong/br`；全篇禁 `<div>`、`<h1>~<h4>`、`<ul>/<ol>/<li>`、任何 `data-*` 属性**。列表用 `<br>`+`·`/`①②③` 或 table 单元格实现。文字颜色永远写在包住文字的 `<p>/<span>/<b>/<strong>` 自身 style 上，**`<td>/<section>/<th>` 只承担 background/padding/width/border，不写 color**（td 内裸文字必须包 `<span style="color:同色">`）。
- **白字大标题**：一行一个独立 `<p style="color:#fff;text-align:center;display:block;">`，**绝不在白字标题/色块内用 `<br>` 拆行**（br 会打断第二行白色继承、回退深色看不见）；正文段落内部才允许单个 `<br>`（禁 `<br><br>`）。
- 标准骨架（自上而下）：标题色块（坐标小字+主标题+「第X篇·共N篇|主题」）→ 开场叙事 → 台词卡（暖色）→ 竖条小标题×N → 正文段 → 方法/对照/流程 table 卡 → 「我后来试的几件小事」卡 → 金句居中块 → 预告/陪伴卡（`#f4f6f5`类灰底，无动作指令）→ 来源声明（米白 `#faf9f6`+灰字 `#9a9890`，左对齐）。

**四、微信粘贴丢样式——三类根因与一键自检修复（2026-09-04 四系列实测实证，强制）**
> 现象：HTML 粘进公众号后台后头部白字大标题整块消失、卡片标题/金句丢色。三类根因（一篇可同时含多类，处理顺序固定 **A→C→B**）：
- **A类 · data-id 残留**：秀米/外部编辑器往返保存会给每个节点注入 `data-page-node-id` 等 `data-*`（连 body/head/meta 都有）；微信把带 data-* 的节点当"外部组件"整段重置样式。→ 删全部 `data-*`。
- **C类 · div/h 骨架 + 白字标题 br 拆行**：`<div>/<h1-4>/<ul>/<li>` 的 color 微信继承最不稳；白字标题内 `<br>` 打断第二行白色。→ div/h→p，白字标题 br 拆成独立居中 `<p>`。
- **B类 · 颜色挂 td/section**：文字色写在 `<td>/<section>` 上、内部是裸文字，微信向下继承不稳会丢色。→ color 下沉到包住文字的 `<p>/<span>/<b>`；已自带色的强调标签(b/strong)内部不要再包外层色 span（会盖掉金句强调色）；一个标签只能一个 style。
- **一键工具（幂等，可重复跑）**：`工具脚本/微信HTML规范校验修复_wx_html_fix.py`。体检 `python wx_html_fix.py --check <文件…>`；修复 `python wx_html_fix.py <文件…>`（自动 A剥data-* → C div/h→p、白字拆br → B td色下沉span、合并重复style、查标签配平）。规范全文 `工具脚本/微信公众号排版HTML规范.md`。
- **交付铁律**：全部正文必须 `合格 N/N`——data-*=0、td/section/th 带 color=0、白字块 br=0、无 div/h1-4/ul/li/img/class/`<style>`块、table/tr/td/p/span/b 配平。已写入专家 wechat-article-studio SOP 第4步（三条铁律）+第9步（终检）。
