## 一、内容红线（不可让步）

**1. 文章类型分轨**（细则 `02-writing.md`）：
- **方法文/概念文** → 场景/心理转折/机制/方法/边界**五层齐全**。
- **叙事文** → 可缺机制与方法，但**必须有场景、心理转折、边界**；按三标准验收：细节诚实度/情绪克制度/承认不确定。
- **⛔"允许缺方法"≠"可不写边界"**——厌学/自伤/抑郁等议题，专业求助边界照写。

**2. 叙事真实性三分法（最高门槛）**：①用户确认真实经历→可写"我和儿子"；②课程案例/改编→**第一屏标"场景改编"**；③他人案例→第三人称。**红线：绝不把讲师自述改写成"我"。**

**3. 事实核验**：书中模型写"书中提出"、课程观点写"课程认为"；**研究/数字/履历核不到不写**；不写"必然导致"。

**4. 人物连续性**：孩子固定 **15 岁/高一/儿子**；叙事者"一个也在重启的爸爸"；后台【作者】用账号名"归途有光·和孩子一起重启"。

**5. ⛔ 正文禁例三条**：①绝对化归因+制造羞耻 ②密集引用不标出处 ③结尾居高临下给指令。

**6. 过稿捷径警惕**：并列分论点须做**"核心动作提取"**比对——同质即合并或换角度。

**7. 卡片张数按内容厚度定（2026-09-17）**：**张数是"果"不是"因"**——先数长文**独立核心意思**，卡数服从它；**3 张在某些篇就是正解**，不硬凑 5 张。区间 **3–5 张**；内容卡>3 须确认。**红线**：不为凑数拆意思（碎卡=空卡）、不为省事硬塞（过载）。**Gate A 须写明张数依据**。细则 `14-card-writing.md` 1.3。

## 二·补 · 收口双句（账号锚点，不可删）

- **规则**：文末「身份自述 + 认知转折」两句为**账号锚点级内容**，**去模板化 = 换表达 ≠ 删该层**。
  位置在**来源声明之前**；**两句应各成一段**（同一陪伴块内两个 `<p>`）。
- **巡检**：`工具脚本/收口双句巡检_check_closing.py <系列>/公众号文章`。
  判定：转折句需**单段 10–80 字**且含「转折标记 + 认知动词」——**拼成一段会因超长被漏检**。
- **⭐ 补写纪律（2026-09-19 踩坑）**：陪伴块色值（如 `#EEF4F2`）**正文中间可能也在用**。
  从前往后 `re.search` 会命中中间块并造成**破坏性替换**（曾删掉第2篇一个内容块）。
  → **文末插入/替换一律 `rfind` 倒序定位**，并加"含'爸爸'等关键词"的安全校验。
- **判"缺不缺"先跑工具**，别凭肉眼——该系列 5 篇肉眼看着都像"有结尾"，实测缺 6 项。

- **⭐⭐ C26 密度估算：直接 import 密度脚本的 `total_of`，不手写公式（2026-09-19）**：
  我手算 `130+80×标题行+66×正文行+23×(段数-1)` 得 64.9%，官方脚本报 **61.6%**——
  **差值 5%，正好横跨目标带下限**，判断会反过来。
  真公式（密度脚本 `total_of`，content 卡）：`32+28+head_h+40+30+body_h`，**不含 `23×(段数-1)`**。
  → **凡估算密度，一律 import 工具的 `total_of`**；手写公式＝自己造口径（C22 同类）。
- **⭐⭐ C27 渲染器 `save(limit_kb=100)` 必然贴上限（2026-09-19）**：
  它取"**第一个 ≤100KB 的 q 值**"，所以永远贴着 100KB——实测收尾卡余量仅 **8 字节**（C11 同类）。
  → 已改为 **98**（留 2KB），画质无可见差异。**各系列渲染器都复制同一份代码，应同步推广。**
- **⭐ C28 改配色前先 grep 色值用法（2026-09-19）**：
  `GOLD` 是高亮块**底色**（块内文字用 `INK` 深色），我差点填成深金 → 会"深字压深底"。
  **色值含义要看代码，不能凭变量名猜。**
- **⛔ C29 查 data 污染必须用完整正则（2026-09-19）**：
  第一遍只 grep `data-id` 得 0，误判"没污染"；实际属性名是 **`data-page-node-id`**（117 处）。
  → **一律用 `\s*data-[a-zA-Z0-9-]+=`**，不要用想象的属性名。
- **⭐ C30 自检脚本曾漏「原创真实经历」类（2026-09-19，已修）**：
  `系列发布全套自检_selfcheck.py` 严格分支只认"非原文摘录"三类 →
  **真实经历类系列永远无法通过**（这类本就没有"非原文摘录"一说）。
  已补判据：`真实经历 + (模糊化|转载请联系授权|不构成专业建议)`。
  **教训：判据要覆盖"内容类型分轨"的每一类，否则会把合规稿判成不合格。**

- **⛔⛔ C31 渲染器不得在「import 时」产生文件系统副作用（2026-09-19）**：
  `卡片文章渲染_card_render.py` 在**模块顶层**写了 `os.makedirs(OUT)`，而 `OUT` 是
  **"第1篇"的硬编码默认值** → ①**任何 import（含密度预估脚本）都会凭空建出**
  `卡片文章/发布包_第1篇_xxx/卡片发布包/` 空目录；②**跑第2篇时若配置未生效会错写进第1篇**。
  → **建目录一律移出模块顶层**，交给"配置读取完成之后"执行。
  ⚠️ **全库 7 个渲染器都有此缺陷**（同源代码副本），**已产生 3 个多余空目录**。
  共性教训：**只读的核对不该变成有副作用的操作**；产生的目录会被误当正式产物。
- **⭐ C32 描述与卡片的"重复"要分两类（2026-09-19）**：
  **核心事件的原话**（如"我不聊"）在描述里保留**是必要的**——描述是钩子，必须交代发生了什么；
  该改的是**整句照搬**（实测抓到最长 **31 字**逐字重复）。
  → **机械匹配只作筛子，命中后逐条人工判断**（与 C22 同源）。
  **纪律**：**设计阶段就跑一次重复度检测**（不必等写完），本次靠它提前清掉 5 处。

- **⭐⭐ C33 收尾卡金句有"宽度上限"，写前先量（2026-09-19 实测）**：
  高亮金句块**按文字宽度自适应**，**超宽就溢出画布**（实测报"越界 (-45, 580, 1287, 672)"）。
  **qsize=72 粗体下的实测临界值**：单行总宽 **≤1100px 安全**、1152px 已溢出。
  换算成字数：**约 16–17 个汉字**（含标点）。
  → **写收尾金句前先 `draw.textlength()` 量宽度**；超了**压缩表述**（如"还愿意往前挪一步的"→"还肯往前走一步"），
     **不要**去改版式参数。
  ⭐ 与 C20 同源：**渲染器报警时，先查内容是否超载，再看版式**。

## 三·补 · 卡片文章三条硬经验（2026-09-17，已入 SOP）

- **⭐⭐ C19 已连发 4 次**（密度超标）：根因都是**执行时偏离 Gate A 拆卡表**——自加节点 / 自带说明行 / **照搬长文段落**。
  **"原则提醒"对它无效，只有机械比对能拦**。→ **写配置后、渲染前先跑密度预估**（本次靠它做到 10 张卡零返工）。
- **⭐⭐ C20（体积超标先量密度）**：内容卡**压不进 100KB**（q=30 仍超）时，
  **第一反应不该是柔化底图**——**内容卡是纯色底，柔化几乎无效**；真因通常是**文字太多撑满画面**。
  → **先量密度**。反证：精减内容后**体积自然达标，q 反而从 30 升到 39–57，画质更好**。
  **压体积的正解是减内容，不是降质量。**
- **⭐⭐ C21（规则要给"目标带"，不能只给"上限"）**：与 C11（贴着上限写）同源。
- **⭐⭐ C23 卡片密度最终定案（2026-09-18，用户定"组合①"）**：
  **目标带 62–68%**（原 50–60%）、**红线 70% 不变**、**行距比 1.66**（原 1.78）、**字号 40px 不变**。
  → 单卡容量 **≈198 字 → 220–240 字**；上下留白自然值 **约 225–265px**。
  ⭐ **为什么不用"缩小字号"扩容**：40px = 手机 12.6pt（舒适线）；38px = 11.9pt（偏小）。
    **结论：靠"收紧行距 + 提高目标带"扩容，不靠"缩小字号"。40px 是底线。**
  ⭐ **控制变量是"行数"不是"字数"**（密度阶梯式，断行差一行差一整档 ≈5%）：
    **主标题 1 行→10–11 行；主标题 2 行→9–10 行**；第 11 行必破 70%。
  ⛔ **留白不是独立参数**：`留白 = 可用区×(1−密度)`——**压留白不降密度、反而升密度**。
    SOP 只规定密度目标带，**不规定留白数值**。（我曾在方案里把因果搞反，见 C23）
- **⭐⭐ C22 复核存量时"核过"≠"核到位"**：①**必须用 SOP 规定的工具**，不自造口径；
  ②判据要**逐项确认两端**——既看"超没超上限"，也看"离上限多远、是否该写满"。
  **"落在区间内"是最懒的合规判定**，它掩盖"下限贴着旧标准"这类问题。
- **⭐⭐ C24 先判"过密还是过稀"，再选手段（2026-09-19 新发现）**：
  **改版式与改内容，对密度的影响方向相反**——
  **行距收紧 → 同样文字占高变少 → 密度下降**。
  实测：孩子总犯错误 1篇卡2 旧行距 1.78=48.8% → 新行距 1.66=**46.5%（更稀）**。

  | 病情 | 解法 | 实例 |
  |---|---|---|
  | **过密**（>70%） | 压文字（**压行距也有帮助**，两者同向） | 父母做到这点（最高 93%） |
  | **过稀**（<58%） | **必须补内容**（压行距只会更稀） | 孩子总犯错误 / 为什么学生不喜欢上学（30/65 张过稀） |

  ⛔ **默认"过密"就直接压行距 = 开错药**。**先量基线，再决定方向。**
  ⭐ 判断依据就是 `卡片密度预估_density.py` 的统计行（目标带/偏高/偏低·过稀/破红线）。
- **⭐ 扩写描述时最容易犯的错：顺手把卡片内容再讲一遍**（2026-09-19 实例）：
  我把描述扩到 608 字，复查发现 4 段里 **3 段与收尾卡重复**（"没有父慈子孝的长谈"
  "导航声比话多""他问周六放一起"全在收尾卡上）。→ 重写为 485 字，改讲卡片没讲的。
  **SOP 的「扩写后必须重做重复度对照」正是为此**——务必执行，别省。
- **⭐ 字段表标注必须与卡面逐字一致**（2026-09-19）：我在字段表里"顺手统一"了标注口径，
  但卡面印的是另一种 → 造成不一致。**改标注要同步改配置并重渲**，否则只改字段表＝造假。
  ⭐ 反过来说：**多类标注不必然是"过散"**——若各类有明确指向（心得/方法/观点/边界），
  **是合理区分，不该硬合并**。判"过散"前先问：这几类各指什么？
- **⭐⭐ C25 密度是「行数阶梯」，且可用「标题行数」配平（2026-09-19 实测，最实用）**：
  ```
  content 卡块高 = 130 + 80×标题行数 + 66×正文总行数 + 23×(段数-1)
  目标带 869~953px（62–68%）
  → 标题2行+3段+9行=930 ✅ ｜ 标题2行+4段+8行=887 ✅ ｜ 标题1行+3段+10行=939 ✅
  ```
  **阶梯特性**：改 1 行 = ±66px ≈ ±4.7%；**跨档就跳**（8行=61.6% → 9行=66.3% → 12行=77.4%）。
  ⭐ **当文案行数改不动时，改「标题行数」是配平密度的有效手段**——
  长标题拆两行 = 块高 +80px，足以把 61.6% 抬进目标带。
  **timeline 卡同理会跳档**：5 节点必须 `tl_gap≤20`、4 节点需 `tl_gap=64`
  → 已把 `tl_gap` 做成**配置项**按卡传值（渲染器已改造）。
  ⛔ **改版式常量必须同步四处**：算高公式 + 绘制循环 + 收尾线坐标 + 预估脚本。
  （我只改一处时，预估与实际差了 3%——老坑第 N 次。）
- **⭐ 补内容先解「目标行数」，再写文案**（2026-09-19）：
  两系列初始都**过稀**，我第一次补写**6 张直接破红线**（最高 85.8%）。
  → **先跑 `卡片密度预估_density.py` 拿到目标行数区间，再按行数写**，返工数大幅下降。
  **不要"写完再量"。**
- **⭐⭐ C22（判据设计错了，结论就全错）**：复核「儿童情绪管理」时我连发 3 次误报——
  ①用「12 字精确前缀」判"卡片照抄长文"→ 全红（**卡片本就该改写压缩**，逐字匹配必然全红）；
  ②判"缺引导原文"只查最后一段（实际写在第 2 段）；③把"**不是**永远不发火"误判为绝对化。
  → **复核前必须先想清楚"什么才算真问题"，再设计判据**；长句级重复要用**最长公共子串（≥14 字）**，
