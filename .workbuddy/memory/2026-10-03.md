## 追加：核实「口播区换行 vs 视频合成」（用户提问）

用户："口播文案原来是一句一行，好像和视频生成有关系，我看看新的好像没有换行了，会影响视频合成么？"

**结论：不影响。** 核实过程与结论：

1. **文件里确实是一句一行**（第 01 条第 11–48 行，每行一句）——不是没换行；
2. **"看起来没换行"是 Markdown 渲染**：CommonMark 里**单个换行 ＝ 空格**，要显示换行得行尾加两空格（硬换行）；
3. **新旧一致**：查了旧文案《别再说装病》，行尾**也没有**硬换行标记（`grep -c '  $'` 两边都是 0）；
4. **合成不受影响**：管道读**原始文本**、不经过渲染 → 逐字稿 **36 行 = 36 句**、管道解析逐项一致。

**顺带实测"能不能加硬换行"**（用户审稿被渲染视图困扰）：
- ✅ **给内容行加行尾两空格 → 完全无害**：提词器 31 句／48 行不变、管道解析逐项相同、逐字稿 638 字不变、自检逐项相同；
- ⛔ **唯一禁忌：别给 `---` 行加空格**——第一次实验就是 `sed 's/$/  /'` 全文加，把 `---` 变成 `---  ` →
  **不再被识别为分隔符**，且**被当成一句台词** → 提词器从 31 句变 32 句。**实验设计出错，第二次才测准**。

## 第十八轮：BGM 音量异常（用户听感）—— 管道一处「静默失败」

**用户反馈**：「第二篇 BGM 声量有点高，第一篇比较合适，**你调整参数了？**」

**先回答**：**没有调过参数** —— 两条 MD 的 `### 背景音乐` 节**一字不差**（`-12`／全程／压低 `8`／斜坡 `0.35`）。

**但差别是真的**，根因是**管道的 BGM 预补偿在 02 条被静默跳过**：

| | 01 条 | 02 条 |
|---|---|---|
| 日志 | `BGM 预补偿 +15.8 dB（素材 -29.8 → -14.0），有效 gain **-27.8 dB**` | **`分析失败，未取到 JSON`** → 跳过 → 有效 gain 停在 **-12 dB** |
| 无人声窗口 `mean_volume`（只有 BGM） | **-19.7 dB** | **-14.9 dB**（偏高 4.8 dB ← 用户听出来的） |

**排查（关键一步：手动复现那条命令）**：
`analyze()` 跑的是 `ffmpeg -i stage1_cut -af "<前置链>,loudnorm=print_format=json"`。
我**手动跑同一个文件、同一条命令** → **两条都成功**（01: −29.78、02: −29.33，与日志数值一致），
前 30 秒和完整跑都成功 → **说明它是偶发失败、非确定性**（`video_audio.run` 不检查返回码，所以失败被静默吞掉）。
⚠️ 排除项：`stage2 = stage1 = _stage1_cut.mp4`（已核对代码），**不是文件不一致**。

**修法（两处，都已落 + 已 skills_sync）**：
1. `video_audio.analyze(..., retries=2)` —— 取不到 JSON 就**重试**（间隔 0.8s）；
2. `video_make.py` 预补偿处：**仍失败就 `raise` 停下**，⛔ **不再静默跳过**
   （宁可让人重跑一次，也不产出"BGM 音量不对、还一声不吭"的成片）。

**重跑 02 条（第三条成片）**：预补偿**生效**（`+15.3 dB → 有效 gain -27.3 dB`，与 01 条的 -27.8 一致）；
无人声窗口 **-14.9 → -18.5 dB**（01 条 -19.7，**差 1.2 dB，基本齐平**）。
成片 **126.6s**｜161.0 MB｜**10.18 Mbps**｜响度 **−14.8 LUFS / −2.4 dBTP**｜**调色仍在**（脸部 87/121/137）｜封面卡＋归位。
旧版留 `_成品/_旧版本/成片_02_调色版_BGM偏高.mp4`。

**技能文档**：`hk54` 补「⚠️ 预补偿依赖响度分析，而分析会偶发失败」一节（含症状／根因／两处修法／**自查法**：
看 `_过程文件/合成日志*.txt` 里**有没有 `BGM 预补偿 +X dB` 那一行**，没有＝被跳过了）。

**📌 两条可复用经验**：
1. ⭐ **"看起来像人调了参数"的问题，先查"管道里有没有哪一步被静默跳过"** ——
   这次两条参数一模一样，差异全在"一个生效、一个没生效"。
2. ⭐ **静默降级比报错更贵**：`analyze` 失败只是 print 一行就过去了，
   代价是用户得靠耳朵发现 BGM 偏高、再返工两条片。
