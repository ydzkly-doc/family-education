### 建的三条标点规则（已写进 `MEMORY_内容生产侧.md` 新节）

1. ⭐ **问句就用 `？`**（含汇报式问句："什么时候算做到？""要不要当着大家更正过来？"）。
2. ⭐ **承接的两句连成一句**（`，`；各自带停顿用 `；`），目标 15~35 字、2~4 分句；⛔ 不许电报腔。
3. ⭐ **锚点句必须独占一行、以 `。？！` 收尾** → **锚点与下一句之间那个句号是"必须的"**；
   要衔接就在**下一句开头加连接词**（"所以…""它…""毕竟…"），⛔ 不是把锚点并进长句。

**④ ⛔ 当日踩到的大坑（已赶在推送前修正）**：
第一次 `git add -A` 后 `git show --stat` 才发现，**混进了 4 个 pptx（约 196MB，单个最大 141MB）**。
**根因**：我统计体积时用的是 `git status --porcelain` 的路径 → **未跟踪的目录被 git 折叠成一条**，
我又写了"是文件才算大小"，于是 `扶鹰资料/` 被算成 **0 字节**，那 141MB 完全没出现在"超 5MB"清单里。
→ **正确做法**：`git add -A` **之后**用 `git diff --cached --name-only` 逐条 stat（那时已是文件路径）。
→ **补救**：确认这些 pptx **此前从未入库**（`git ls-tree HEAD~1 扶鹰资料/` 为空）→ `git rm --cached` ＋ **`--amend`**
  （**提交未推送，amend 是唯一能把 196MB 挡在历史之外的办法**；一旦推出去就只能重写历史）。
→ **修正后**：仓库最大已跟踪文件回到 **2.81 MB** ✓。
⚠️ **判据（写进 .gitignore 注释）**：**入库看体积，不看类型**——用户只点了"视频和音频"，但 100MB+ 的二进制是同一个问题。

📌 **两条可复用经验**：
1. **统计待提交体积，必须在 `git add -A` 之后**对 `git diff --cached --name-only` 逐条 stat
   （`git status --porcelain` 会把未跟踪目录折叠成一条 → 漏掉里面的大文件）；
2. **提交未推送时，`--amend` 是唯一能把大文件挡在历史之外的机会**——推出去就只能重写历史。
