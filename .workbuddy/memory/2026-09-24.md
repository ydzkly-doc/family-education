## ⭐⭐ 发布第2条 · 用户指出"上下冲突"（2026-09-24，本轮最重要的订正）

**用户原话**：「那天我儿子跟我说，明天不想去学校。……这段上下冲突吧」

### 诊断（两处，第二处更严重）

1. **硬冲突**：孩子说"明天不想去"，两句之后又说"能去"——**同一天，两个相反的答案**，观众会读成"孩子在敷衍/改口"。
2. **⭐ 更要紧**：这个矛盾摆出来了**却没接住**。本条要立的是"**他没有骗我，他是真的想去**"——
   ⚠️ **孩子一旦先明确说过"不想去"，这个结论就被自己的开场拆了**：观众会想"他明明说了不想去，你怎么说他真想去"。

### ⭐⭐ 根因（我自己的错，值得记牢）
**那句"明天不想去学校"是我替孩子补的台词**——素材 5 里只有那四句，**没有这一句**。

> **纪律（新增）：凡涉及孩子的话，没有确认过的一句都不能补。**
> 补"我的动作/我的状态"可以（那段对话本来要交代由头，素材没给，由我交代合理）；
> **补孩子的话不行——那等于替他说了他没说过的话。**
> 与红线条「孩子侧不细写」同源，但更隐蔽：**它不是"泄露"，是"凭空生成"。**

### 改法（**用"我"做由头**）
| 改前 | 改后 |
|---|---|
| 那天我儿子跟我说，／明天不想去学校。／我张口就问—— | **那阵子我其实也不知道该怎么办。**／**那天晚上没忍住，张口就问——** |

**为什么改后反而更好**：
- 用的是**用户确认过的原话**（"其实当时只是期望，也不知道怎么办"），不是我编的；
- ⭐ **"不知道该怎么办"给"问错了"一个可理解的原因**——不是因为我凶，是我也没底。
  **观众也是这样的人**，给了原因他才敢往下听（全系列姿态：同路人不是导师）；
- **"那天晚上"→"第二天早上"** 把时间锁死，比原来更顺；
- 少一个由头，观众注意力**全集中在那三句问话上**（它们才是主角）；原来让孩子先说一句，反而分散了。

## 20:0x 技能改造：**1~N 段自适应 + 锚点定位**（用户指出两处兼容缺口）

**用户提的两个问题**（都很准）：
1. 源文件可能是 **1~N 段**，不一定固定 3 段
2. "MD 里缺时间线，要不要加？" → **结论：不加秒数，改加「锚点」**

### 一、1~N 段自适应（两条路都通）

| 输入 | 分段方式 | 阶段编排 |
|---|---|---|
| **多文件（N 个）** ⭐ 首选 | **每个文件 = 一段**，顺序即段序 | ①拼接(归一化+叠化+色温对齐+降噪) → ②剪停顿 → ③ASR… |
| 单文件（1 个） | 按「段间长静音」自动切 | ①剪停顿(保留段间停顿) → ②画面处理(切段+叠化) → ③ASR… |

**为什么多文件是首选**：不用猜段边界、**不受环境底噪影响**（`-35dB` 检不出静音时会静默退化成 1 段，
叠化悄悄失效——已加 `health_check()` 主动提醒）、段序可控。
CLI：`--video a.mp4 b.mp4 c.mp4`；spec：`"videos": [...]`。

**关键技术改动**：
- `video_visual.build_timeline(entries, ...)` —— 把「段」抽象成 `{file,start,end}`，
  于是「单文件多段」与「多文件拼接」共用同一条代码路径（`xfade_segments` 变成薄包装）。
- **`map_time(t, keep)`**：多文件模式下段边界是在「拼接时间轴」上算的，而②剪停顿会缩短时间轴
  → 必须换算，否则 `seg` 锚点整体偏移。（`cut_silence` 现在返回 keep 区间）
- `merge_short_entries()`：过短段（<0.2s）并入相邻段，否则 xfade 的 offset 越界。
- `plan_uniform_fps/size` + **在 build_timeline 内部自动探测统一**（不能外包给调用方，实测外包会漏）。
- 无音轨素材自动补 `anullsrc`，否则 `acrossfade` 引用 `[N:a]` 直接失败。

### 二、锚点定位（替代时间码）—— 回答"MD 要不要加时间线"

**结论：不加秒数。** 写秒数既费事又脆弱（素材一变全错位）。改用四种位置表达：

| 写法 | 含义 |
|---|---|
| `"anchor": "文本"` | **推荐**：自动定位到含该文本的字幕行（去标点比对 + 相似度兜底，容忍错字）|
| `"seg": 2` | 第 N 段开头（配 `offset`）|
| `"at": "end"` | 片尾倒数若干秒（配 `hold`）|
| `"start": 12.5` | 硬写秒数（最不推荐）|

配套：`hold`（持续秒数）、`lead`（anchor 提前量）。`punch`/`cover` 支持**单个对象或数组（多张卡）**。
定位失败 → **打印原因 + 列出可用字幕行**（绝不静默失败）。

### 三、本轮新抓到的坑（都是实测）

1. **⛔ 所有 `-i` 必须在所有 `-vf`/`-af` 之前** —— 已踩**两次**（selftest + e2e 脚本），
   报 `Option vf ... cannot be applied to input url <第二个输入>`。
2. **⛔ xfade 输入规格不一致** → `First input link main parameters (size AxB) do not match...`
   → **安全必须内置在拼装函数里**（自动探测统一），外包给调用方会漏。
3. **⛔ 多张卡片时间重叠 = 文字叠字** —— 实测画面上出现"检查害怕出来，也会让人觉得疼"串字。
   → 新增 `resolve_overlaps()`：优先裁前一张尾巴，裁不动（<1.2s）就把后一张整体后移。
4. **⚠️ 无音轨段拼接后会被「剪停顿」整段吃掉**（补的静音成了"长静音"，实测 13.05s → 9.30s）。

⭐ **BGM 为 opt-in，默认没有** —— `bgm: None`，与 `punch` / `cover` / `hook` / `subs_emph` 同一惯例。
**默认值判据（重要，以后新增能力照此判）**：
- **需要「额外素材」的项 → 默认关**（`None`）：punch / cover / hook / **bgm**
- **对「已有素材」做处理的项 → 默认开**：`audio.enabled` / `visual.enabled` / `cut_silence` 都是 `True`

**三条实现约定**：
1. 只有给了 `file` 才启用
2. **文件不存在 → 报错停下，绝不静默跳过**（静默跳过会让人以为垫上了 BGM，出片才发现）
3. **不自动扫 `_素材/` 里的音频**（放进去的可能只是参考素材，自动垫上会造成意外）

⭐ **两个独立能力，绝不能混**：
- **自动 ducking**（全程、跟着人声走）＝ `sidechaincompress`
- **定点额外压低**（某一句话那半秒）＝ `dips: [{anchor, extra, hold}]`
→ 用户 MD 那句「**此处背景乐压低半秒**」＝ **后者**，不是自动 ducking。两者要同时存在。

**技术影响**：加 BGM 会**拉高 PLR**（实测含 BGM 素材 17~19dB ＞ 达标上限 12.5dB）
→ 响度可能达不到 `-14 LUFS`。建议默认 `gain: -24dB` + 人声段再压 10~12dB，
当「**氛围垫**」而非「音乐」（契合用户"真人真声真实"定位）。

**MD 侧**：加「### 背景音乐」区块，**不写就不垫**。
