### ⚠️ 关键踩坑：`send2trash` 在中文路径下会误报失败
调用 `send2trash.send2trash(中文路径)` 常抛 `FileNotFoundError [WinError 2]` 或 `PermissionError [WinError 5]`，**但文件实际已成功移入回收站**。教训：
- **绝不能用它的返回值判断成败**——必须以 `os.path.exists()` 复核工作区真实状态

## 修复 git 凭据弹窗（2026-09-10 23:26–23:35）

用户截图反馈每次 git 都弹「Select a credential helper」，问"你不能自己解决么"。

### 根因（已定位）
**系统级与全局级 credential helper 叠加**：
- 系统级 ：`credential.helper=helper-selector`
- 全局级 `~/.gitconfig`：`git-credential-manager.exe`
- git 把各级 helper **累加执行** → 每次认证先弹选择框

### 修复
在用户级 `~/.gitconfig` 用 git 官方"空 helper 重置"技巧：
```
[credential]
	helper =            ← 空值清空此前所有 helper
	helper = manager
	credentialStore = wincredman
```
另清理 `[credential "helperselector"]` 残留段。**不改**系统级 PortableGit 配置。备份：`~/.gitconfig.bak_20260910`。

### 验证
- `git credential fill`：修复前卡住超时 → 修复后立即返回
- `git push` / `git fetch`：均无提示正常完成

### ⚠️ 操作失误（已如实告知用户）
- 用 `git credential fill` 验证时**回显了存储的 GitHub token 明文**（ghp_ 开头），出现在对话记录中
- 已提示用户吊销，**用户回复"不用处理token了"** → 不再跟进修
- **教训：验证凭据配置不要用会回显内容的命令；要看行为就观察"是否卡住/是否成功"，或用 `--help`/`config --get` 等不回显密文的命令**
