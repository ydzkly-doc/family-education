# 硬坑清单 · 完整取证（从 SKILL.md 外置）

> 这是 `SKILL.md`「硬坑清单」的**完整版本**：每条都带实测现象、根因、修法、判据。
> **什么时候读它**：主文件那张「一行判据表」里，看到某条**与你当前改动相关**时，再来这里看细节。
> **为什么外置**：原来 47 条 385 行，结果是「改代码前必读」变成了「会跳读」；
> 判据一行就够，细节按需查。
> 条目编号与主文件表格一致（共 47 条）。

<a id="hk1"></a>

1. **ffmpeg 滤镜里的 Windows 路径会被吃掉**
   `C:\` 的**冒号是滤镜参数分隔符**。→ **`subprocess(cwd=目标文件所在目录)`，滤镜里只写文件名**。
   `drawtext` 同理（cwd 切到字体目录，只写 `fontfile=msyh.ttc`）。


<a id="hk2"></a>

2. **CJK 满宽字符必须自动折行**
   16 汉字 × 104px = 1664px，竖屏只有 1080px → **两侧被裁**。`wrap_cjk()` 已内置并在自检打印宽度。


<a id="hk3"></a>

3. **`sys.stdout` 不可双重 `TextIOWrapper`**
   多模块互相 import 会报 `I/O operation on closed file`。→ 一律用 `sys.stdout.reconfigure(...)`。


<a id="hk4"></a>

4. **ASS 颜色是 BGR 倒序**：`#C2703C` → `&H003C70C2`。用 `ass_color()` 转，别手写。


<a id="hk5"></a>

5. **`arnndn` 后必须做采样格式归一化且显式指定采样率**
   RNNoise 按 480 样本分帧，与本构建的 AAC 编码器不兼容 → 报
   `Error submitting audio frame to the encoder: Invalid argument`。
   实测 `fltp` 失败、`s16` 成功；且不写 `sample_rates` 会被顶到 96000Hz。
   → 链尾固定 `aformat=sample_fmts=s16:sample_rates=48000:channel_layouts=stereo`。


<a id="hk6"></a>

6. **真峰值要靠 `alimiter`，且限制点比目标低约 1 dB**
   单遍 `loudnorm` 压不住真峰值（目标 -1.5，实测产出 +0.71）。
   而 `alimiter` 限的是**采样峰值**，dBTP 是**真峰值**（含采样间过冲），两者差约 0.9 dB。
   → `限制点 = TP目标 − headroom_db`（默认 1.0）。
   ⚠️ `alimiter.level` 必须为 **false**，否则自动抬电平会毁掉 loudnorm 成果。


<a id="hk7"></a>

7. **两遍 loudnorm 必须"带着前置链"去测**
   降噪/EQ/压缩会改变响度（实测掉约 6 LU）。在**前置链之前**测会算错补偿量
   （实测目标 -14 只到 -15.72）。→ `analyze(src, pre_chain, cwd)`。


<a id="hk8"></a>

8. **`acompressor.makeup` 在本链里无效**
   loudnorm 是线性补偿，会把 makeup 加的增益原样抵掉（1.0/2.0/3.0 输出完全相同）。**别调它。**


<a id="hk9"></a>

9. **HF 模型不可并发下载，且 `hf_xet` 后端可能写出 0 字节**
   → 串行下载 + **下载后实际加载校验**；必要时绕过 `huggingface_hub` 改用 curl 直下。


<a id="hk10"></a>

10. **`subprocess` 传 list，不经过 shell**（中文路径 + 特殊字符才安全）。


<a id="hk11"></a>

11. **`dict.get(k, default)` 在「键存在但值为 None」时返回 `None`，不是 default**
    `default_spec()` 里 `punch`/`cover` 默认就是 `None`，
    所以 `spec.get("cover", {}).get("at")` 会报
    `AttributeError: 'NoneType' object has no attribute 'get'`（实测踩过）。
    → **一律写 `(spec.get("cover") or {}).get("at", 0.0)`**。
    同样适用于 `spec.get("audio")`。**新增可选字段时务必套 `or {}`**。


<a id="hk12"></a>

12. **所有 `-i` 必须在所有 `-vf`/`-af` 之前**
    否则报 `Option vf ... cannot be applied to input url <第二个输入>`
    ——ffmpeg 把 `-vf` 当成**下一个输入**的选项了。
    ⚠️ **已踩两次**（自检脚本 + 端到端脚本）。造多输入命令时第一件事就是数 `-i`。


<a id="hk13"></a>

13. **`xfade` 要求各输入的分辨率/像素格式/SAR/帧率/时间基完全一致**
    不一致会报 `First input link main parameters (size AxB) do not match the
    corresponding second input link xfade parameters (size CxD)`，
    或更阴的「**命令成功但时长不对**」（实测第一次输出只有预期的 2/3）。
    → 每段分支固定加 `settb=AVTB,setsar=1,format=yuv420p`；
    音频同理加 `aformat=sample_fmts=fltp:sample_rates=48000:channel_layouts=stereo`
    再进 `acrossfade`（多段素材常因声道/采样率不一致而串不起来）。
    ⭐ **这个安全必须内置在拼装函数里（自动探测并统一），不能外包给调用方**
    —— 实测外包会漏（调用方忘记传尺寸就炸）。


<a id="hk14"></a>

14. **多张卡片时间重叠 = 两条 Dialogue 同时显示 = 文字叠字**
    金句卡 1 的 `hold` 太长会盖到卡 2 的开头，两行大字直接叠在一起
    （实测：画面上出现"检查害怕出来，也会让人觉得疼"这种串字）。
    → `resolve_overlaps()` 自动错开：优先裁前一张的尾巴，
    裁不动（会短于 1.2s）就把后一张整体后移。


<a id="hk15"></a>

15. **无音轨的片段在拼接后会被"剪停顿"整段吃掉**
    `build_timeline` 会给无音轨段补 `anullsrc` 静音，于是这一整段成了"长静音"，
    后续 `silencedetect` 会把它剪掉（实测 13.05s → 9.30s）。
    → 纯 B-roll 素材请单独确认是否需要保留；口播素材（都有音轨）不受影响。


<a id="hk16"></a>

16. **⛔ `loudnorm` 的分析结果必须校验后才能回喂**
    实测在极端素材（纯正弦波 + 数字静音）上，`loudnorm=print_format=json`
    会吐出 **`input_tp = 5825`** 这种垃圾值；直接回喂会报
    `Value 5825 for parameter 'measured_TP' out of range [-99 - 99]`，
    **整条合成命令失败、成片出不来**。
    → `valid_measured()` 校验各值是否落在合法区间，不合格就**自动退回单遍模式**。
    合法区间见 `MEASURED_RANGES`。


<a id="hk17"></a>

17. **按标题取子节时，匹配到的名字必须「越长越优先」**
    `md_spec._pick(subs, "大字卡", "金句")` 若按遍历顺序取第一个命中，
    `### 强调句（⭐ **金句**版下，这 2 句就是全部会上底部字幕的句子）`
    会因标题含「金句」二字**抢先于** `### 金句大字卡（居中）` 被命中
    → **大字卡被解析成强调句、真正的金句卡静默丢失**
    （实测 `punch[0].text` 变成了"我儿子，会不会是装的"）。
    → 修：先整键精确匹配，再按 name 长度取最长（"大字卡" 3 字 > "金句" 2 字）。
    ⚠️ **同类风险**：任何"按标题/关键词挑节"的地方，只要标题可能带说明性括号，
    就有被短词抢走的可能 —— **改 MD 标题文案时尤其要留意**。


<a id="hk18"></a>

18. **`to_end`（显示到片尾）要精确等于片长，不能写成 `max(end, total_dur)`**
    片尾定格卡走 `at:"end"` 且未给 `tail` 时，默认 tail 2.5s 会让终点落在片尾**之后**
    （实测 94.0s vs 片长 91.8s）。虽超出部分不显示，但落点不干净，
    且一旦以后加"延长片尾"的逻辑就会真的多出黑屏。
    → `to_end` 为真时直接返回 `total_dur`。


<a id="hk19"></a>

19. **⛔ 改 `scripts/` 前，先 grep 一遍要加的 CLI 参数名与函数名（协作纪律）**
    非 ffmpeg 问题，但代价一样大：曾因未先检查，在 `video_make.py` 里
    **二次定义 `--md` / `--videos-dir`** → argparse 直接报
    `conflicting option string`，**脚本完全跑不起来**；并重复实现了一个已有模块。
    → 加参数前 `grep -n 'add_argument("--xxx"' scripts/*.py`；
      加函数前 `grep -n "def xxx" scripts/*.py`。
    **多人/多会话改同一套脚本时，这条是底线。**


<a id="hk20"></a>

20. **带 `\fad` 淡入的元素在 t=0 是「完全透明」的**
    凡是"取某一帧"的场合都会被坑：
    - **封面**（`make_cover` 渲染 t=0）→ 抓到一张**纯背景图**。
      实测：封面文件一直是"没有字"的，直到这轮排查才发现（277KB vs 之前的 100 多 KB）。
    - **开头钩子**（视频号**默认取第一帧**当封面）→ 第一帧是空的。
    → 静帧 / 首帧场合一律传 `"anim": ""` **关掉淡入**（`hook` 与 `cover` 代码里已处理）。
    ⚠️ **排查手法**：对比「带 `-ss` 抓帧」与「不带 `-ss` 抓帧」的文件大小 ——
      差异巨大（61KB vs 10KB）就说明抓到的是透明帧。**这个坑不带报错，只能靠看图发现。**


<a id="hk21"></a>

21. **`amix` 默认会「归一化」音量** —— 两个输入各降 6dB 那种
    必须显式 `amix=inputs=N:duration=first:normalize=0:dropout_transition=0`：
    - `normalize=0` 否则整体电平被改（口播会莫名变小）
    - `duration=first` 以**第一个输入**（口播）长度为准
    - `dropout_transition=0` 否则某个输入结束时会有 2 秒的奇怪渐变


<a id="hk22"></a>

22. **淡入 + 淡出不能吃满整段**（BGM 头尾段尤其容易踩）
    实测：head 段只有 1.5s，而淡入 1.0s ＋ 交接淡出 0.5s = 1.5s
    → **整段都在渐变里、没有满音量时刻**，volumedetect 只有 **-58dB**（等于没听见）。
    → `_fit_fades()` 保底留 20% 长度的满音量段。


<a id="hk23"></a>

23. **"剪停顿"会把头尾静音一起压掉** —— 而那块静音正是 BGM 的落点
    默认会把长静音压到 0.35s（两侧各留 0.175s），于是 BGM 计划报「头尾太短」。
    → BGM=`头尾` 时剪停顿**自动保留头尾静音**（`keep_edges=True`）。
    ⚠️ 判断只依据配置字面值（剪停顿发生在 ASR 之前，那时还没有时间码可用）。


<a id="hk24"></a>

24. **BGM 混音必须发生在 loudnorm 之前** —— 这是「两阶段」的原因
    loudnorm 两遍法要**先测量再补偿**；若按"纯口播"测量，加进来的 BGM 能量
    会让成片整体偏响（或偏轻）。→
    `Stage A`：前置链 + BGM → **WAV**（pcm_s16le，别用 AAC，白损失一次音质）→
    `Stage B`：测量那个 WAV → loudnorm + 限制器 → 出片。


<a id="hk25"></a>

25. **自检脚本必须幂等**（清空自己的临时目录）
    实测：BGM 自检里用 ffmpeg 生成的测试音频，第二轮被当成**曲库曲目**扫进来，
    于是「曲库为空应报错」这条用例失败、曲目数从 3 变 5。
    → 开头 `shutil.rmtree(临时目录)`；曲库扫描同时忽略 `_` 开头的文件（项目惯例）。


<a id="hk26"></a>

26. **判定"某成分在不在"，基准必须与它同链路**（做验证时的思维坑）
    第一次测「BGM 有没有漏进人声段」时，我拿**原始素材**当基准，
    可成片要过 loudnorm（整体增益）→ 基准不在同一增益下，差值毫无意义，
    于是误报"有泄漏"。正解：加一组**同处理链、只是不加 BGM** 的对照组。


<a id="hk27"></a>

27. **⛔ `sidechaincompress` 在本机构「压不动」** —— 自动压低改用**人声区间音量包络**
    本机实测（440Hz 侧链 + 110Hz 主信号）：`threshold=0.0316 ratio=8 attack=80
    release=400` 压缩量只有 **~2.5dB**（期望 12dB）；`threshold` 降到 0.001、
    `ratio` 提到 20 也没变化；把 `level_in` 抬到 8 反而把**整条 BGM 抬高 18dB**
    （那是"主输入增益"，不是"压低量"）。
    → 正解：**用 ASR 给出的人声区间直接写 `volume` 包络**
    （`volume=volume=X:enable='between(t,s,e)'` 串接），实测**精确压 12dB**、区间外恢复原音量。
    附带好处是**可控、可验证**，且不依赖压缩器的信号检测行为。
    ⚠️ 每个区间前后各留 `duck_lead`（默认 0.08s）——让人声**起音之前** BGM 就退下去，
      否则第一个字会被盖住。相邻区间用 `duck_merge`（0.5s）合并，避免实例过多。


<a id="hk28"></a>

28. **⛔ `BorderStyle=3`（ASS 底板盒）的颜色取自 `OutlineColour`，不是 `BackColour`**
    实测：把底板色写进 `BackColour`、`OutlineColour` 留默认近黑时，
    渲染出来的是一块**深灰底板** —— 配上深色字**几乎看不清**
    （浅底卡的整个卖点就是"浅底深字"，这一条错了就全废）。
    → `_style_line()` 在 `border_style == 3` 时**把底板色改写到 `OutlineColour`**。
    ⚠️ 另外此时 **`outline` 的语义变成「底板内边距」**（padding），不是描边粗细
      —— 浅底卡的 `outline=18` 是在给底板留边，不是在描字边。


<a id="hk29"></a>

29. **`zoompan`（Ken Burns）有三个参数一个都不能少**
    · `d=1`  —— 每个输入帧输出 1 帧。**不给会把一帧变成 N 帧**，时长直接翻倍
    · `fps=` —— **必须显式给**，否则被强制成默认 25fps（实测素材是 30fps）
    · `s=`   —— 输出尺寸，与输入一致，避免二次缩放
    ⚠️ `x`/`y`/`z` 表达式里含**逗号** → 必须用单引号包住
      （`x='iw/2-(iw/zoom/2)'`），否则被滤镜参数分隔符切开（与硬坑 1 同源）。
    ⚠️ 它**每帧重采样**，明显拖慢编码；顺序必须是 `zoompan` 在 `ass` **之前**，
      否则字幕会跟着一起放大。


<a id="hk30"></a>

30. **`ffmpeg -i 文件`（仅探测、无输出）永远返回非零退出码**
    报错原文是 `At least one output file must be specified` —— 这是**正常行为**，
    但本项目封装的 `run()` 见到非零码会**直接抛异常**。
    → 探测类调用（`probe_duration` / `probe_fps`）一律用**裸 `subprocess.run`**。
    ⚠️ 症状很误导：堆栈指向 `RuntimeError: ffmpeg 失败：`，让人以为是命令写错了。


<a id="hk31"></a>

31. **⛔ 同一条逻辑绝不在两处各写一遍** —— 本项目**第 3 次**同类事故
    「把 hook / 金句卡 / 浅底卡 并入卡片列表」这段逻辑，在**正式流程**与
    **`--preview`** 里各写了一份，于是预览表只并入了 `punch`：
    · `--preview` **看不到开头钩子**，也看不到浅底卡（连样式分组里都没有「小卡」）
    · 但**成片完全正常** → 使用者看到预览空白，只会得出"我写了却没生效"的结论
    · 前两次同源事故：`md_spec` 漏解析 hook（引擎支持、规范也支持，只差解析一环）、
      `--set` 的覆盖被 `audio.override` 分支吃掉
    → **修法**：提成 `build_card_list()` / `count_cards()` / `describe_cards()`，
      两处**共用**；并由 `selftest.py`「⑤ 预览表完整性」把行为锁住。
    → **判据**：一旦出现"正式流程能做 A，某个检查/预览/派生视图没做到 A"，
      **先怀疑是重复实现**，而不是去补那一处。
    ⚠️ 连带陷阱：分类计数必须在 `strip_kind()` **之前**算 ——
      标记被清掉后再计数，hook 与浅底卡会**全部塌成"金句卡"**（实测）。
    ⚠️ 新增元素类型要**同步三处**：`ELEMENT_KEYS`（渲染）、`STYLE_DEF`（样式）、
      预览的样式分组列表（打印）；漏任一处就是"静默漏掉一类元素"。


<a id="hk32"></a>

32. **⛔ 强调句（底部字幕）的锚点句必须"独占一行"，否则只上屏半句** —— 2026-09-25 实测
    金句版下**上屏文字 = 锚点命中的那一"行"的原文**
    （`fill_text=True` → `resolve_place()` → `find_line_by_text()`，返回整行 `ln["text"]`，
    而**不是** MD 里那个 `「」` 文本）。于是：
    · **锚点句跨两行**（`安全在前，` / `返校在后。`）时，`k in _key(ln)` 精确包含失败
      → **退化到相似度匹配**（`difflib.ratio() ≥ 0.62`，取**最高**那一行）
      → 只命中其中一行，**字幕只剩半句**（实测「安全在前，返校在后」→ 只上屏「安全在前，」）。
    · ⛔ **症状是不报错**：相似度匹配总能"找到"一行，落点表也照常打印该条目
      → **只看落点表发现不了**（本次五条里三条中招，全靠读 ASS 才发现）。
    · 📌 **影响面**：**只有强调句**。大字卡 / 序号条 / 浅底卡的卡面文字来自 MD 的 `text`，不受影响。
    → **正解**：**要上屏的整句，在「二、口播文案」里就写成独立的一行**。
    → **判据**：改完文案跑 `--preview`，打开 `_过程文件/preview.ass`，
      核对 `,强调,` 那几行是不是**完整句子**（"落点表有条目" ≠ "上屏完整"）。
    ⚠️ **一行的宽度上限约 9~10 字**：超过会被硬折、**可能在词中间断开**
      （实测「但不能是唯一那把尺子」→ `但不能是唯` / `一那把尺子`）。
      **含逗号的句子会在标点处折、反而好看** → 长句宁可**加个逗号**，也别让它整段超宽。
    ⚠️ 连带：**序号条/浅底卡的锚点也走同一套匹配** —— 锚点句若跨行，同样会命中一半，
      只是卡面文字自写、看不出来；**卡出现的时机**会偏（挂在半句上）。
    ⭐ **"独占一行"还不够——那一行必须以句末标点结尾**（2026-09-26 补，重做 02 时实测）：
      **逐字稿的"行"是按 `。？！`（可带右引号）断句的**——**不结尾的短行会被"合并"进下一句**

40. **⭐ 成片偏暗的后期补救（"成片后处理"路线）＋ 一个码率坑** —— 2026-09-27 实测
    · **场景**：**已经出片**才发现画面偏暗（典型原因：拍摄时**逆光**、脸在阴影里）。
      不想重跑整条管道（约 10 分钟）时的补救：
      ```bash
      ffmpeg -y -i 成片.mp4 -vf "eq=brightness=0.08:contrast=1.05:saturation=1.05" \
        -c:v libx264 -preset veryfast -b:v 10M -maxrate 12M -bufsize 20M \
        -pix_fmt yuv420p -c:a copy -movflags +faststart out.mp4
      ```
    · **幅度参考**（手机室内**逆光**口播实测）：全帧 YAVG 143→**161**、人脸 150→**168**；
      `+0.04` 改善不明显、**`+0.08` 主观明显且不过曝**、`+0.13` 开始**发灰过曝**。
    · ⛔ **背景救不回来**：逆光时背景已接近饱和，提亮只会把它**推爆** → **根治在拍摄**（下一条第 6 条）。
    · ℹ️ **字幕不受影响**：白字已经饱和，`eq` 的**加法**提亮后仍是纯白（视觉无差异）→ 所以"成片后处理"是可行的。
    · ℹ️ **音频用 `-c:a copy`**：响度与真峰值**一点不动**（实测提亮前后同为 −14.7 LUFS / −2.5 dBTP）。
    · ⛔ **坑 1：`-crf` 和 `-b:v` 同时给 → 码率不可控**。同一条 10M 成片，写 `-crf 20 -b:v 10M`
      出来只有 **6426 kbps**（掉 37%、体积 305→192 MB）。→ **要锁码率就用 ABR：只给
      `-b:v … -maxrate … -bufsize …`，不要给 `-crf`**（重做后恢复 10002 kbps）。
      （⚠️ 脚本里 `-crf 20 -b:v` 能"看起来对"，是因为**输入输出内容几乎相同**；一旦画面被处理过就会掉。）
    · ⛔ **坑 2：重做必须从"未提亮"备份出发** —— 对已提亮的成片再提一次＝**叠加成 +16%**。
      → **动手前先 `cp 成片.mp4 _旧版本/成片_XX_未提亮.mp4`**。
    · ℹ️ **封面图要一起提亮**（否则封面与视频画面亮度不一致），对 `cover.png`／`cover_1x1.png`
      跑同样的 `-vf eq=...` 即可（PNG 无损，不涉及码率）。

46. **⛔ 折行会把"本该 2 行的句子变成 3 行" → 字幕上顶 → 压到嘴** —— 2026-09-28 重写 `wrap_cjk`
    · **症状**：`第四步，只商量一个能试的动作。`（16 字）被排成 `第四步，`／`只商量一个`／`能试的动作。`

      ② **硬断取中点**——为了"两行一样长好看"，代价还是**多一行**。
    · **新算法（三阶段）**：**行数 = ⌈总宽 ÷ 行宽⌉** → 每行断点**必须同时满足**
      「本行不超宽」＋「剩下的内容后面几行装得下」→ 再在候选中**优先标点、其次离目标最近**。
      → **行数最少（不顶脸）＋ 分布均衡（末行不会只剩一两个字）**。
