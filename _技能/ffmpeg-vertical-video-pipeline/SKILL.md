# 口播短视频自动合成管道

把「口播素材 + 文案」变成可直接发布的 **1080x1920 竖屏成片**，全程 ffmpeg，无 GUI。

## 何时用

- 有**口播视频**（真人出镜/录音），要做成带字幕的竖屏短视频
- 需要**批量**产出，不想一条条手工剪
- 想要"关键指标标暖色""金句大字卡""序号条"这类**精细且统一的字幕排版**
- 需要音质统一（降噪、去齿音、响度标准化到平台标准）
- 想加**背景音乐**（⭐ 默认不垫；可只垫没有口播的头尾，或全程垫底并在人声段自动压低）

**不适用**：需要复杂转场、素材库特效、花字动画的创意剪辑——那类还是剪辑软件更合适。

## 管道构成

**输入形态自适应：1 个文件 或 N 个文件（分段拍）。段数不固定，1~N 都能跑。**

| | **单文件（1 个）** | **多文件（N 个，分段拍）** ⭐ |
|---|---|---|
| 怎么分段 | 按「段间长静音」自动切 | **每个文件 = 一段**（顺序即段序）|
| ① | 剪停顿（**保留**段间长停顿）| 拼接：归一化尺寸/帧率 → 叠化 → 色温对齐 → 降噪 |
| ② | 画面处理：切段 + 叠化 + 色温对齐 + 降噪 | 剪停顿 |
| ③~⑦ | 完全一致 | 同左 |

```
①剪停顿/拼接 ─> ②画面处理 ─> ③ASR ─> ④ASS ─> ⑤音频(含BGM) ─> ⑥合成 ─> ⑦封面
```

| 阶段 | 手段 | 说明 |
|---|---|---|
| ① 剪停顿 / 拼接 | `silencedetect`+`trim`/`concat`；多文件用 `xfade` | 压缩过长停顿；多文件按文件分段并串联 |
| ② 画面处理 | `xfade` + `colorchannelmixer` + `hqdn3d` | 段间叠化 / 段间色温亮度对齐 / 画面降噪 |
| ③ 取时间码 | faster-whisper + 序列对齐 | 词级时间戳；有文案则只取时间码 |
| ④ 编译字幕 | 自建 ASS | 逐字标色、自动折行、**淡入与入场缩放动画** |
| ⑤ 音频美化 | arnndn/deesser/eq/loudnorm/alimiter | 降噪、去齿音、音色塑形、响度标准化、**首尾淡入淡出** |
| ⑤b **BGM 混音** | `amix` + **`volume` 包络** + `afade` | **默认不启用**；混音**必须在 loudnorm 之前**（见「BGM 轨道」） |
| ⑥ 合成 | `scale`+`crop`+**`zoompan`**+`ass` | 裁到 1080x1920、（可选）**画面轻微推近**、烧字幕 |
| ⑦ 封面 | 同一套 ASS 逻辑 | `-frames:v 1` 出 PNG，同时出 **1:1 方版** |

> ⭐ **多文件是首选**：不用猜段边界、**不受环境底噪影响**、段序可控。
> 单文件按静音切段只在"一次拍完、中间有明显长停顿"时可靠——
> 若环境有底噪导致 `-35dB` 检不出静音，会**静默退化成 1 段**（代码里有健康检查会提醒）。

> ⛔ **画面处理必须在 ASR 之前**：每个转场吃掉 `xfade` 秒，
> 若在语音识别之后才做，字幕时间码会整体错位。

## 前置条件

```bash
# 0) 先自检环境（会把 ffmpeg 与模型全部列出来）
python scripts/paths.py
```

| 依赖 | 说明 |
|---|---|
| **完整版 ffmpeg** | 必须含 `libx264` + `ass`/`subtitles`。⛔ 很多软件自带的 ffmpeg 是阉割版（无 libx264、无 ass），**烧不了字幕** |
| Python 环境 | 需 `faster-whisper`（语音识别）。模型可本地预置，也可让 faster-whisper 自行下载 |
| RNNoise 降噪模型 | `.rnnn` 文件，ffmpeg **不自带**，需另下（用不到降噪可不备） |
| 中文字体 | Windows 自带微软雅黑即可；ASS 用字体名 `Microsoft YaHei` |
| **BGM 曲库**（可选）| 要用背景音乐才需要：音乐放 `_资产/bgm/`（或 `<本篇>/_素材/bgm/`），配 `曲库.md` 标风格。⛔ **不联网下载**（版权）——需自行准备 |
| BGM 混音能力 | `amix` / `volume` / `afade` —— 本机构建均已具备，无需额外准备 |

**路径可通过环境变量覆盖**（换机器时用）：
- `WB_FFMPEG` → ffmpeg 绝对路径
- `WB_VIDEO_MODELS` → 模型目录

默认查找顺序见 `scripts/paths.py`。

## 快速开始

**⭐ 最省事的方式：只给「文案 MD + 素材目录」**（MD 里的「上屏方案」自动变成剪辑单）

```bash
python scripts/video_make.py \
    --md 文案.md \
    --videos-dir _素材 \
    --out 成片.mp4
```

- `--md` 读 MD 里的 **`## 上屏方案`** 区块 → 自动生成 `subs / subs_emph / punch / seq / marks / cover`
  （格式见 `reference/md_authoring_guide.md`）；**并从「口播文案」段自动抽出逐字稿**当 `--script`
  （落成 `<文案名>_文案.txt`，不用你手工抽）
- `--videos-dir` 按**文件名排序**取目录里全部视频（**忽略 `_` 开头的产物**），**顺序即段序**
  → 建议素材命名 `01.mp4 02.mp4 03.mp4`
- 想看 MD 被解析成了什么：加 `--dump-params`

**其他方式**（等价，按需选）：

```bash
# 单个素材（一次拍完）
python scripts/video_make.py \
    --video 素材.mp4 \
    --script 文案.txt \
    --out 成片.mp4

# 分段拍（N 个文件，空格分隔，顺序即段序）——推荐
python scripts/video_make.py \
    --video 第1段.mp4 第2段.mp4 第3段.mp4 \
    --script 文案.txt \
    --out 成片.mp4

# 剪辑单 JSON（可复用、可存档）
python scripts/video_make.py --spec 剪辑单.json

# 要垫背景音乐（⭐ 默认不垫，给了 --bgm-* 才混）
python scripts/video_make.py --md 文案.md --videos-dir _素材 --out 成片.mp4 \
    --bgm-style "安静的钢琴" --bgm-placement 头尾
```

- `--script` 是**一行一句**的文案（空行与 `#` 开头行忽略）。**给了就用你的文案**，只从识别结果取时间码
- **不给 `--script`** 则走听写模式：直接用语音识别分段当字幕
- 中间产物默认落在 `<成片目录>/_过程文件/`

## ⭐ 卡片位置怎么给（**不用写时间码**）

金句卡、序号条、封面都要落在某个时刻。**不要写秒数**——写秒数既费事又脆弱
（素材长度一变就全错位）。用**锚点**表达意图：

| 写法 | 含义 | 例 |
|---|---|---|
| `"anchor": "文本"` | **推荐**：自动定位到含该文本的那句字幕 | `"anchor": "不等于孩子在装"` |
| `"seg": 2` | 第 2 段开头（配 `"offset"` 微调）| `{"text": "②", "seg": 2, "hold": 2}` |
| `"at": "end"` | 片尾倒数若干秒 | `{"text": "…", "at": "end", "hold": 4}` |
| `"start": 12.5` | 硬写秒数（**最不推荐**）| |

可调参数：`hold`（持续秒数，金句卡默认 4.5 / 序号条 2.5）、
`lead`（anchor 的提前量，让卡片早于那句话出现）、`offset`（seg 微调）。

**`punch` 与 `cover` 可给单个对象，也可给数组（多张卡）**：

```json
"punch": [
  {"text": "检查没查出来，不等于孩子在装",
   "marks": [{"word": "不等于孩子在装", "color": "#B0552F", "bold": true}],
   "anchor": "他是在装病逃学", "hold": 4.0},
  {"text": "害怕，也会让人觉得疼", "anchor": "害怕考试"}
],
"seq": [{"text": "①", "seg": 1, "hold": 1.8},
        {"text": "②", "seg": 2, "hold": 1.8}]
```

⛔ **内置保护**（都实测踩过）：
- 锚点找不到 → 打印原因 **+ 列出可用字幕行**，绝不静默失败
- 多张卡时间重叠 → **自动错开**（重叠会让两条字幕同时显示 → 文字叠字）
- 卡片起点超出片长 → 明确提示

## ⭐ 字幕策略（三种版本，`spec["subs"]`）

**字幕不一定要全程都有。** 按内容需要选一种：

| 版本 | 效果 | 怎么配 |
|---|---|---|
| **全字幕** | 每句话都有底部字幕 | `"subs": "all"`（默认） |
| **金句版** | **只有关键句**才出字幕 | `"subs": [{"anchor": "某句"}, ...]` |
| **纯卡片** | 无底部字幕，只有居中大字卡 | `"subs": "none"` + `punch` |
| **全字幕 + 金句强调** | 全程都有，但金句那几句**更大更粗** | `"subs": "all"` + `subs_emph` |

```json
// 金句版：**只写锚点，字幕自动照抄原句**（时长跟随那句话）
"subs": [
  {"anchor": "我儿子，会不会是装的",
   "marks": [{"word": "装的", "color": "#C2703C", "bold": true}]},
  {"anchor": "那点力气，本来该用来帮孩子的"}
]

// 全字幕 + 金句强调（第三种版本）
"subs": "all",
"subs_emph": [
  {"anchor": "会不会是装的", "style": "强调"},
  {"anchor": "不等于孩子在装", "style": "强调", "color": "#C2703C", "size": 86}
]

// 关键词筛选（懒得逐条列时）
"subs": {"keep": ["装病", "害怕"]}
```

可选样式名：`字幕`（62px 底部）/ `强调`（78px 加粗，仍在底部）/ `序号条` / `金句`（100px 居中）。

**行内单项覆盖**（任意条目都可用）：`size` / `color` / `bold` / `scale` / `outline` / `spacing` / `outline_color`。
> ⚠️ 想**换位置**（居中、靠上）请用 `"style": "金句"` 换整套样式——
> 用行内标签改对齐要靠 `\pos` 绝对定位，中英混排时容易错位。

**片尾定格卡**（方便截图）：`{"anchor": "...", "at": "end", "hold": 2.0, "to_end": true}`

## ⭐⭐ 文案 MD 怎么写（**给内容创作者的要求**）

完整规范见 `reference/md_authoring_guide.md`。三条硬规则：

1. **⛔ 不要写时间码**。剪停顿会改时长、重拍会改时长 → 写秒数必然失效。
   改说"**挂在哪句话上**"。
2. **用「」把要上屏的原话逐字抄准**。定位靠文本匹配（去标点比对，容忍个别错字，
   但不容忍整句改写）。
3. **一次说清是哪种版本**：全字幕 / 金句版 / 全字幕+金句强调。

MD 里固定写一个 `## 上屏方案` 区块（模板见规范文档），管道就能把它读成剪辑单。
**创作者不需要写 JSON** —— MD 才是维护的那一份。

**⭐ 管道直读（不用手工转换）**：`--md 文案.md` 即可，解析逻辑在 `scripts/md_spec.py`。
支持版本三选一，且写法容错（`全字幕` / `金句` / `金句版` / `全字幕+金句` / `全字幕 + 金句强调` 都认）：
`全字幕`→`subs:"all"`；`金句`→`subs:[这几句]`；`全字幕+金句`→`subs:"all"` + `subs_emph`。

单看解析结果（不改任何文件）：

```bash
python scripts/md_spec.py 文案.md          # 打印解析出的剪辑单片段
python scripts/md_spec.py --selftest       # 解析逻辑自检（不需要外部文件）
```

**颜色约定**（`md_spec.py` 里已固定，MD 只需写"标暖色"这类词）：

| 用在哪 | 颜色 | 说明 |
|---|---|---|
| 字幕 / 强调句的标色词 | `#C2703C`（`WARM`）| 与项目品牌暖橙一致 |
| 金句大字卡的标色词 | `#A8551F`（`WARM_DEEP`）| 深一档，100px 大字上更清楚；**且默认加粗**（MD 不写也加） |

**⭐⭐ 容错边界（实测，金句版最关键的一条）**

金句版 MD 通常写着"不必逐字照稿念"。**这个承诺实测成立**：

> 模拟一次真实偏离 —— 改词（肚子疼→肚子痛）＋ 漏句 1 句 ＋ 合并 2 处 ＋ 加话 2 处
> （"嗯"、"对吧"），实念 26 段 vs 原稿 42 句 →
> 全局对齐仍 **39/42 匹配**，**6 处挂句全部定位成功**。

所以拍的时候：**可以说错、可以漏句、可以临时加话**。
⛔ 但**挂句必须"大致念到"** —— 整句换成别的意思就定位不到，字幕/卡片会缺一块。
定位失败时管道会**打印原因 + 列出可用字幕行**（绝不静默漏），照提示改锚点即可。

## ⭐ BGM 轨道（背景音乐）—— **默认关闭**

**不写 `bgm` 就是没有 BGM。** 这是刻意的：需要「额外素材」的能力一律默认关
（与 `punch` / `cover` / `hook` 同一判据），而 `audio` / `visual` / `cut_silence` 这类
「对已有素材做处理」的默认开。

### 位置是参数（二选一）

| `placement` | 效果 | 用在哪 |
|---|---|---|
| **`头尾`**（默认） | **只垫没有口播的地方** —— 开头到第一句话之间、最后一句话到片尾 | 口播为主、不想被音乐干扰 |
| **`全程`** | 整片垫底，**人声一出现自动压低**（ducking） | 想要节奏更满 |

```jsonc
"bgm": {
  "file": "轻音乐.mp3",        // 或...
  "style": "安静的钢琴",        // 按风格从曲库筛（与 file 二选一）
  "placement": "头尾",          // ⭐ 头尾 / 全程
  "gain": -24,                 // 相对口播的音量（dB）
  "duck": 12,                  // 仅「全程」：人声段再压多少 dB
  "fade_in": 1.0, "fade_out": 2.0,
  "dips": [{"anchor": "某句", "extra": 6, "hold": 0.5}]   // 定点额外压低
}
```

**`dips` 与自动 ducking 是两件事**：ducking 跟着人声全程起伏；
`dips` 是"说到这一句时 BGM 再退一档"（MD 里常写的"此处背景乐压低半秒"）。
两者可叠加，`dips` 用的还是**锚点**（不写秒数）。

### 曲库（按风格筛时用）

```
<本篇>/_素材/bgm/     ← 单篇专属
<项目>/_资产/bgm/      ← 跨系列复用（推荐）
```

风格标注靠目录下的 `曲库.md`（表格：文件 | 风格 | 情绪 | 时长 | 适用）；
没有它也能用，但退化为按文件名关键词匹配。查/试：

```bash
python scripts/video_bgm.py --list              # 曲库里有什么
python scripts/video_bgm.py --pick "安静的钢琴"   # 试一次筛选
```

匹配规则：词整体命中记 1 分；中文长词（如「安静的钢琴」）自动切 **2 字滑窗**
（安静/静的/的钢/钢琴），按命中比例计分 → **命中多者优先**，同分按文件名排序（可复现）。

### 三条实现上的硬约束

1. **混音必须在 loudnorm 之前** —— 否则 loudnorm 按"纯口播"的响度去补偿，
   加进来的 BGM 能量会让成片整体偏响/偏轻。故走两阶段：
   `Stage A 混音落盘 WAV（无损）→ 测量 → Stage B 上 loudnorm 编码`。
2. **`amix` 必须 `normalize=0`** —— 默认会按输入个数**归一化**（把音量改掉）。
   同时 `duration=first`（以口播长度为准）+ `dropout_transition=0`。
3. **`头尾` 模式要求片头片尾有静音** —— 所以剪停顿时会**自动保留头尾静音**（`keep_edges`）；
   若素材本身头尾没静音（一开口就是正片），管道会**报错停下**并提示改用「全程」，
   **不会硬塞**。

### 找不到曲子 / 没法垫时

一律**报错停下**并说明怎么办，绝不静默产出"你以为垫了 BGM、其实没有"的成片：

```
⛔ BGM 无法启用，已停下
   要按风格「安静的钢琴」筛，但**曲库是空的**。
   → 把音乐放进 `_资产/bgm/` 或 `<本篇>/_素材/bgm/`，并加一个 `曲库.md` 标注风格…
```

> ⛔ **不联网下载音乐**（版权风险）——曲子需要人提供。
> ⚠️ **BGM 会拉高 PLR**（含音乐素材实测 17~19dB ＞ 达标上限 12.5dB）→
> 响度可能够不到 `-14 LUFS`。**这与代码无关，是物理约束**；把 BGM 压低最省事。

## ⭐ 浅底文字卡 与 画面推近

### 浅底文字卡（`cards`）

**画面下方的浅底深字卡片**——用于"想让人截图存下来"的完整话（话术卡 / 台词小卡 / 小字卡 / 祝愿卡）。

```jsonc
"cards": [
  {"text": "我听到了，你现在很不想去", "anchor": "我听到了", "hold": 3.0},
  {"text": "今晚不用把所有原因说清", "anchor": "我听到了", "size": 82}
]
```

| 样式 | 用途 | 观感 |
|---|---|---|
| **`小卡`**（`cards` 默认）| 浅底文字卡 | 浅米底板 + 深墨字，**不带动画** |
| `引用` | 引用标记（轻轻提一下）| 更小 + 暖棕 + **半透明** + 不带动画 |

- **字号不用精确算**：MD 写 `比字幕大一号` / `大一点` / `小很多` 会自动映射；也可写 `字号 82`
- **位置在字幕上方**（不打架）；与金句卡共用**同一套重叠保护**（互相压住也是"叠字"）
- ⛔ **和居中大字卡别混**：`punch`（金句卡）= 全片最重那一句、居中；`cards` = 下方浅底卡，可有多张

> ⛔ **`BorderStyle=3` 画底板时，颜色取自 `OutlineColour` 而不是 `BackColour`**
> （实测踩过：写进 BackColour 会渲染成**深灰底板**，配深色字几乎看不清）——见硬坑 28。

### 画面轻微推近（`zoom`，Ken Burns）

整片从 1.0 **匀速**推到 `1+zoom`，让静止的口播画面"活"起来。

```jsonc
"zoom": 0.06      // 0 = 关（默认）；0.05~0.08 是"轻微"；太大显得刻意
```

- MD 里写 `### 画面` + `- 轻微推近` 即可；也可 `- 推近 0.1` / `- 不推近`
- ⭐ **兜底识别**：老写法把"画面轻微推近"写在金句卡条目里，**照样生效**（实测过 01 篇）
- ⚠️ 顺序固定 `scale → crop → zoompan → ass`——**字幕不跟着放大**（已实测确认）
- ⚠️ 该滤镜**每帧重采样**，会明显拖慢编码，没必要每条都开

## 标准作业流程（接到新素材时照这个走）

> **⭐ 素材还没拍？先做这一步。** 文案 MD 定稿后立刻预览上屏方案 ——
> 确认"哪句会出现、卡片挂没挂对、有没有挤在一起"，**再去拍**，
> 省掉"拍完才发现上屏方案有问题"的返工：

```bash
python scripts/video_make.py --md 文案.md --preview   # 不需要素材，几秒出落点表
```

**要垫 BGM？先确认曲库里有东西**（⭐ BGM 默认不垫，MD 里写了 / 命令行给了才会混）

```bash
python scripts/video_bgm.py --list        # 曲库里有什么
```

曲库为空、或头尾没有可垫的静音段时，管道会**报错停下**并告诉你怎么补——
**不会**静默产出"你以为垫了 BGM、其实没有"的成片。

**第 0 步 · 先确认素材是「几个文件」**

| 情况 | 怎么做 |
|---|---|
| **分段拍的 N 个文件** | 直接把多个文件传给 `--video`（空格分隔，**顺序即段序**）⭐ 首选 |
| 一次拍完的单个文件 | 传 1 个文件；如果中间有较长停顿，先 `video_visual.py --probe` 看切出几段 |
| 单个文件但**环境有底噪** | 静音可能检不出 → 用 `--noise-db -28`，或按语义切成多个文件传进来 |

**第 1 步 · 先测素材能不能达标**（不改任何文件）

```bash
python scripts/video_audio.py --analyze 素材.mp4
# 多文件时对第一个（或拼接后的）文件测即可
python scripts/video_visual.py --probe-multi 第1段.mp4 第2段.mp4   # 顺便看各段规格/色温差
```

会输出响度、真峰值、以及 **PLR 达标预判**（见下方「PLR 硬约束」）。
**先看这一步的结论再决定目标值**，否则可能白调。

**第 2 步 · 出多档对比让人挑**

```bash
python scripts/video_audio.py --ab 素材.mp4 --outdir 对比目录
```

对同一素材跑 `关闭/轻/标准/强/仿剪映声音美化` 五档，逐个听。
重点听四件事：**①背景噪声剩多少 ②齿音刺不刺 ③人声发闷还是过亮 ④音量是否平稳**。

**第 3 步 · 定稿参数**

把选定的参数用 `--set` 或写进剪辑单；确认无误后可固化进 `scripts/video_audio.py` 的 `DEFAULT`。

**第 4 步 · 出成片**

```bash
python scripts/video_make.py --video 素材.mp4 --script 文案.txt --out 成片.mp4 --set ...
```

## ⭐ PLR 硬约束（判断响度能否达标）

同时满足「目标响度 `I`」与「真峰值上限 `TP`」存在硬约束：

```
PLR（峰值−响度比）= TP − I     ← 素材自身动态范围
达标所需上限      = TP目标 − I目标 = (-1.5) − (-14) = 12.5 dB
```

**素材 PLR 超过 12.5 dB 时两者无法同时达标**——限制器会把峰值硬压下去，响度随之掉，
**调 loudnorm 补不回来**（已用 5 种方案实测确认）。

- 纯口播素材 PLR 通常 **10~12 dB** → 可达标
- 含背景音乐的视频常 **17~19 dB** → 不可达标
- `--analyze` 会给出预判，**实测预测精度 ±0.1 LU**

超标的出路：①接受现状（平台通常还会再归一化）②放宽 TP（超 0 不可行）③加强压缩以降 PLR。

## 参数速查

| 参数路径 | 作用 | 取值建议 |
|---|---|---|
| `audio.preset` | 整体预设 | 标准（默认）|
| `audio.arnndn.mix` | 神经网络降噪强度 | 0.6 温和 / **0.8 平衡** / 0.95 激进 |
| `audio.arnndn.model` | 降噪模型 | 默认 `bd.rnnn`，可选 `std/sh/mp/cb/lq` |
| `audio.highpass.f` | 去低频隆隆声 | 男声 70~90，女声 90~120 |
| `audio.deesser.i` | 去齿音强度 | 0.25 轻 / **0.4** / 0.7 重 |
| `audio.eq` | 音色冷暖厚薄（段列表）| `180Hz -2` 去闷、`3kHz +2` 提咬字、`8kHz +1` 加空气感 |
| `audio.compressor.threshold` | 压缩起点(dB) | -18 温和 / -20 更实 |
| `audio.compressor.ratio` | 压缩比 | 3.0 / 4.0 |
| `audio.loudnorm.I` | 目标响度 LUFS | 短视频平台 **-14**；越大越响 |
| `audio.loudnorm.TP` | 真峰值上限 dBTP | **-1.5**（留安全余量）|
| `audio.loudnorm.two_pass` | 线性两遍法 | true 更精确（默认）|
| `audio.alimiter.headroom_db` | 限制器余量 | 默认 1.0（见坑 6）|
| `audio.fade.in_s` / `out_s` | 首尾淡入淡出 | 0.15 / 0.25 秒 |
| `cut_silence` | 是否剪停顿 | true（默认）|
| **画面处理** | | |
| `videos` | **素材列表（N 个文件）** | 分段拍时给多个；顺序即段序 |
| `visual.enabled` | 是否做画面处理 | true（默认）|
| `visual.seg_gap` | 段间判定静音秒数（**仅单文件**）| **1.2**（比说话停顿长、比段间停顿短）|
| `visual.noise_db` | 静音判定阈值（**仅单文件**）| -35；有底噪/混响时用 **-25 ~ -30** |
| `visual.trim_tail` | 裁掉每段尾部静音秒数（**仅多文件**）| 0；分段拍常见 0.3~0.6 |
| `visual.transition` | 段间转场类型 | 叠化/黑场/白场/溶解/左滑/上滑/**无**（硬切）|
| `visual.xfade` | 转场时长（秒） | 0.25，0.15~0.4 较自然；0 = 硬切 |
| `visual.color_match` | 段间色温亮度对齐 | true；多段拍摄**强烈建议开** |
| `visual.denoise` | 画面降噪 | 关闭/轻/**中**/强；室内低光用「轻」~「中」|
| `subs` | **字幕策略** | `"all"`（默认）/ `"none"` / `[{"anchor"}]`（金句版）/ `{"keep":[...]}` |
| `subs_emph` | 给指定句叠加强调样式 | `[{"anchor":"某句","style":"强调"}]` |
| `marks` | 全片标色规则 | 匹配不到的词静默忽略 |
| **`hook`** | **开头大字钩子** | `{"text":"他是不是装的？","hold":2.6}` —— 静音场景抓人 + **保证第一帧可做封面** |
| `punch` | 金句大字卡（**居中**） | 用 `anchor`/`at` 定位；`to_end:true` 定格到片尾 |
| **`cards`** | **浅底文字卡**（画面下方） | `[{"text","anchor","hold","size"}]`；默认样式 `小卡`；可 `"style":"引用"` |
| **`zoom`** | **画面轻微推近**（Ken Burns） | `0.06` = 整片推到 1.06；`0` = 关（默认）；⚠️ 拖慢编码 |
| `seq` | 序号条 | 用 `anchor` 挂到具体句子上，别猜时间 |
| `crf` / `preset` | 画质 / 编码速度 | 18 / medium |
| **`bitrate`** | **目标码率** | `"8M"`；不设则 CRF 模式（视频号建议 6~10 Mbps）|
| **BGM（默认关）** | | |
| `bgm.file` / `bgm.style` | 来源：指定文件 / 按风格从曲库筛 | **二选一**；两个都不给会报错停下 |
| **`bgm.placement`** | ⭐ **BGM 位置** | **`头尾`**（默认，只垫无口播处）/ `全程`（整片垫底 + 自动压低）|
| `bgm.gain` | 音量（相对口播）| **-24** 氛围垫 / -18 已相当明显 |
| `bgm.duck` | 仅「全程」：人声段压低 | 默认 12 |
| `bgm.fade_in` / `fade_out` | 首尾淡入淡出 | 1.0 / 2.0 秒 |
| `bgm.duck_lead` | 压低区间提前量 | 0.08 秒（人声**起音前**就退下去，否则第一个字被盖）|
| `bgm.dips` | 定点额外压低 | `[{"anchor":"某句","extra":6,"hold":0.5}]` |

## ⭐ 视频号发布规格与安全区

| 项 | 值 | 我们的实现 |
|---|---|---|
| 分辨率 | 竖屏 **1080×1920**（9:16）| ✓ |
| 编码 | **H.264**（H.265 部分平台不支持上传）| ✓ `-profile:v high -level 4.0` |
| 帧率 | 25 或 30fps | ✓（多段不一致时自动统一）|
| **码率** | **6~10 Mbps**（平台还会二次压缩，源别太寒酸）| 默认 CRF + `-maxrate 12M`；`--bitrate 8M` 直接对齐 |
| 音频 | AAC | ✓ 192k / 48kHz |
| **封面** | 默认取**视频第一帧**；**朋友圈分享时裁成 1:1** | `hook` 保证第一帧有字；`cover` 出 9:16 + **1:1 两张** |
| **安全区** | 顶部/底部/右侧都有 UI 遮挡 | 见 `SAFE`：字幕 `margin_v=460`、`margin_lr=110` |

**遮挡区**（1080×1920，**估算值——发布前建议真机发一条"仅自己可见"确认一次**）：

| 位置 | 大小 | 会被什么压住 |
|---|---|---|
| 顶部 | 180px | 作者信息 / 关注按钮 |
| **底部** | **360px** | **标题文案 + 评论区入口 ← 最容易压住字幕** |
| 右侧 | 110px | 点赞 / 评论 / 转发 / 收藏（竖排在右下）|

`--preview` 与 `video_build_ass.py --safe-check` 都会自动检查元素是否落在安全区内；
出片时（④ 生成 ASS 之后）也会自动跑一遍并打印警告。

**内容侧结论**（检索 + 本项目 `_资产/发布数据复盘.md`，两者吻合）：

- **静音自动播放**场景 → 前 3 秒靠**大字视觉**抓人 → 这就是 `hook` 的用途
- **别照抄抖音砍时长**：真正要改的是"**信息有没有一直在往前走**"，
  删掉"刚才说到 / 接下来我们看 / 在讲这个之前"这类过渡句（信息停滞才是划走触发点）
- **结尾给"转发理由"，而不是求关注** —— 视频号的真杠杆是**被转发**，与项目复盘一致
- 微信**从未公开**完播率基准；网传"及格线"都是转抄 → 用**自己近 10 条的中位数**做基线

| `--show-chain` | 最终会跑的 ffmpeg 滤镜链与各环节开关（含 **BGM** 段） |
| `--preview` | **上屏落点表**（用逐字稿模拟时间码）+ 生成 `_过程文件/preview.ass` + **BGM 状态** |

> `--preview` 是"MD 定稿 → 开拍"之间的检查点：
> 能看到**哪句会出现、卡片挂没挂对、有没有挤在一起**。
> 模拟时间码按字数估算，**真实成片以语音识别为准**，它看的是位置关系。

**素材是「分段拍」时，先跑 `video_visual.py --probe`**：
它会告诉你切出几段、段间停顿在哪、各段色温差多少、要不要开对齐。
⚠️ 但如果**只有一个文件而它只切出 1 段**，`health_check` 会提醒你可能是底噪盖过了阈值——
这时要么调 `--noise-db`，要么**直接传多个文件**（更可靠）。

## ⛔ 硬坑清单（改代码前必读，全部实测踩过）

1. **ffmpeg 滤镜里的 Windows 路径会被吃掉**
   `C:\` 的**冒号是滤镜参数分隔符**。→ **`subprocess(cwd=目标文件所在目录)`，滤镜里只写文件名**。
   `drawtext` 同理（cwd 切到字体目录，只写 `fontfile=msyh.ttc`）。

2. **CJK 满宽字符必须自动折行**
   16 汉字 × 104px = 1664px，竖屏只有 1080px → **两侧被裁**。`wrap_cjk()` 已内置并在自检打印宽度。

3. **`sys.stdout` 不可双重 `TextIOWrapper`**
   多模块互相 import 会报 `I/O operation on closed file`。→ 一律用 `sys.stdout.reconfigure(...)`。

4. **ASS 颜色是 BGR 倒序**：`#C2703C` → `&H003C70C2`。用 `ass_color()` 转，别手写。

5. **`arnndn` 后必须做采样格式归一化且显式指定采样率**
   RNNoise 按 480 样本分帧，与本构建的 AAC 编码器不兼容 → 报
   `Error submitting audio frame to the encoder: Invalid argument`。
   实测 `fltp` 失败、`s16` 成功；且不写 `sample_rates` 会被顶到 96000Hz。
   → 链尾固定 `aformat=sample_fmts=s16:sample_rates=48000:channel_layouts=stereo`。

6. **真峰值要靠 `alimiter`，且限制点比目标低约 1 dB**
   单遍 `loudnorm` 压不住真峰值（目标 -1.5，实测产出 +0.71）。
   而 `alimiter` 限的是**采样峰值**，dBTP 是**真峰值**（含采样间过冲），两者差约 0.9 dB。
   → `限制点 = TP目标 − headroom_db`（默认 1.0）。
   ⚠️ `alimiter.level` 必须为 **false**，否则自动抬电平会毁掉 loudnorm 成果。

7. **两遍 loudnorm 必须"带着前置链"去测**
   降噪/EQ/压缩会改变响度（实测掉约 6 LU）。在**前置链之前**测会算错补偿量
   （实测目标 -14 只到 -15.72）。→ `analyze(src, pre_chain, cwd)`。

8. **`acompressor.makeup` 在本链里无效**
   loudnorm 是线性补偿，会把 makeup 加的增益原样抵掉（1.0/2.0/3.0 输出完全相同）。**别调它。**

9. **HF 模型不可并发下载，且 `hf_xet` 后端可能写出 0 字节**
   → 串行下载 + **下载后实际加载校验**；必要时绕过 `huggingface_hub` 改用 curl 直下。

10. **`subprocess` 传 list，不经过 shell**（中文路径 + 特殊字符才安全）。

11. **`dict.get(k, default)` 在「键存在但值为 None」时返回 `None`，不是 default**
    `default_spec()` 里 `punch`/`cover` 默认就是 `None`，
    所以 `spec.get("cover", {}).get("at")` 会报
    `AttributeError: 'NoneType' object has no attribute 'get'`（实测踩过）。
    → **一律写 `(spec.get("cover") or {}).get("at", 0.0)`**。
    同样适用于 `spec.get("audio")`。**新增可选字段时务必套 `or {}`**。

12. **所有 `-i` 必须在所有 `-vf`/`-af` 之前**
    否则报 `Option vf ... cannot be applied to input url <第二个输入>`
    ——ffmpeg 把 `-vf` 当成**下一个输入**的选项了。
    ⚠️ **已踩两次**（自检脚本 + 端到端脚本）。造多输入命令时第一件事就是数 `-i`。

13. **`xfade` 要求各输入的分辨率/像素格式/SAR/帧率/时间基完全一致**
    不一致会报 `First input link main parameters (size AxB) do not match the
    corresponding second input link xfade parameters (size CxD)`，
    或更阴的「**命令成功但时长不对**」（实测第一次输出只有预期的 2/3）。
    → 每段分支固定加 `settb=AVTB,setsar=1,format=yuv420p`；
    音频同理加 `aformat=sample_fmts=fltp:sample_rates=48000:channel_layouts=stereo`
    再进 `acrossfade`（多段素材常因声道/采样率不一致而串不起来）。
    ⭐ **这个安全必须内置在拼装函数里（自动探测并统一），不能外包给调用方**
    —— 实测外包会漏（调用方忘记传尺寸就炸）。

14. **多张卡片时间重叠 = 两条 Dialogue 同时显示 = 文字叠字**
    金句卡 1 的 `hold` 太长会盖到卡 2 的开头，两行大字直接叠在一起
    （实测：画面上出现"检查害怕出来，也会让人觉得疼"这种串字）。
    → `resolve_overlaps()` 自动错开：优先裁前一张的尾巴，
    裁不动（会短于 1.2s）就把后一张整体后移。

15. **无音轨的片段在拼接后会被"剪停顿"整段吃掉**
    `build_timeline` 会给无音轨段补 `anullsrc` 静音，于是这一整段成了"长静音"，
    后续 `silencedetect` 会把它剪掉（实测 13.05s → 9.30s）。
    → 纯 B-roll 素材请单独确认是否需要保留；口播素材（都有音轨）不受影响。

16. **⛔ `loudnorm` 的分析结果必须校验后才能回喂**
    实测在极端素材（纯正弦波 + 数字静音）上，`loudnorm=print_format=json`
    会吐出 **`input_tp = 5825`** 这种垃圾值；直接回喂会报
    `Value 5825 for parameter 'measured_TP' out of range [-99 - 99]`，
    **整条合成命令失败、成片出不来**。
    → `valid_measured()` 校验各值是否落在合法区间，不合格就**自动退回单遍模式**。
    合法区间见 `MEASURED_RANGES`。

17. **按标题取子节时，匹配到的名字必须「越长越优先」**
    `md_spec._pick(subs, "大字卡", "金句")` 若按遍历顺序取第一个命中，
    `### 强调句（⭐ **金句**版下，这 2 句就是全部会上底部字幕的句子）`
    会因标题含「金句」二字**抢先于** `### 金句大字卡（居中）` 被命中
    → **大字卡被解析成强调句、真正的金句卡静默丢失**
    （实测 `punch[0].text` 变成了"我儿子，会不会是装的"）。
    → 修：先整键精确匹配，再按 name 长度取最长（"大字卡" 3 字 > "金句" 2 字）。
    ⚠️ **同类风险**：任何"按标题/关键词挑节"的地方，只要标题可能带说明性括号，
    就有被短词抢走的可能 —— **改 MD 标题文案时尤其要留意**。

18. **`to_end`（显示到片尾）要精确等于片长，不能写成 `max(end, total_dur)`**
    片尾定格卡走 `at:"end"` 且未给 `tail` 时，默认 tail 2.5s 会让终点落在片尾**之后**
    （实测 94.0s vs 片长 91.8s）。虽超出部分不显示，但落点不干净，
    且一旦以后加"延长片尾"的逻辑就会真的多出黑屏。
    → `to_end` 为真时直接返回 `total_dur`。

19. **⛔ 改 `scripts/` 前，先 grep 一遍要加的 CLI 参数名与函数名（协作纪律）**
    非 ffmpeg 问题，但代价一样大：曾因未先检查，在 `video_make.py` 里
    **二次定义 `--md` / `--videos-dir`** → argparse 直接报
    `conflicting option string`，**脚本完全跑不起来**；并重复实现了一个已有模块。
    → 加参数前 `grep -n 'add_argument("--xxx"' scripts/*.py`；
      加函数前 `grep -n "def xxx" scripts/*.py`。
    **多人/多会话改同一套脚本时，这条是底线。**

20. **带 `\fad` 淡入的元素在 t=0 是「完全透明」的**
    凡是"取某一帧"的场合都会被坑：
    - **封面**（`make_cover` 渲染 t=0）→ 抓到一张**纯背景图**。
      实测：封面文件一直是"没有字"的，直到这轮排查才发现（277KB vs 之前的 100 多 KB）。
    - **开头钩子**（视频号**默认取第一帧**当封面）→ 第一帧是空的。
    → 静帧 / 首帧场合一律传 `"anim": ""` **关掉淡入**（`hook` 与 `cover` 代码里已处理）。
    ⚠️ **排查手法**：对比「带 `-ss` 抓帧」与「不带 `-ss` 抓帧」的文件大小 ——
      差异巨大（61KB vs 10KB）就说明抓到的是透明帧。**这个坑不带报错，只能靠看图发现。**

21. **`amix` 默认会「归一化」音量** —— 两个输入各降 6dB 那种
    必须显式 `amix=inputs=N:duration=first:normalize=0:dropout_transition=0`：
    - `normalize=0` 否则整体电平被改（口播会莫名变小）
    - `duration=first` 以**第一个输入**（口播）长度为准
    - `dropout_transition=0` 否则某个输入结束时会有 2 秒的奇怪渐变

22. **淡入 + 淡出不能吃满整段**（BGM 头尾段尤其容易踩）
    实测：head 段只有 1.5s，而淡入 1.0s ＋ 交接淡出 0.5s = 1.5s
    → **整段都在渐变里、没有满音量时刻**，volumedetect 只有 **-58dB**（等于没听见）。
    → `_fit_fades()` 保底留 20% 长度的满音量段。

23. **"剪停顿"会把头尾静音一起压掉** —— 而那块静音正是 BGM 的落点
    默认会把长静音压到 0.35s（两侧各留 0.175s），于是 BGM 计划报「头尾太短」。
    → BGM=`头尾` 时剪停顿**自动保留头尾静音**（`keep_edges=True`）。
    ⚠️ 判断只依据配置字面值（剪停顿发生在 ASR 之前，那时还没有时间码可用）。

24. **BGM 混音必须发生在 loudnorm 之前** —— 这是「两阶段」的原因
    loudnorm 两遍法要**先测量再补偿**；若按"纯口播"测量，加进来的 BGM 能量
    会让成片整体偏响（或偏轻）。→
    `Stage A`：前置链 + BGM → **WAV**（pcm_s16le，别用 AAC，白损失一次音质）→
    `Stage B`：测量那个 WAV → loudnorm + 限制器 → 出片。

25. **自检脚本必须幂等**（清空自己的临时目录）
    实测：BGM 自检里用 ffmpeg 生成的测试音频，第二轮被当成**曲库曲目**扫进来，
    于是「曲库为空应报错」这条用例失败、曲目数从 3 变 5。
    → 开头 `shutil.rmtree(临时目录)`；曲库扫描同时忽略 `_` 开头的文件（项目惯例）。

26. **判定"某成分在不在"，基准必须与它同链路**（做验证时的思维坑）
    第一次测「BGM 有没有漏进人声段」时，我拿**原始素材**当基准，
    可成片要过 loudnorm（整体增益）→ 基准不在同一增益下，差值毫无意义，
    于是误报"有泄漏"。正解：加一组**同处理链、只是不加 BGM** 的对照组。

27. **⛔ `sidechaincompress` 在本机构「压不动」** —— 自动压低改用**人声区间音量包络**
    本机实测（440Hz 侧链 + 110Hz 主信号）：`threshold=0.0316 ratio=8 attack=80
    release=400` 压缩量只有 **~2.5dB**（期望 12dB）；`threshold` 降到 0.001、
    `ratio` 提到 20 也没变化；把 `level_in` 抬到 8 反而把**整条 BGM 抬高 18dB**
    （那是"主输入增益"，不是"压低量"）。
    → 正解：**用 ASR 给出的人声区间直接写 `volume` 包络**
    （`volume=volume=X:enable='between(t,s,e)'` 串接），实测**精确压 12dB**、区间外恢复原音量。
    附带好处是**可控、可验证**，且不依赖压缩器的信号检测行为。
    ⚠️ 每个区间前后各留 `duck_lead`（默认 0.08s）——让人声**起音之前** BGM 就退下去，
      否则第一个字会被盖住。相邻区间用 `duck_merge`（0.5s）合并，避免实例过多。

28. **⛔ `BorderStyle=3`（ASS 底板盒）的颜色取自 `OutlineColour`，不是 `BackColour`**
    实测：把底板色写进 `BackColour`、`OutlineColour` 留默认近黑时，
    渲染出来的是一块**深灰底板** —— 配上深色字**几乎看不清**
    （浅底卡的整个卖点就是"浅底深字"，这一条错了就全废）。
    → `_style_line()` 在 `border_style == 3` 时**把底板色改写到 `OutlineColour`**。
    ⚠️ 另外此时 **`outline` 的语义变成「底板内边距」**（padding），不是描边粗细
      —— 浅底卡的 `outline=18` 是在给底板留边，不是在描字边。

29. **`zoompan`（Ken Burns）有三个参数一个都不能少**
    · `d=1`  —— 每个输入帧输出 1 帧。**不给会把一帧变成 N 帧**，时长直接翻倍
    · `fps=` —— **必须显式给**，否则被强制成默认 25fps（实测素材是 30fps）
    · `s=`   —— 输出尺寸，与输入一致，避免二次缩放
    ⚠️ `x`/`y`/`z` 表达式里含**逗号** → 必须用单引号包住
      （`x='iw/2-(iw/zoom/2)'`），否则被滤镜参数分隔符切开（与硬坑 1 同源）。
    ⚠️ 它**每帧重采样**，明显拖慢编码；顺序必须是 `zoompan` 在 `ass` **之前**，
      否则字幕会跟着一起放大。

30. **`ffmpeg -i 文件`（仅探测、无输出）永远返回非零退出码**
    报错原文是 `At least one output file must be specified` —— 这是**正常行为**，
    但本项目封装的 `run()` 见到非零码会**直接抛异常**。
    → 探测类调用（`probe_duration` / `probe_fps`）一律用**裸 `subprocess.run`**。
    ⚠️ 症状很误导：堆栈指向 `RuntimeError: ffmpeg 失败：`，让人以为是命令写错了。

**ASS 动画标签速查**（libass 已启用，零额外渲染成本）：
`\fad(入ms,出ms)` 淡入淡出 · `\t(参数)` 补间动画 · `\move(x1,y1,x2,y2)` 移动 ·
`\frz/\frx/\fry` 旋转 · `\blur` 模糊 · `\clip/\iclip` 裁剪遮罩

> **选型判据**：是「确定性的规则执行」就值得搬进来；
> 是「素材库存量」或「需要模型判断」就别搬（那正是剪映的护城河）。
> ⚠️ 本机构建**缺 `whitebalance`**，需要白平衡时用 `colortemperature` + `colorchannelmixer` 组合替代。
