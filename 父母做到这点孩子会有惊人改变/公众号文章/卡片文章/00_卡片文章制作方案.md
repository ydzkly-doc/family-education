### 🔴 本篇修掉的三个缺陷（两个是**首次发现**的通用问题）

| # | 缺陷 | 根因 | 修法 |
|---|---|---|---|
| 1 | ⭐⭐ **符号豆腐块** | 对照卡原用 `✕`/`✓`（U+2715/U+2713）——**微软雅黑不含这两个区段**，渲染成**空心方框** | 先换 `×`/`√`（但实测 `×` 仅 28×28、`√` 33×44，与 56px 中文字不匹配）→ 换全角 `Ｘ`/`Ｏ`（42×42 饱满，但中文语境里像英文）→ **最终改为纯中文「旧 / 新」**（零字体风险，且与第 2 篇"旧车/新车"呼应） |
| 2 | ⭐ **引号用了 ASCII 直引号** | 配置与描述全是 `"`（U+0022），**中文排版应为全角 `""`**——不是错别字，是排版规范问题 | 全量改为全角；并在交付自检里加了"引号已全角"这一项 |
| 3 | **封面卡越界** | 改全角引号后行变宽，墨迹到 x=-13/1255 | 字号 112 → **84**（11 字行，可用宽 1050px → 上限 88） |

### ⭐ 为缺陷 1 加了「豆腐块自检」（脚本能力提升）

**`has_glyph(ch)`**：判定某字符在该字体下是**真实字形**还是**豆腐块**——
判据是「包围盒四边实心 + 中心区域近乎全空」（空心方框特征）。
**`check_symbols(texts)`**：扫描文案里所有非中文非 ASCII 符号，**渲染时自动报警**。

**⚠️ 写这个检测器踩了三次坑（值得记）**：
1. 首版用 `np.asarray()`，但**脚本根本没导入 numpy** → 异常被 `except` 吞掉 → **静默返回"有字形"**，
   **检测器形同虚设**。→ 改为纯 PIL 实现，并给 `except` 加**打印告警**（不再静默）。
2. 第二版用 `mask.load()` → `ImagingCore` 没有该方法 → 同样走异常分支。
3. 第三版用 `bytes(mask)` + stride 手工索引 → **stride 算法不对**，读数全错。
4. **最终版**：`ImageDraw` 画到 `Image` → `list(im.getdata())` → 二维索引。**简单可靠**。

**→ 教训：检测器自己有 bug 时最危险——它会让"自检通过"变成假象。**
   因此**必须做反向测试**（拿已知有问题的输入喂进去，看它报不报警）。
   本次反向测试：`check_symbols(['✕…','✓…'])` **必须**返回缺字列表——通过后才敢信它。

### ⭐ 新增卡型：**四宫格卡（quad）**

**为什么加**：系列规划明确要求"十六字箴言四宫格卡片"，**原脚本没有此卡型**。

**版式**：2×2 等大圆角格，每格「大字（敬/慈/和/真）+ 一句白话」；
格底色**交替**（LIGHT / PAPER）形成视觉节奏；格高**取最高者统一**，保证两行对齐。

**JSON 用法**：
```json
{ "type": "quad", "topic": "...", "head": "...",
  "quads": [ {"t":"对上以敬","d":"对长辈：可以有不同意见，但不当面顶、不带刺。"}, ... ] }
```

## 七、⚠️ 累计教训（跨篇）

| # | 教训 | 出处 |
|---|---|---|
| 1 | **版式类判断必须实测，不能凭目测** | 第 1 篇（疑"下方留白偏多"，实测均衡）；第 2 篇（疑"署名偏挤"，实测间距 257–328px 充足）——**两次目测都错** |
| 2 | **底图越亮，保护性暗化与压字强度越要调高** | 第 1 篇收尾卡（veil 0.44→0.52）；第 2 篇收尾卡（归因于亮度均值 49.8 更高，`--closing-top` 直接取 0.40） |
| 3 | **估 ≠ 实测** | 第 2 篇设计文档初稿把描述估成 371 字，实测 394（差 23）。**字数一律以脚本输出为准** |
| 4 | **自检脚本自己也可能有 bug** | 第 2 篇自检里"末段引导长文"判定写错（`any(... or ...)` 逻辑错），**误报 ❌**；核实后为 ✅。→ **自检报错先核实，别急着改内容** |
| 5 | ⭐⭐ **自检器自己有 bug 时最危险** | 第 3 篇写"豆腐块检测"时，首版因 numpy 未导入**静默返回"正常"**，检测器形同虚设。→ **检测器必须做反向测试**（喂已知问题输入，验证它真会报警） |
| 6 | ⭐ **中文字体不等于全符号字体** | 微软雅黑**不含** U+2713/2714/2715/2717（✓✔✕✗）等常用符号区段。→ 卡片文案里的**任何非中文符号都要先验字形**，优先用纯中文表述 |
| 7 | **引号要用全角** | 配置与描述一度全是 ASCII `"`（U+0022）。→ 中文排版用 `""`；交付自检加"引号已全角"项 |
| 8 | ⭐⭐ **内容卡的"满"要用像素验证** | 第 4 篇卡④初版 228 字 → 实测上留白仅 **210px**（可用区顶 132），**几乎顶边**；精简至 175 字后 329px ✅。**临界状态肉眼判断不了，读像素一眼就清楚** |
| 9 | **新卡型要按需新增，不要硬塞** | 第 4 篇需要"十六字四宫格"，原脚本没有 → **新增 `quad_card`**（2×2 等大格、底色交替、格高统一）。**规则要求什么版式，就补什么卡型**，不要用内容卡硬凑 |
| 10 | ⭐⭐ **内容结构决定卡型；"塞不下"是选错卡型的信号** | 第 5 篇卡④初版把"半年/一年/三年"硬塞进两格对照卡 → 第二格过载、**署名胜压到卡片框上（仅隔 46px）**。换成时间线卡后间距 268px ✅。**发现"某格塞不下"时，该换卡型，而不是硬压文字** |
