# 封面裁切前先量主体纵向区间，不要靠位移裁切线凑

| 项 | 内容 |
|---|---|
| 维度 | 07 封面与视觉 |
| 来源 | 本项目实证（孩子受欢迎能力培养 第5篇「冰箱纸条」返工 1 次，2026-09-15） |
| 状态 | ✅ 可直接用 |
| 可迁移度 | 高（任何 2.35:1 横裁 + 多元素竖向堆叠的封面都会踩） |

## 问题

2.35:1 头条封面从 3:2（1536×1024）横裁，**纵向只有 654px 可裁区**。当主体是多元素纵向铺开（三条规则、三张纸条、上中下三样物件）时，AI 很容易把整组铺满甚至超出这 654px。

居中裁 → 切掉顶部元素一半；把裁切线上移救顶部 → 切掉底部元素。**顾此失彼，怎么移都不对。**

本轮实测：三张纸条纵跨 y 130–843，**总高 713px > 654px**，无解。

## 做法

**① 生成时就在提示词里锁死整组占比（治本）**

不要只说"三张纸条"，要写清**整组在画面高度里占多少**：

```
the whole group of notes occupies only about 42-48 percent of the image height,
tightly clustered and small, with generous plain surface visible above the group and below it
```

配合既有约束 `leave at least 25 percent empty surface ABOVE the group and BELOW it`。
改后新版组高 550px，从容落入 654px 裁切带。

**② 裁切前用脚本量出主体区间再断言（可复用检查法）**

比目检可靠——取主体所在横向条带，看灰度行均值的亮/暗突变：

```python
import numpy as np
from PIL import Image

im = Image.open(src).convert('L')
a = np.array(im); h, w = a.shape
band = a[:, int(w*0.44):int(w*0.58)].mean(axis=1)   # 主体所在横向条带的逐行灰度
th = band.mean() + 5                                 # 亮主体用 +；暗主体用 -
rows = [i for i, v in enumerate(band) if v > th]
segs = []; s = rows[0]; p = rows[0]
for r in rows[1:]:                                   # 聚成连续区间
    if r - p > 8: segs.append((s, p)); s = r
    p = r
segs.append((s, p))

top, bot = segs[0][0], segs[-1][1]
CROP_H = 654
pad = (CROP_H - (bot - top)) // 2
y0 = top - pad; y1 = y0 + CROP_H

assert y0 >= 0 and y1 <= h,  '越界'
assert y1 <= 945,            '水印可能残留（水印固定在 y>945）'
assert bot <= y1,            '主体超出裁切带 → 重生，不要硬裁'
```

**③ 断言失败就重生，不要硬裁**

重生比修补便宜：修补（裁剪拼接/生成式填充）会留痕迹，而且改一处常常破坏另一处。
重生时把 ①的占比约束加进提示词即可。

## 为什么有效

- **把"构图问题"提前到"提示词问题"**：AI 不知道最终要裁 2.35:1，必须显式告诉它留白。
- **断言把目检变成闸门**：目检会漏（尤其"切掉 10% 边角"这类），脚本断言漏不掉。
- **`y1 ≤ 945` 是硬约束**：平台水印固定打在右下角 y>945，横裁要切到它就必须让下边界落在这之上。这条与"保头"常冲突，冲突时同样优先重生。

## 关联

- 与既有规则 **A2（主体不能太小）**、**B2（必须生成横图不生成竖图）**、**B3（后处理只缩不放）**、**C（裁切线纪律）** 配套使用。
- 姊妹坑：**多元素纵向铺开** 的提示词要同时给"整组占比"与"上下留白"两个数，缺一个都会返工。
