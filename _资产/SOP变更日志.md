- **新增**：删改降幅 30% 复核线、相邻篇语言指纹、不强制装配件、"结构稿 ≠ 可发布成稿"、备选标题须有据、巡检"质量优化"维度。

### 2026-09-06
- **预览污染隔离**：发现 present_files 的内置 HTML 预览面板会把渲染后的 DOM 写回磁盘源文件（注入 `data-*`）。对策：合并预览页输出到独立 `_预览/` 子目录，且 present_files 只列该副本、绝不直接列各发布包 `正文_*.html`。

### 2026-09-05
- **发布包内操作指南格式**：由 `.md` 改为纯文本 `.txt`（发布包是"打开即用"成品夹，用户习惯直接看 txt）。此规则已于 2026-09-10 进一步演进为"不再生成"。

### 2026-09-04
- **微信粘贴丢样式三类根因**（A 类 `data-*` 残留 / B 类 颜色挂容器 / C 类 div-h 骨架 + 白字标题 br 拆行）：四系列实测确认，固化为"三条铁律"+ 一键校验脚本。

### 2026-09（更早）
- **正文布局由 table 骨架改为 section 流式**：旧 SOP 曾要求"全 table 骨架"，实测**微信安卓 X5 内核会把 `<table>` 宽度固化**，窄屏（360–410px）整列右裁、内容被屏切掉（iOS WebKit 因二次缩放故正常，现象为"安卓显示不全、苹果正常"）。改 `width:100%`、剥 `data-id`、拖窄浏览器均无效，根子在 table 布局。**现行标准：section 流式 + `<p>` 段落 + 内联样式。**


## 2026-09-10 · 交付纪律纠正：**「少交付」不等于「少确认」**

**背景**：用户反馈"为什么每次都要执行 present_files，关键是执行这一步很耗时"。Agent 在改进 SOP 时**过度外推**，写成了"消耗额度的步骤可连续推进、不逐篇停问"。

**用户纠正原话**："这个不对，还是要等待我确认，但是可以不用每次都 present_files，需要我会明确给你指令"。

**被推翻的旧做法**：
1. ~~agent md 注意事项原文："…若说直接做/一次做完，记入授权并连续推进，不再逐篇停问"~~ → **删除**
2. ~~Gate 弹性条："用户可显式放行整段流程…按授权连续推进…把确认降级为告知+可回退"~~ → **改为**"关卡本身不可弹性跳过；授权仅限当次点名的那一件事，不得推及未提及关卡"
3. ~~确认判定规则："若用户一次性提前给出跨阶段授权…可视为对相应 Gate 的预先放行"~~ → **改为**"不承认概括式跨阶段授权；判断不了就按未授权处理、停下来问"
4. references/08-selfcheck.md："用 present_files 一次性交付全部成果" → 改为"交付与否听用户指令，不要每步自动 present"

**现行规则（当前唯一正确做法）**：
- **交付维度可松**：present_files 不必每次调用；中间验证/自检/脚本输出不必交付；是否交付、是否打开预览以用户明确指令为准。
- **确认维度绝不放松**：Gate 1/2/3 永远等用户当次、明确、点名到该步的指令。"直接做/一次做完/继续做/接着弄"**不得扩大解释**为对未提及关卡的授权。
- **两者的关系**：**完全无关，不得互相推导**。防抢跑自检表新增第 6 条专门针对此误推。

**附加修正**：references/04-html.md "每次 present_files 之后也应重跑" → "**若打开过 HTML 预览**（预览面板会写回 data-*），交付前须重跑"。
