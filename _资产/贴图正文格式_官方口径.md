我用的是同一份微信官方开发者文档（草稿管理 · 新增草稿 / 更新草稿），以下是**图片消息（article_type=newspic，即贴图）** 的原文口径。

---

## 一、⭐ 你问的问题：是否支持富文本？

**官方原文（draft_add / draft_update 同一字段说明）**：

> `content`　string　是　图文消息的具体内容，大小不可超过2kb，**支持HTML标签**，必须少于2万字符，小于1M，且此处会去除JS……
> **图片消息则仅支持纯文本和部分特殊功能标签如商品**，商品个数不可超过50个

**逐字解读**：

| 载体 | 正文格式 | 能不能用 HTML |
|---|---|---|
| 图文消息（news）＝长文 | **支持 HTML 标签** | ✅ 能（我们现在的正文 HTML 就是走这条） |
| **图片消息（newspic）＝贴图** | **仅支持纯文本** ＋ 部分特殊功能标签（如商品） | ❌ **不能** |

**→ 结论：贴图的正文编辑框不支持富文本。**

**具体意味着什么**：

| 能力 | 贴图正文 | 说明 |
|---|---|---|
| 加粗 / 斜体 / 下划线 | ❌ | 无富文本工具 |
| 字号 / 颜色 / 背景色 | ❌ | 同上 |
| `<section>` `<p>` 等 HTML 标签 | ❌ | 会作为纯文本显示或被过滤 |
| `<img>` 插图 | ❌ | 图片只能走 `image_info.image_list`（卡片图） |
| 分段（空行换行） | ✅ | 纯文本换行，**分段靠空行** |
| emoji / 符号 | ✅ | 实测资料称"可以加些 emoji 表情和符号" |
| 超链接（小程序 / 网站） | ✅ | 实测资料称"文字还能带上小程序和网站超链接" |

**⚠️ 由此产生一条纪律**：项目的《微信公众号排版HTML规范》（section 流式、零 data-*、标签白名单那套）**只适用于长文正文**，**对贴图正文完全不适用**——贴图正文是**纯文本**，不要往里面塞任何标签。

---

## 二、顺带核出的两处数字修正

### 修正 1：图片消息**没有 author 字段**（印证我上一轮的判断）

官方示例里，`news` 结构有 `"author":"麦多多"`，而 **`newspic` 结构的示例里完全没有 author 字段**：

```json
// 官方示例 · 图片消息结构（原文照录，注意无 author）
{
    "article_type":"newspic",
    "title":TITLE,
    "content":CONTENT,
    "need_open_comment":0,
    "only_fans_can_comment":0,
    "image_info":{ "image_list":[ { "image_media_id":IMAGE_MEDIA_ID } ] },
    "cover_info":{ "crop_percent_list":[ ... ] }
}
```

→ **贴图确实不能填作者。** 上一轮我删掉字段表里的「作者」是对的。

### 修正 2：标题长度是 **32 字**，不是我写的 64 字

官方原文：

> `title`　string　是　**标题，总长度不超过32个字**。注意不要使用Unicode转义格式。

我上一版写"上限 64 字"——**那是图文消息的标题限制**（另一份官方文档《公众平台图文消息编辑方法》写"长度不超过64字"），**图片消息是 32 字**。

**→ 影响**：主标题「我忍了20天没吼他，他一点没变」14 字，**安全**；但备选②「我变了，孩子为什么还没变？」12 字也安全。**若以后写长标题，上限按 32 字卡。**

---

## 三、字数上限：三个口径，取最严的

| 口径 | 数值 | 来源 |
|---|---|---|
| 官方 API：`title` | **≤32 字** | 微信官方开发者文档 |
| 官方 API：`content` 大小 | ≤2kb（写在图文消息条目下，**是否适用贴图不明确**） | 同上 |
| 实测：**标题＋正文合计** | **≤1064 字** | 腾讯新闻 / 电商派 实测公众号新版图片消息 |

**取法**：以**实测的「标题+正文 ≤1064 字」**为硬约束（最贴近编辑器真实表现），官方 32 字只管标题。

**我们本篇的用量**：标题 14 字 ＋ 正文 880 字 ＝ **894 字**，余量约 170 字。**安全。**

---

## 四、卡片图张数：官方上限与我原先写的不同

| 口径 | 数值 | 来源 |
|---|---|---|
| **官方 API** | **图片数量最多为 20 张**，首张即为封面图 | 微信官方开发者文档（`image_info` 字段说明） |
| 订阅号助手 | 最多 **20 张**（"文字生成图片"每张图上文字 ≤2000 个） | 微信派 / 电商派 |
| 早期实测 | 最多 **9 张** | 西瓜数据（较早版本） |

**→ 修正**：我上一版写"上限 9 张"，**偏保守**；官方现行口径是 **20 张**。
**但张数结论不变**——多方实测一致指向**张数越多越掉量**（2–3 张最佳、5 张以上掉、8 张以上断崖），
所以我们仍取 **5 张**。**"上限是多少"与"该用多少"是两件事。**

## 五、还有一处值得记：图片消息的**封面比例是 16:9**

官方文档 `cover_info.ratio` 字段说明：

> 图文消息（news）仅支持 **"2.35_1"** **"1_1"**
> **图片消息（newspic）支持 "1_1" "16_9" "2.35_1"**

实测资料也印证："图片消息跟图文消息的封面尺寸略有不同，**为 16:9**"。

**→ 含义**：贴图的封面是**首张卡片图**，而系统按 **16:9** 裁切展示。
我们的卡片是 **3:4 竖版**，首张图当封面时会被**中心裁成 16:9**——
所以**封面卡的核心文字必须放在画面垂直中央区**，否则可能在 16:9 裁切里被切掉。
**→ 这是下一版本要检查的一项**（本篇封面卡文案偏上，需复核）。
