# 两版同步规则（标准版 ↔ Codex 派生版）

> 日期：2026-09-10　｜　状态：**已生效**
> 依据：用户确认"可以定这个规则"

---

## 一、为什么需要这条规则

本项目同时存在两套 SOP：

| | 位置 | 形态 |
|---|---|---|
| **标准版** | `wechat-article-studio.zip` → `agents/wechat-article-studio.md` | 单文件完整 SOP（435 行，0–12 步） |
| **派生版** | `Codex技能/wechat-article-studio/` | SKILL.md + 5 个 references 拆分版 |

派生版的 `origin.md` 原本写着："**后续原专家包更新不会自动同步到此版**"——这意味着每改一次标准版，两版就分叉一点，最终会变成两套互相矛盾的标准。

**规则的目的：让"分叉"变成"有序同步"。** 不是要求两版完全一样（它们在平台适配层本就该不同），而是要求**内容标准必须一致**。

## 二、规则内容

### ① 标准版 = WorkBuddy 专家 SOP

`~/.workbuddy/plugins/cache/my-experts/wechat-article-studio/1.0.0/agents/wechat-article-studio.md`

- 它是**唯一权威源**；
- 任何内容标准的修改都在这里发起；
- 改完后必须**同一轮内**同步到派生版。

### ② 必须同步（内容标准，与平台无关）

| 内容标准 | 派生版落地位置 |
|---|---|
| 叙事真实性三分法与人物连续性 | `references/quality.md` §一 |
| 五层完整性、30% 降幅复核线、篇幅区间 | `references/quality.md` §七 |
| 去模板化、结构轮换、语言指纹、相邻篇轮换 | `references/quality.md` §二 · `references/editorial.md` |
| 标题三类轮换、备选标题须有据 | `references/quality.md` §三 · `references/editorial.md` |
| 事实核验分级、适用与风险边界 | `references/quality.md` §四 |
| 系列规模与跨系列去重 | `references/editorial.md` |
| 发布包件数与卫生、微信正文规范、封面比例与安全区 | `references/publishing.md` |
| 巡检分类、清理安全流程 | `references/maintenance.md` |
| 工具脚本的参数与用途 | `references/publishing.md` |

### ③ 不同步（平台适配层——两版本就该不同）

- `present_files`、专家注册命令、CodeBuddy 专用元数据（`displayName` / `profession` / `maxTurns`）；
- WorkBuddy 私有 Python 解释器绝对路径（派生版按当前工作区运行时定位）；
- 生图积分提示、绑死某平台的固定裁切坐标与去水印命令（派生版服从当前图像工具规则）；
- `agents/openai.yaml` 等 Codex 格式文件。

### ④ 冲突时

以标准版为准，并在派生版 `references/origin.md` **记录差异原因**（便于追溯，避免"为什么这两版不一样"的困惑）。

## 五、这套规则的可复用性

"标准版 + 派生版"的同步模式不限于本项目。当一份工作流 SOP 要在多个平台/格式落地时，通用做法是：

1. **指定唯一标准版**（避免双头）；
2. **把差异拆成两类**——"内容标准（须同步）"与"平台适配层（不须同步）"，写清各自清单；
3. **在派生版里附一张对照表**（哪个标准落在哪个文件），否则同步时会找不到地方；
4. **冲突时以标准版为准，并记录原因**（保留追溯，不静默覆盖）。

比笼统说"两版要保持同步"可执行得多。
