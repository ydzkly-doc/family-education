## 四、行为验证（双向实验 · 决定性证据）

### 实验 1：不读文件 → 是否知道内容？

**指令**：不使用任何文件读取工具，回答 references 里的内容。

**结果**：
> 不知道。
> 1. 我不知道该文件内容。
> 2. 我不知道其中的唯一标识符。
> 3. 我不知道是否提及"S面式"或"句式节流基线"。
> 本次回答未使用任何文件读取工具，**内容未进入我的上下文**。

→ ✅ **references 没有进入常驻上下文**

### 实验 2：读取文件 → 能否获取？（对照组）

**指令**：用 Read 工具读取同一文件后回答。

**结果**：
> 1. 唯一标识符：**LOADCHECK-ALPHA-7731**
> 2. 提到了。句式节流基线：单篇"不是…而是…"≤2次；"那一刻/忽然/慢慢/一点点"同类词合计≤3次；"愿你…"不每篇都用。

→ ✅ **需要时可正常获取，且内容完整准确**

### 双向闭环结论

| | 常驻上下文可见？ | 需要时可获取？ |
|---|---|---|
| **references 内容** | ❌ 不可见 | ✅ 可获取 |

**这正是方案 A 要的机制**：规则"在该出现时出现"，而不是全部常驻。

## 六、方案 A 的落地要点（已验证部分）

1. **plugin.json 写法**（已验证合法）：
   ```json
   "agents": ["./agents/wechat-article-studio.md"],
   "skills": "./skills"
   ```
2. **skill 目录结构**：`skills/<name>/SKILL.md` + `skills/<name>/references/*.md`
3. **SKILL.md 内用「何时加载 → 文件」表**引导按需读取（照 `tdoc-orchestrator` 的写法）
4. **分层边界已由 C 铺好**：P0 红线常驻 agent md、P1/P2 细则下沉 references

**仍需注意**：正式迁移时，agent md 里必须写清"执行到第 N 步时去读哪个 reference"，否则 Agent 可能因不知道有细则而跳过。
