### 2.2 官方判定算法（`cli/engine/layout.ts`）

```ts
// Rule A：line-height 解析为 0 → 违规
// Rule B：lineCount ≥ 2 且 contentHeight/lineCount < fontSize × 0.95 → 违规
const range = document.createRange();
range.selectNodeContents(node);
const lineCount = Array.from(range.getClientRects()).filter(r => r.height > 0).length;
const contentHeight = range.getBoundingClientRect().height;
```

- 判定对象（`collectLineHeightFallback` 的 `blockTags`）：
  **`p, div, section, h1-h6, li, td, a`** —— ⚠️ **含 `section`！**
- 只测「**有直接文本子节点**」的块（`hasDirectText`）
- 沙箱屏幕配置 `DEFAULT_SCREENS`：**585px / 677px / 375px**（三档，取最严）
- viewport 677×800

### 2.3 根因（已实证）

**触发条件 = 块级标签（`<p>`/`<section>`）内「裸文本 + 内联元素」混排。**
浏览器把内联元素边界算成额外 rect → `lineCount` 虚增 → `contentHeight/lineCount` 被除小 → 误判叠字。

**⚠️ 与 font-size / line-height 取值完全无关**（已做消融：删掉行高、补字号、调大行高，全都照样报）。

**✅ 正解（视觉零变化）**：把块内**直接子级的裸文本也包进 `<span>`**（不带任何样式）
→ 块内无裸文本 → 通过。已验证「剥离新增 span 后与原文逐字节相同」。
