# 卡片文章（贴图）· 总纲与索引

> **本文件是「按需参考层」的总纲**：卡片文章在第 **9.5 步**触发。
> 流程骨架、P0 红线、Gate 关卡在专家本体中，已常驻，无需在此重复。

## 零、地位与适用范围

### 0.1 它管什么

**每篇公众号长文，额外产出一个「卡片版本」**（微信官方形态名：**贴图**，俗称"小绿书"）。

| 项 | 说明 |
|---|---|
| **适用** | 所有系列、所有长文（**存量补做 / 新生成同办**） |
| **不适用** | 长文本身的写作与排版（仍走原 SOP 第 0–9 步） |
| **触发点** | **第 9.5 步**（长文第 9 步自检之后）；**长文是唯一素材来源** |

### 0.2 与长文的关系（一句话）

> **长文是「深度内容」，卡片文章是「轻量分发形态」，两者共享同一份素材、不同的组织方式。**

- 长文：吃**订阅关系**，触达 ≈ 粉丝数 + 社交转发；
- 卡片文章：吃**算法关系**，**不看粉丝数**，**优先推给非粉丝**；
- 卡片文章底部**自动带原文链接** → 陌生人刷到卡片 → 点进长文 → 关注沉淀。

### 0.3 三档优先级如何接入

| 档 | 卡片文章里包含哪些 |
|---|---|
| **P0 · 红线** | ①平台规格不违背 ②**每张卡印「与内容类型匹配的标注」**（真实经历标**身份**、改编标**改编**，**不得一律写"改编"**）③不杜撰（回溯长文）④不加动作指令/不绝对化 ⑤不标原创/不填作者 ⑥Gate A/B |
| **P1 · 质量线** | 张数控制、封面卡抓眼球、内容卡信息完整、三件交付物齐备、体积/比例合规、自检通过 |
| **P2 · 偏好** | 配色、底图意象、话题标签数量 |

**已知冲突的既定裁决**：
- **内容完整 vs 张数少** → **两者都要**：张数收敛到 5 张，靠**每张内容做厚**解决（不是靠加卡）。
- **体积小 vs 画质** → **柔化底图**解决（文字是后画的，不受影响）。
- **封面卡抓眼球 vs 身份/来源标注可见** → **标注进 16:9 安全区**，两者不冲突。

## 一、形态定义

```
卡片文章 = 封面卡 × 1 + 内容卡 × N + 收尾卡 × 1（N ≤ 3）
         + 卡片正文（纯文本，含话题标签）
         + 字段表（标题 / 无作者 / 描述指引 / 标签）
```

### 1.1 三条禁令

| ⛔ | 说明 |
|---|---|
| **不是**"把长文拆成几张图" | 要**重新组织叙事节奏**，按"一屏一段"重新分屏 |
| **不是**"长文摘要截屏" | 卡片图是**重新排版的文字卡**，不是正文截图 |
| **不是**"长文的缩略版" | 它是**独立成型**的内容，单看卡片也能读懂 |

### 1.2 平台机制（为什么要做）

| 机制 | 依据 |
|---|---|
| 贴图走**算法推荐**，**优先推给非粉丝** | 后台提示语："发布后优先推荐给非粉丝用户，触达更多新读者" |
| 官方力推：一年 1.16 亿篇、同比涨 377%；近一月活跃号 52% 用过 | 微信《公众号14周年创作者报告》2026-08-17 |
| **粉丝少 + 内容大众向的号最受益** | 行业双号实测：专业深度内容/大粉丝号效果不明显 |

> **系统的自动生成版封面难看、描述被截、无标签** → **必须自做才能拿到流量**。

## 二、⭐ 平台规格（官方口径 · 不可违背）

> **纪律**：标 ✅**官方** 的**不得凭印象改写**；标 ⚠️**实测 / 反推** 的可作依据但**不得当平台承诺**；标 🔶**待确认** 的**不得写入结论**。

> **⚠️ 元规则 · 平台规格带时效（易被当成永久事实，务必先读）**
> 微信贴图的**尺寸、字段、推荐机制、通知规则都可能变**——本节的结论**是某一时点的快照，不是永久事实**。
> **每次做卡片文章前，至少抽查三项**：图片张数上限 / 展示比例 / **是否占通知额度**；
> **以当前官方文档（developers.weixin.qq.com）+ 后台实际显示为准**。
> 若官方页面无法访问（如网络原因），**该项降级为 🔶待确认**，并在交付说明里写明"未复核"。

| 项 | 规格 | 强度 |
|---|---|---|
| **正文格式** | **仅纯文本** + 部分特殊功能标签（如商品） | ✅ **官方** |
| **标题上限** | **32 字** | ✅ **官方** |
| **图片张数** | 最多 **20 张**（首张即封面图） | ✅ **官方** |
| **展示比例** | **3:4**（最佳展示尺寸） | ✅ **官方** |
| **封面展示比例** | **16:9**（可选 1:1 / 2.35:1） | ✅ **官方** |
| **作者字段** | **无**（newspic 结构无 author） | ✅ **官方** |
| **能否标原创** | **不能** | ✅ 多源一致 |
| **描述字数** | **200–350 字**（钩子型，**目标值**）；硬上限 **1064**（含换行符） | ⚠️ 形态规律，多来源一致（见 `14-card-writing.md` 2.2.2） |
| **是否占用群发通知额度** | **⚠️ 反推：可能占用**（同日多篇送达数相同、文章本体送达为 0）；**待后台确认** | ⚠️ **项目数据反推**（**非**实测确认） |
| **必须勾"允许被推荐"** | 否则**公域入口锁死** | ✅ 多源一致 |

### 2.1 ⛔ 最重要的一条（官方原文）

> **「图片消息则仅支持纯文本和部分特殊功能标签如商品」**（对照图文消息：「**支持HTML标签**」）

| 能力 | 长文（news） | **贴图（newspic）** |
|---|---|---|
| 加粗 / 斜体 / 下划线 | ✅ | ❌ |
| 字号 / 颜色 / 背景色 | ✅ | ❌ |
| `<section>` / `<p>` 等标签 | ✅ | ❌ 会当纯文本或过滤 |
| `<img>` 插图 | ✅ | ❌（图只能走卡片图列表） |
| **分段** | HTML 控制 | **靠空行** |
| emoji / 符号 | ✅ | ✅ ⚠️ **仅限描述字段** |
| 超链接（小程序 / 网站） | ✅ | ✅ |

> **⚠️⚠️ 上面这行"符号 ✅"只适用于描述（`content`）字段——不要误推到卡片图！**
> **两层完全不同**：
> - **描述字段**：微信客户端渲染 → emoji、符号**正常显示**。
> - **卡片图上的文字**：由**本工坊用 PIL + 中文字体（微软雅黑）绘制** →
>   **字体不含的符号会变成空心方框（豆腐块）**（✔✕✓✗ 全在此列）。
> **→ 卡片图文案里的任何非中文符号，必须先验字形**（见 `15-card-visual.md` 5.3）。

> **⛔ 纪律**：本工坊的《微信公众号排版HTML规范》（section 流式、零 `data-*`、标签白名单）
> **只适用于长文正文**，**对卡片正文完全不适用**。

### 2.2 ⚠️ 封面按 16:9 展示 → 必须设安全区

首图作封面时按 **16:9 中心裁切**展示，而卡片本身是 3:4 → **裁切带只占卡片中间约 42%**。

```
1242×1656 卡片 → 16:9 裁切带 = y 478 ~ 1177（高 698px）
```

**→ 封面卡的所有关键内容（身份/来源标注、主文案、署名）必须落在该带内。**

**自检断言（必须写进脚本）**：
```python
y0, y1 = int((H - W*9/16)/2), int((H + W*9/16)/2)   # 478, 1177
assert 所有文字块 b[1] >= y0 and b[3] <= y1          # 仅封面卡强制
```

### 2.3 两套规格别混

| 用途 | 比例 | 体积 |
|---|---|---|
| **长文封面**（原有） | **2.35:1**（1200×511） | ≤200KB |
| **卡片图**（本细则） | **3:4**（1242×1656） | **<100KB** |
| 卡片图**作贴图封面时** | 系统按 **16:9** 裁切展示 | **需设 16:9 安全区** |

## 三、⭐ 三件交付物（职责边界 · 硬规定）

| 文件 | 放什么 | **⛔ 不放什么** |
|---|---|---|
| `01_标题作者摘要.txt` | **后台要填的字段** + 卡片顺序 + 来源声明 + 回溯对照 + 发布清单 + 差异对照 | **不放正文全文**（避免两处不同步） |
| `02_卡片正文（纯文本）.txt` | **正文纯文本**，**末行带话题标签** | **不放任何 HTML 标签**；不放卡图文字 |
| `第XX篇_卡片_NN_*.jpg` | 卡图，**文件名即顺序**（两位序号）｜**必须带篇号前缀** | — |

### 3.1 命名与目录

```
第XX篇_卡片_NN_短标签.jpg   篇号前缀 + 两位序号；短标签取该卡核心意象（"封面""腌萝卜""时间线"）
01_标题作者摘要.txt
02_卡片正文（纯文本）.txt
```

> ⛔ **篇号前缀是硬要求**（2026-09-15 修）。原因：**卡图要上传到公众号图库，而图库按文件名去重**——
> 不同篇都用 `卡片_01_封面.jpg` 时，**后上传的会覆盖前一篇的**，导致前一篇的卡片图被换掉。
> 同理，**底图成品也要带篇号前缀**（见第 6.3 节）。**共享目录里的资产一律带归属标识。**

```
<系列>/公众号文章/发布包_第X篇_xxx/
├── 长图文发布包/           ← 长文三件套（正文.html / 01字段 / 封面.jpg）
└── 卡片发布包/             ← 卡片交付物（01字段 / 02正文 / 第XX篇_卡片_NN.jpg）
```

**⚠️ 目录迁移前必做**：改造 3 个工具脚本，否则自检链路全断。

| 脚本 | 现状假设 | 需改造为 |
|---|---|---|
| 系列发布全套自检 | `发布包_*` 下**直接**找文件 | 优先查 `长图文发布包/`，**回退**包根 |
| 重建全部正文预览 | 同上 | 同上 |
| 模板感诊断 | 同上 | 同上 |

**兼容策略**：加一个"解析内容目录"辅助函数——**子目录存在则用之，否则回退包根**。

### 3.2 ⭐ 目录迁移时机（**策略：逐篇随做**，2026-09-15 用户确认）

> **规则：做某篇的卡片文章时，顺手把该篇的发布包迁为新结构。**

| 情形 | 做法 |
|---|---|
| **本篇要新做卡片文章** | 建 `卡片发布包/` 的同时，把已存在的长文三件套移入 `长图文发布包/` |
| **旧系列、暂不做卡片** | **保持旧结构不动**（工具链兼容，照常可用） |
| **新系列 / 新建发布包** | **直接用新结构**（一步到位，无需迁移） |

**⭐ 关键区分**：**目录迁移 = 移动文件位置，不修改内容**。
→ **不违反"存量补做时只读长文不改"的纪律**（那条禁止的是**改长文内容**，不是禁止移动文件）。

**⚠️ 迁移三步（顺序不可颠倒）**：
1. **先改造 3 个工具脚本**（见上表）——**必须在移动文件之前**，否则自检链路全断；
2. 建两个子目录，移入文件；
3. **跑全套自检 + 预览重建验证**（确认 `wx_html_fix` 合格数不变、预览篇数不变）。

**⚠️ 迁移时要同步检查的两处判据**（易漏，2026-09-15 踩过）：
- **「发布包卫生」白名单正则**必须含 `长图文发布包` 与 `卡片发布包`；
  否则这两个子目录会被误判为"多余待清理"甚至误删（详见 `08-selfcheck.md`）。
- **`.gitignore` 不应误伤**子目录内的交付物（子目录名不含 `_` 前缀，正常不会被忽略规则命中）。

## 四、⭐ 标准工作流（12 步 · **含两道强制关卡**）

> **前置条件**：**长文已完成**。卡片文章**不先于长文**——长文是唯一素材源。

### 4.0 ⛔ 最重要的一条：**先出设计文档，等确认，才能动手**

> **生成卡片文章是一个「分阶段」的过程，不是一次做完。**
> **第 0–3 步只产出「设计文档」，交付后必须停手等用户确认；确认之前，禁止执行第 5 步及以后的任何动作。**

| 阶段 | 步 | 产出 | 是否停手 |
|---|---|---|---|
| **① 设计阶段** | 0–3 | **设计文档**（拆卡表 + 正文草稿 + 字段草案 + 素材回溯） | — |
| **⏸ Gate A** | 4 | 把设计文档交付用户确认 | **⛔ 必须停手** |
| **② 制作阶段** | 5–9 | 底图 + 5 张卡 | — |
| **⏸ Gate B** | 10 | 首张封面卡交付确认（首次做 / 换风格时） | **⛔ 必须停手** |
| **③ 组装阶段** | 11–12 | 完整发布包 + 自检报告 | — |

**⛔ Gate A 未确认前，明令禁止**（逐条照办，不得以"先做了再说"绕过）：
1. **禁止生成任何底图**（消耗积分、且方向可能白做）；
2. **禁止渲染任何卡片**（含试渲、样张）；
3. **禁止创建 `卡片发布包/` 目录或任何占位文件**；
4. **禁止做目录迁移**（迁移与卡片制作是一个动作，等确认后一起做）；
5. **禁止跑底图后处理脚本**。

**允许做的事**：只有**只读的核对计算**（如正文字数核对、标签数核对、素材段号回溯）。

### 4.1 分步产出表

| 步 | 动作 | 产物 | 关卡 |
|---|---|---|---|
| **0** | **读长文**：全文读完，标出可回溯的段落 | 素材清单（段号 → 场景/机制/金句） | — |
| **1** | **拆卡**：按"一屏一段"设计 5 张 | 拆卡表（主题标签 + 主标题 + 正文草稿 + **来源段号**） | — |
| **2** | **写描述**：**钩子型 200–350 字**，**只写卡片没讲的**（后台口径含换行） | 描述草稿 + 话题标签 | — |
| **3** | **起字段**：标题（≤20 字优先）+ 备选 + 取舍说明 + 数字一致性核对 | 字段草案 | — |
| **3.5** | **汇成设计文档并交付**（见下"设计文档必备内容"） | ⭐ **设计文档**（独立 md） | — |
| **4** | **⏸ Gate A · 设计文档确认** | 用户明确确认 | **⛔ 停手等确认** |
| **5** | **生成底图**：封面卡 + 收尾卡（**先告知消耗积分**） | 2 张 AI 底图 | — |
| **6** | **底图后处理** | 底图成品 + 底部条带 | — |
| **7** | **目检底图**：无水印、压字区干净 | 目检通过 | ⚠️ 人工 |
| **8** | **渲染 5 张卡**：脚本生成 + 自检 | 5 张 JPG | — |
| **9** | **逐张核验**：无重叠/无出界，封面卡验 16:9 | ⚠️ **几何类必须实测**（读像素），**语义类（水印/错字/读得通）才靠目检**——目测对留白、间距极不可靠（连续两次看错）；见 `15-card-visual.md` 九 | ⚠️ 人工+实测 |
| **10** | **⏸ Gate B · 封面卡风格确认**（首次做 / 换风格时） | 封面卡样张 | **⛔ 停手等确认** |
| **11** | **组装交付包 + 目录迁移**（按策略「逐篇随做」） | 完整发布包（新结构） | — |
| **12** | **全套自检 + 交付** | 自检报告 | — |

### 4.2 ⭐ 设计文档必备内容（Gate A 交付物）

设计文档**必须是独立文件**（如 `00_第X篇拆卡方案_GateA.md`），且**必须含下列 7 项**：

| # | 内容 | 说明 |
|---|---|---|
| 1 | **素材清单** | 逐条标出**长文段号** → 场景/机制/金句（证明不杜撰） |
| 2 | **拆卡表** | 每张卡：主题标签 + 主标题 + 文案草稿 + 内容量 |
| 3 | **取舍说明** | **砍掉了哪些素材、为什么**（不是只列用了什么） |
| 4 | **描述全文 + 与卡图的「重复度对照」** | 纯文本草稿（**钩子型 200–350 字**）+ 字数核算（用 `卡片正文字数核算_check.py`）+ **标出"卡片已讲/描述只讲没讲的"** + **末段有自然引导原文的句子** |
| 5 | **字段草案** | 主标题 + 备选 + 标签 |
| 6 | **⚠️ 数字一致性核对** | 卡片文案里的数字/引语**与长文正文逐项比对**（防与长文摘要或印象不一致） |
| 7 | **⭐ 逐张标注类型表** | 每张卡：来源段号 → **内容类型（真实/改编/他人）** → **该卡标注文字**（**真实经历＝身份标注，⛔ 不得写"改编"**）；⚠️ 同篇内可并存不同类型 |

> **为什么第 6 项重要**：本项目**实测发现过长文字段表摘要与长文正文数字打架**
> （摘要写"讲八遍"、正文写"讲了两遍"）。**卡片一律以长文正文为准**。

### 4.3 关卡纪律（**与主机 Gate 1/2/3 同等效力**）

- 只认用户**当次、明确、点名到这一步**的指令（"确认/OK/开工/按这个做/可以了"）；
- **⛔ "继续做 / 你定就行 / 一次做完 / 接着弄" 等概括说法，不得扩大解释为对未提及关卡的授权**；
- 用户说"看看 / 参考一下 / 还有吗"**不算确认**；模糊或未点名时，**停在关卡、等待**；
- **"少交付"≠"少确认"**——减少 present_files 频率**绝不等于**可以减少关卡确认；
- **不得因"这是增量功能"而放宽关卡**。

### 4.4 存量 vs 新生成（**两个入口，同一套规则**）

> ⭐ **核心不变式**：**无论哪种入口，长文都是唯一素材源，且卡片文章都在长文完成后做。**

| 入口 | 场景 | 流程差异 |
|---|---|---|
| **A · 存量补做** | 已有长文（含已发布的） | 直接从**第 0 步读长文**开始 |
| **B · 新生成** | 新系列 / 新篇 | 长文走完原 SOP 0–9 步 → 再进第 0 步 |

**两入口只有 3 处差异**（起点 / 长文状态 / 图片素材），**其余规格、张数、文案规则、关卡、自检完全一致**。

**⚠️ 存量补做的三条额外纪律**：
1. **⛔ 只读长文，绝不回改**（长文可能已发布，改动会造成线上线下不一致）；
2. **⛔ 不改长文标题去迁就卡片**（卡片标题可另起，不得反向修改长文）；
3. **可回溯对照以"已定稿长文"为准**。

**批量补做的排序建议**：数据表现好的 → 主题大众向、痛点明确 → 总纲/导航型 → 其余按系列顺序。

## 五、⭐⭐ 错误案例库（**横向索引 · 真实踩过的 15 处错**）

> **用法**：每一步动手前，扫一眼本节对应条目。

### 5.A · 平台规则类（来源：未先查官方文档就动手）

| # | 错误 | 正确做法 | 教训 |
|---|---|---|---|
| **A1** | 以为贴图正文**支持富文本**，按长文 HTML 规范设计 | **官方：仅纯文本** | **先查官方文档，再设计** |
| **A2** | 标题上限写 **64 字** | **32 字**（64 是图文消息的） | 长文/贴图的规格**别互相套用** |
| **A3** | 卡片张数上限写 **9 张** | 官方 **20 张** | 别拿早期资料当现行口径 |
| **A4** | 描述上限写 **100 字** | 标题+正文 **≤1064 字** | 规格要查三处：官方文档 / 实测 / 后台 |
| **A5** | 字段表里填了**作者** | 贴图**无 author 字段** | 长文字段不能照搬 |
| **A6** | 不知封面按 **16:9** 展示 → 封面卡文字被裁 | **设 16:9 安全区** | 官方 `cover_info.ratio` 有说明 |
| **A7** | 不知"**张数越多越掉量**" → 设计了 8 张 | **5 张上限** | **"上限"≠"该用多少"** |

> **⛔ 元规则：动手设计前，先查官方文档（developers.weixin.qq.com）+ 平台实测。**
> **凭印象套长文规格，是错误的最大来源。**

### 5.B · 交付物类

| # | 错误 | 正确做法 | 教训 |
|---|---|---|---|
| **B1** | 字段表里**存了两处正文** | 字段表**只放后台要填的字段** | **单一真相源** |
| **B2** | 正文文件**缺话题标签** | 标签**写在正文末行** | 交付物要"**粘贴即用**" |
| **B3** | 内容卡**文字太少** → 读者"没头没脑" | **每张做厚** | **张数少 ≠ 内容薄** |

### 5.C · 技术类 → 详见 `15-card-visual.md`

| # | 错误 | 正确做法 | 教训 |
|---|---|---|---|
| **C1** | 排版引擎**绘制方式混用** → **文字重叠** | **只用一种绘制方式** | 排版引擎要写扎实 |
| **C2** | 底图**不柔化** → 压到 q=40 仍超限 | **柔化底图** | 柔化只动底图，**不损文字** |
| **C3** | **体积超限未计入失败判定** | **超 100KB 必须记失败** | 自检不能只看"保存成功" |
| **C4** | 保存报 `PermissionError` / `Errno 22` | **保存加重试** | Windows 下文件会被占用 |
| **C5** | 用**亮度阈值**找水印 → **必然误报** | 脚本只**裁切** + **人工目检** | **目检是最终判据**（**限语义类**） |
| **C16** | ⭐⭐ **卡片图里用了字体不支持的符号**（`✕`/`✓` U+2715/2713）→ 渲染成**空心方框**，且缩略图里**肉眼几乎看不出** | **优先用纯中文**（「旧 / 新」「该做 / 别做」）替代；必须用符号时先跑 `check_symbols()` 验字形。⚠️ **别把"描述字段支持符号"误推到卡片图**——两层渲染器不同 | **中文字体 ≠ 全符号字体**；且**检测器必须做反向测试**（本项目首版检测器因 numpy 未导入而静默失效，详见 `15-card-visual.md` 5.3.1） |
| **C15** | ⭐ **把"目检"用错地方**：靠目测判断"留白偏多/署名偏挤" → **连续两次看错**（实测分别为 487/504px 均衡、间距 257–328px 充足） | **语义类**（水印/错字/通顺）→ 人工目检；**几何类**（留白/间距/越界）→ **读像素实测**。另：**日志数字 ≠ 成品实测值**（勿混用） | **目检与实测是分工，不是谁替代谁**（见 `15-card-visual.md` 九） |
| **C6** | 内容块**重心偏上、下方大留白** | **块内垂直居中** | 版式要按"可用区"计算 |
| **C7** | 标点**落在行首** | **行首禁则** | 中文排版基本盘 |
| **C8** | ⭐ **高亮色块按 `size` 估算块高** → 文字下缘被切（"点"的四点底、"子"的钩） | **按 `textbbox` 墨迹实测**定块高 + 相邻行保护 | **字号 ≠ 墨迹高度**；见 `15-card-visual.md` 5.1 |
| **C9** | ⭐ **底图成品文件名不含篇号** → 下一篇处理**覆盖**上一篇的成品 | 输出名带**篇号前缀**（`第14篇_封面卡_底图.png`），脚本加 `--prefix` | 共享过程目录里的资产**必须带归属标识** |
| **C10** | ⭐ **卡片文件名不含篇号**（`卡片_01_封面.jpg`）→ **上传公众号图库时跨篇覆盖**，前一篇的图被换掉 | 文件名带篇号：`第14篇_卡片_01_封面.jpg`；自检脚本加"缺前缀"断言 | **面向同一资源池的资产，命名必须唯一**（同 C9） |
| **C11** | 描述**贴着上限写**（余量仅个位数）→ 后台口径稍异就**用不了** | 按 **`14-card-writing.md` 2.2.2「钩子型 200–350 字」**写，不贴上限 | **按"上限"写作＝把风险留给自己** |
| **C13** | ⭐⭐ **把描述写成近 1000 字**（理由"内容要完整"）→ **与卡片图内容重复**，且违背形态规律（贴图是"预告片"，不是长文容器） | **描述只写「卡片没讲的」+ 钩子 + 引导原文**，**200–350 字**；先做**重复度对照** | **把「能填多少」当成「该填多少」＝形态错配** |
| **C14** | 描述**只顾讲内容、结尾没有指向长文** → **引流链路断了**（卡片文章的本职就是引流） | 末段用**内容指向**自然引导（"那封信我一字不改地留在了长文里"）；⛔ **不得写成"点击阅读原文"式动作指令** | **引导≠指令**：用陈述句指路，不用祈使句命令 |
| **C12** | ⭐⭐ **字数用「去空白」口径算** → **漏算全部换行符**，报 983 而实际 1035，**已超限而不自知** | 一律用 `卡片正文字数核算_check.py`（**后台口径：标题+content，换行算 1 字符**）；CRLF 先归一 | **口径不对，越算越错**；数字必须与后台能对上（拿后台显示值校准） |

### 5.D · 数据与认知类（**最危险，会污染所有后续判断**）→ 详见 `10-ops.md` 附录

| # | 错误 | 正确做法 | 教训 |
|---|---|---|---|
| **D1** | 把"文章本体 vs 后台卡片"**当成封面 A/B 测试** | 那是**同一内容的两个载体** | **先问"这个对比的定义是什么"** |

| **D3** | 把**自己的推断当数据**写进结论 | 分清**数据 / 推断**，推断须显式标注 | **反向陈述自检** |

## 六、交付前检查清单（12 项）

### 6.1 卡片图（5 项）

- [ ] 张数 **≤5**（封面 1 + 内容 ≤3 + 收尾 1）
- [ ] 全部 **1242×1656**，比例 **精确 3:4**
- [ ] 单张 **≤100KB**
- [ ] **封面卡关键内容落在 16:9 安全区**（y 478–1177）
- [ ] 逐张核验：**无重叠 / 无出界 / 无错别字 / 无水印**（语义类靠目检）
- [ ] ⭐ **无缺字（豆腐块）**：卡片图里所有非中文符号都验过字形（脚本自检过）
- [ ] ⭐ **几何类已实测**：留白均衡、间距充足、未出安全区（**读像素算过，不是目测**）

### 6.2 内容（4 项）

- [ ] 每张内容卡：**主题标签 + 主标题 + 完整正文段**（信息自足）
- [ ] 中间内容卡不是“一屏一句”：有核心判断与至少 2 条支撑信息，正文占屏与留白均衡；过薄时回到长文补足，不用空行或重复句填充
- [ ] **每张卡都有标注，且类型与内容来源匹配**（真实经历＝身份标注 / 改编＝改编标注 / 他人＝来源标注）
- [ ] 全部文案**可回溯到长文**（附段号对照）
- [ ] 无动作指令 / 无绝对化 / 人设一致

### 6.3 交付物（3 项）

- [ ] `01_标题作者摘要.txt` —— **只放后台字段，无正文**
- [ ] `02_卡片正文（纯文本）.txt` —— **纯文本 + 末行话题标签**，字数 ≤1064
- [ ] 卡图文件名**两位序号**，顺序即发布顺序
