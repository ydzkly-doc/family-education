# 卡片文章 · 内容设计细则

> **归属**：卡片文章细则三件套之「内容设计」。
> 总纲（平台规格 / 交付物 / 目录迁移 / 工作流 / Gate / 案例库）见 `13-card-article.md`；
> 视觉技术（底图 / 排版引擎 / 视觉断言）见 `15-card-visual.md`；发布操作与数据复盘见 `10-ops.md` 附录。

## 一、⭐ 张数规则

| 项 | 值 | 依据 |
|---|---|---|
| **平台上限** | **20 张** | 官方 |
| **实测最优** | **2–3 张** | 多源实测同向 |
| **掉量拐点** | 5 张以上开始掉、8 张以上断崖 | 同上 |
| **本工坊默认** | **封面 1 + 内容 ≤3 + 收尾 1 = 共 5 张** | 用户要求 + 实测吻合 |
| **内容卡上限** | **3 张**；超出**必须与用户确认** | 用户明确 |

### 1.1 机制：为什么"张数越多越掉"

**2026-03 改版后**：用户**不必横滑看完所有图**，**直接往下滑就能看到下方正文、广告、留言区**。

> 实测资料原话：**"翻图不赚钱，往下滑才赚钱。"**
> 贴图的阅读数据与广告收益**全靠竖向滑动触发**。

所以：**张数一多 → 翻几张就累了 → 直接退出 → 根本不会往下滑 → 有阅读、无收益、无推荐。**

> **⚠️ 反直觉但重要**：**翻图多 ≠ 好，反而是负资产。**
> 官方上限 20 张 ≠ 该用 20 张。**"上限是多少"与"该用多少"是两件事。**

### 1.2 5 张的叙事分工

| 卡 | 角色 | 承载 |
|---|---|---|
| 1 | **封面卡** | 抓眼球的总钩子（≤20 字，只负责让人停下） |
| 2 | **内容卡①** | **核心机制**（为什么会这样） |
| 3 | **内容卡②** | **对照 / 方法**（该怎么看） |
| 4 | **内容卡③** | **转折 / 时间线**（那我该等多久 / 我做了什么） |
| 5 | **收尾卡** | 情绪落点 + 承接原文 |

**为什么内容卡只要 3 张**：滑动越长、单卡信息越碎。**3 张足够承载一条完整叙事线**（机制 → 方法 → 转折）。

## 二、⭐ 内容撰写规则

### 2.1 标题（上限 32 字）

| 规则 | 说明 |
|---|---|
| **钩子在前 10 字内** | 系统按**前 20 字**截断展示 |
| **≤20 字优先** | 留出余量，避免被截 |
| **可≠长文标题** | 卡片版应重新起，更适合信息流 |
| **优先"冲突/反差"句式** | 有具体数字 + 有反差 |

### 2.2 摘要 / 描述 = **正文**（不是长文的摘要）

> ⭐ **关键认知**：卡片文章的"描述"**不是长文摘要**，而是**卡片文章的正文**。
> 新版贴图里用户**直接往下滑就能读到它**，广告收益也靠"往下滑"触发。

| 规则 | 说明 |
|---|---|
| **字数（⛔ 必须按「后台口径」数）** | **描述 200–350 字**（钩子型）；硬上限 1064，**但不得贴上限写**（见 2.2.2） |
| **核算法** | 计数字符 = **标题 + 正文（`content` 字段，含换行符）**；**换行符算 1 个字符** |
| **工具** | `工具脚本/卡片正文字数核算_check.py <正文txt> --title "标题"`（**必须用它核，不要手数**） |

### 2.2.1 ⛔⛔ 「后台口径」字数：换行符也算字符（2026-09-15 实测校正）

> **这是本项目字数反复出错的根因，务必先读这一节。**

**§ 踩坑经过**：先前核算一直用「**去掉所有空白**」的口径（`len(''.join(text.split()))`），
**把 46 个换行符全漏算了**。结果第 14 篇报 983 字，而**后台实际显示 1035 字**——差 52 字，
**已贴到上限而不自知**。

**§ 实测反推的口径**（用户后台数字为准）：

| 篇 | 标题 | 正文(含换行) | 合计 | 后台显示 |
|---|---|---|---|---|
| 第14篇 | 15 | 1020 | **1035** | **1035** ✅ 精确吻合 |

**→ 结论：计数字符 = 标题 + 正文，其中**换行符按 1 个字符计入。

**§ 三种口径对照（同一份正文）**：

| 口径 | 算法 | 第14篇 | 是否可用于验收 |
|---|---|---|---|
| ❌ 去空白 | `len(''.join(t.split()))` | 884 | **不可用**（漏算换行） |
| ✅ **后台口径** | `len(标题) + len(content)`，CRLF 归一为 1 | **963** | **唯一可用** |
| — | 上限 | — | **1064** |

**§ 硬规定**：
1. **一律用 `卡片正文字数核算_check.py` 核算**，禁止手数或用去空白口径；
2. **描述按 2.2.2 的「钩子型 200–350 字」写**（不是"贴着上限写"）；硬上限 1064；
3. **CRLF 归一为单个换行再数**（`text.replace('\r\n','\n')`），否则 `\r` 会被多算一次。

### 2.2.2 ⭐⭐ 描述的**定位与长度**：钩子型，**200–350 字**（2026-09-15 用户确认）

> **这是卡片文章最容易被做错的一环：把「能填多少」当成「该填多少」。**

**§ 踩坑经过**：初版把描述写成 **948 字**（贴到上限），理由是"内容要完整"。
但用户质疑："卡片文章本身是给长文**引流**的，近 1000 字、没格式的长文本，对阅读真的友好么？"

**§ 检索到的形态规律（多来源一致）**：

| 来源 | 建议正文字数 |
|---|---|
| 头条贴图攻略 | 上限 1000，**建议 200–300 字** |
| 小绿书教程 / 运营号 | **300–500 字** |
| 实测爆款（阅读 4.5 万） | **200 字以下** |
| 对标形态（小红书）官方口径 | **300–800 字**，500 字左右互动最高 |
| 500 篇万赞笔记分析 | **400–800 字**；**超 1000 字用户"只收藏不点赞"** |
| 同上·段落长度研究 | **单段 80–120 字完读率 68%，250 字以上跌到 31%** |

> ⚠️ **证据强度**：全部来自自媒体实测与运营攻略，**无官方明文**；但**多来源高度一致**，
> 且与对标形态（小红书）的官方规范口径吻合。**已在 SOP 里标为"形态规律"而非"官方规定"。**

**§ 形态定位（更根本的一条）**：

> **"深度文用单图发，读者点进去没东西读；金句用长文发，读者嫌累划走。"**
> 小绿书是长文的「**预告片 / 切片**」，**不适合塞长论证**。

**§ ⛔ 硬规则：描述 = 钩子型，200–350 字**

| 项 | 规定 |
|---|---|
| **长度** | **200–350 字**（正文，后台口径含换行） |
| **承担什么** | ① 一句**引语/反问**钩人 ② 给出**卡片里没讲的内容**（卡片已讲的**不再重复**） ③ **引导去长文**看完整故事 |
| **⛔ 不承担什么** | **不复述卡片已有内容**；不做完整叙事；不写"本文讲述…"式导语 |
| **段落** | **每段 ≤120 字**（完读率关键） |
| **发现重复怎么办** | **宁可留白，也不重复**——重复＝用户把同一件事读两遍 |
| ⭐ **结尾必须引导原文** | **末段要自然指向长文**（见下 6.10.1），**但不得写成动作指令** |

**§ ⭐ 判定方法：描述 vs 卡片图「重复度检查」**

写作前先列一张对照表，**标出卡片图已经讲了什么**，描述**只挑没讲的**：

| | 卡片图讲了 | 描述该讲 |
|---|---|---|
| 例（第14篇） | 泄气的晚上 → 腌萝卜 → 施肥/挂果 → 收尾金句 | **时间线节奏 + 记小胜法 + 引导原文** |
| 例（第15篇） | 拍桌子 → 换位 → 四步 → 名师之祸 → 收尾 | **三封信的由来 + 离开桌十秒 + 引导原文** |

**§ 2.2.2.1 ⭐ 结尾必须「自然引导原文」（2026-09-15 用户新增规则）**

> **卡片文章的存在意义就是给长文引流。描述写完正文却没说"长文里还有什么"，等于少了最后一环。**

**§ 三条写法纪律**

| # | 纪律 | 说明 |
|---|---|---|
| 1 | **必须引导** | 末段要**指向长文**，让读者知道"完整的东西在那边" |
| 2 | **必须自然** | 用**内容指向**，不用**动作指令**——写成"那封信我一字不改地留在了长文里"，而不是"点击阅读原文" |
| 3 | **给一个具体理由** | 说清**长文里有什么是这里没给的**（原样抄的那张纸 / 完整的信 / 全部四步） |

**⛔ 与既有红线的边界（最容易搞错）**

项目既有红线是「**不加动作指令**」（不写"点赞/转发/关注"）。**引导原文也必须遵守这条**——
它和"引流"不矛盾：**用"我留在了长文里"（陈述），不用"点原文看"（命令）。**

| ✅ 可用（内容指向） | ⛔ 禁用（动作指令） |
|---|---|
| "那张纸我原样抄进了长文" | "点击阅读原文查看" |
| "那三封信我一字不改地留在了长文里" | "想看完整版请点原文链接" |
| "我把全部四步写在长文里了" | "快去原文看吧" |
| "如果你也在等一个'还没变'的孩子——长文里有我贴冰箱的那张纸" | "戳这里看详情" |

**⭐ 推荐句式（三段式，自然不硬）**

```
【共情/点题】如果你也在等一个"还没变"的孩子——
【给出具体】那张我贴在冰箱上的纸、我是怎么熬过第二十几天的，
【指向原文】我都原样写进长文里了。
```

**⚠️ 位置**：引导句放在**正文末段**（话题标签行的上一段），**不单独成行、不加重语气**。

**§ 例外条款（用户要求优先）**

> **默认按本规则执行（200–350 字钩子型）。**
> **除非用户在制作时明确要求"描述写长一些 / 写完整 / 突破字数"，否则不得自行突破。**
> —— 用户明确要求时，按其要求执行，并在字段表里**注明"应用户要求突破"**。
| **开头 3 行内进场景** | 系统从**开头约 200–260 字**截取做预览 |
| **第一句直接给处境** | 不写"本文讲述……"；读者大概率**不认识这个号** |
| **结尾给情绪落点** | 不写"点赞/转发/关注"等**动作指令** |
| **回复长文主干** | 承载长文主线，让卡片文章**单篇可独立成文** |

### 2.3 卡片文案

| 卡 | 规则 |
|---|---|
| **封面卡** | **全卡 ≤20 字**；分 2–4 行；**不塞正文、不塞观点** |
| **内容卡** | **一张一个完整意思**；**每张信息自足**；建议 60–150 字 |
| **收尾卡** | 用长文最有力的一句收；可含一小段场景承接 |

**⭐ 内容卡必须做"厚"**：

| ⛔ 错误做法 | ✅ 正确做法 |
|---|---|
| 只放一句金句 | **主题标签行 + 主标题 + 足够读懂的正文段** |
| 读者"没头没脑" | **每张卡顶部标出"这张讲什么、讲到第几步"** |

> **纪律：张数少 ≠ 内容薄。** 张数收敛到 5 张，**代价要用"每张做厚"来还，不是用"多加几张"来还**。

#### 2.3.1 ⭐ “一屏一意”不等于“一屏一句”

中间内容卡默认采用：**1 个核心判断 + 2–4 个解释点／步骤／边界／可照念台词**，通常形成 **3–4 个信息块**。同一张卡仍只回答一个问题，但要让读者在不依赖前后卡的情况下看懂“为什么、怎么做、到哪里为止”。

- 建议正文约 **80–160 个中文可见字符**；素材较短时以信息完整为准，不为达字数重复同义句。
- 正文内容建议占可用内容区约 **45%–65%**。低于约 40% 时，先回到长文补足本屏的机制、例子、台词或边界；不得靠空行、拉大段距或无据结论填满。
- 若超过约 70%，或必须明显缩小正文字号才能放下，应删减或拆解；手机可读性优先于“塞满”。
- 扩充只能取自已定稿长文；卡片不能为了变厚新编经历、数字或因果。

**快速自检**：去掉标题后，这张卡是否还包含“判断 + 至少两条支撑信息”？若只剩一句金句或一小段摘要，仍属过薄。

### 2.4 话题标签

| 规则 | 说明 |
|---|---|
| **数量** | 建议 **6–10 个**；样本实测可带 19 个 → **不是硬上限** |
| **位置** | **写在正文末行**（粘贴时一并带入） |

### 2.5 ⛔ 红线

| # | 红线 | 说明 |
|---|---|---|
| 1 | **不杜撰** | 所有观点/比喻/金句**必须能回溯到长文**；长文又能回溯到原材料 |
| 2 | **不加动作指令** | 不写"点赞/转发/关注"（外部资料大量建议引导互动，**与本号纪律冲突，一律不采纳**） |
| 3 | **不用绝对化** | 不写"一定/必然/彻底治好" |
| 4 | **人设一致** | 孩子 **15 岁·高一·儿子**；叙事者"一个也在重启的爸爸" |
| 5 | **敏感议题带边界** | 涉及厌学/自伤等须给专业求助提示 |
| 6 | **不填作者、不标原创** | 平台无该字段 |
| 7 | **⭐ 每张卡印「与内容类型匹配的标注」** | **卡片特有 P0**，见 2.6（**真实经历标身份，⛔ 不得标"改编"**） |

### 2.6 ⭐⭐ 卡片特有的 P0 红线：**逐张标注（标注内容随来源类型而变）**

> **卡片是独立传播单元**——一张卡可能被**单独看到、单独转发**，
> 而长文的"第一屏标注一次"策略**在卡片形态下失效**。

| 形态 | 标注策略 |
|---|---|
| 长文 | **第一屏标注一次**即可 |
| **卡片文章** | **每一张卡都必须印**（顶部第二行） |

### 2.6.1 ⛔ 标注**不是**一律写"改编"——要按内容类型匹配

> **这是最容易搞错的一点：把"逐张标注"误解为"逐张印'改编'"。**
> 结果是——**真实经历被印上"改编"，等于自己抹掉账号最值钱的东西**；
> 反之，**改编被印成"真实记录"，则是最大的真实性风险**。**两种错都是 P0。**

| 内容类型（对应三分法） | 该卡标注写什么 | 示例文字 | ⛔ 禁止 |
|---|---|---|---|
| **① 用户确认真实经历** | **身份标注**（**不写"改编"**） | 「一个也在重启的爸爸 · 真实记录」 | ⛔ 不得标"改编""虚构" |
| **② 课程案例 / 改编情节** | **改编标注** | 「家庭场景改编 · 非作者真实经历」 | ⛔ 不得标"真实记录""真实复盘" |
| **③ 他人案例** | **来源标注** | 「课程中的一个家庭（第三人称转述）」 | ⛔ 不得改写成第一人称"我" |

**判定流程（每张卡各做一次，不是整篇做一次）**：
1. 看这张卡的文案**来自长文哪一段**（段号回溯，见 `13-card-article.md` 4.2 第 1 项）；
2. 查该段在长文里的**内容类型**（真实 / 改编 / 他人）；**⚠️ 同一篇内不同类型可能并存**——封面卡是真实引语、内容卡是改编场景，**完全正常**；
3. 按上表取**对应标注文字**，印在该卡**顶部第二行**。

**⚠️ 位置**：标注必须落在 **16:9 安全区内**（封面卡），否则对外展示时会消失。
**⚠️ 一致性**：同一篇内，**标注不能互相矛盾**（不能封面写"真实记录"、内容卡写"改编"却无说明边界）。

> **⭐ 与长文的关系**：长文里"真实经历 / 课程案例改编 / 他人案例"三分法**写法与标注各不相同**——
> 卡片**继承长文的类型判定**，不要重新判定、也不要统一成一种标注。
> 若长文某段是改编，卡片对应卡就标改编；长文某段是经确认的真实经历，卡片就标身份，**不得降级为"改编"**。

## 三、描述类自检断言（脚本必须写死）

> **⚠️ 卡片文案的两个"隐形"排版坑**（详见 `15-card-visual.md` 5.3）：
> 1. **符号豆腐块**：中文字体**不含** ✔✕✓✗（U+2713 区段）等符号 → 渲染成空心方框。
>    **优先用纯中文**（「旧 / 新」「该做 / 别做」）替代。
> 2. **引号必须全角**：中文排版用 `""`（U+201C/D），**不要用 ASCII `"`**。
